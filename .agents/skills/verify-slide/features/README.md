# 機能の対応表

機能ごとに、入口、操作、動いたと言える結果を書く。仕様は [docs/features/](../../../../docs/features/) が正本で、ここには確かめ方だけを置く。機能を足したり入口を変えたりした PR は、同じ PR でこの表を直す。

`$O` は `http://localhost:8811` のように起動した origin を指す。

| 画面の言語 | `$O/slides/try-static`(作者) | `SLIDE_LOCALE=en-US` と `ja-JP` で開く | 題名と文言が、それぞれ英語と日本語になる |

## 注意

- データを入れ直すと、スライドの deployment が増える。件数を根拠にするときは、置き場を作り直す。
- Firefox は、管理画面で favicon の読み込みを CSP が止めたと console に出す(既知、#79)。この 1 件は失敗に数えない。
- Firefox と WebKit は、viewer で `postMessage` の送り先の origin が合わないと console に出す。原因は調べていない。viewer の console を根拠にするときは Chromium で確かめ、ほかの engine ではこれを除いて数える。
- `scripts/verify-upload.mjs` は、`SLIDE_PERSIST_TO` に `launch.sh` と同じ置き場を渡して使う。渡さないと、既定の置き場(`.wrangler/state`)に書くので、`launch.sh` で起動した Worker には届かない([アップロードの確認手順](../../../../docs/dev/f01-local-slice.md#ローカルで確認する))。
- `scripts/verify-upload.mjs` とデータを入れるコマンドは、作者の session を作り直す。前に控えた cookie は使えなくなる。
