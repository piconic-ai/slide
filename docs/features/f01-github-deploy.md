# F01 GitHub からスライドを更新する

状態は、やめた機能です。第一スコープで、コード、経路、テーブル、手順と設計の文書(`docs/dev/`)ごと取り除きます(2026-11-19)。置く入口は [スライドを、ドロップして置く](f22-browser-drop.md) と [AI エージェントから置く](f23-agent-upload.md) に替わります。この文書は、受け入れ条件の ID を残すために消しません。以前の段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会の前日、登壇者が GitHub の Markdown を修正する。ビルドとアップロードを手作業で繰り返すと、古い資料を公開しやすい。いつものブランチへ push し、Actions の結果からアップロードされた版を確認する。

この場面のために、GitHub App の導入、リポジトリの連携、workflow の設定を作者に求めていた。「置くだけで済む」という第一スコープの約束と、最も離れた入口だったので、やめた。

## 作る範囲

なし。次のものは、ほかの機能が引き継ぐ。

- ファイルを受け取って版として保存する仕組み、上限、内容の検査、招待制: [スライドを、ドロップして置く](f22-browser-drop.md)。
- 手動の公開、公開の停止、以前の版への差し戻し: [作者のみ限定公開で発表し、一般公開する](f02-publication.md)。

## 作らないこと

- 互換のための経路や、使わない列を残すこと。本番のデータは空にしてよい。

## 決めたこと

- GitHub からの更新をやめる(2026-11-19)。GitHub App の導入、リポジトリの連携、workflow の設定が要り、「置くだけ」と最も離れた入口だからである。
