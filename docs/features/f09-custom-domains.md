# F09 自分のドメインで資料を公開する

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

技術発信を続ける作者が、プロフィールや名刺から自分のサイトへ誘導している。資料も slides.example.com など同じ名前の下に置き、読者へ一貫した URL を渡したい。

## 得られる結果

配信基盤を自分で運用せず、所有するドメインで資料を案内できる。

## 体験の流れ

1. PRO または TEAM のワークスペースでドメインを登録する。
2. 案内された DNS 設定で所有を証明する。
3. 証明書と接続状態を確認し、共有 URL を開く。

## 作る範囲

- 所有確認、TLS 証明書、接続状態の表示。
- 独自ドメインからも元の資料と同じ公開範囲を適用する。
- 作者の HTML は認証済みの画面と別のドメインで実行する。

## 作らないこと

- 独自ドメインから R2 バケットを直接公開すること。
- 他のワークスペースが所有確認前にドメインを使用すること。

## 受け入れ条件

- 有料・チーム限定の資料が独自ドメイン経由でも権限なしで読めない。
- DNS の未設定や所有確認待ちを成功と表示しない。
- ドメインの解除・再登録で他人の資料へ誤接続しない。

## 未決事項

- apex とサブドメインの対応範囲、接続数の上限。
- 解約時の URL と、ログインを独自ドメイン間で受け渡す体験。

技術上の制約は [開発設計](../dev/design.md#access-control) を参照してください。
