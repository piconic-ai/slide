# F46 コミュニティに外部のスライドを集める

状態は未実装の設計案です(未決事項が残る)。2026-11-28 に、依頼者との相談で、PDF や、ほかのサービスに置いたスライドも並べる話(issue #113)の最初のスコープとして、コミュニティの管理者が外部のスライドを集める形を決めた。相談のページ: https://claude.ai/artifact/3XHuqhRGR8EqUxF3nbA2x7。[同じリンクでスライドが集まる](f45-link-gathering.md) のリンクのページの上に作るので、実装はその後になる。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に出られなかった人が、その回の発表を見返したい。発表のスライドは、Speaker Deck、Docswell、発表者自身のサイト(HTML のスライドに多い)などに散らばっていて、どこにあったかを追えない。リンクのページとコミュニティのページに並ぶのは、このサービスに置かれたスライドだけなので、同じ回の発表が 5 本あり、置かれたのが 1 本なら、残りの 4 本は見えない。

発表者は、すでに自分の場所で公開を済ませている。このサービスに登録し直す動機は弱い。一方、コミュニティの管理者は、自分たちの回の資料が 1 か所にまとまることに、動機がある。主催者が、いま手でまとめているかどうかの裏付けは、持っていない。

## 得られる結果

コミュニティの管理者が、回のページ(リンクのページ)に、外部のスライドの URL、題名、発表者名を足すと、このサービスに置かれたスライドと、同じ回の下に並ぶ。Speaker Deck と Docswell のスライドは、その場で開いて見られる。ほかは、リンクで元のサイトへ進む。発表者は、何もしない。

管理者は、AI エージェントに頼んで、まとめて足せる。題名やプレイヤーの URL を調べるのは、管理者の側で、サービスは外へ取りに行かない。

## 体験の流れ

1. 管理者が、コミュニティの「リンク」のタブか、回のリンクのページで、「外部のスライドを足す」を押す。
2. 回がまだ無いときは、回の URL(紐づけ用リンクに合うもの)を入れる。スライドの URL、題名、発表者名を入れる。Speaker Deck のスライドをその場で見せたいときは、埋め込みコードも貼る。
3. 回のページに、置かれたスライドの後ろに、外部のスライドの行が並ぶ。
4. 読者が、行の「ここで見る」を押すと、その行の下にプレイヤーが開く。プレイヤーのない行は、確認の画面を経て、元のサイトへ進む。
5. 管理者は、行の題名と発表者名を直し、行を外せる。
6. 発表者や読者は、載せるべきでない行を通報できる。運営が、行を非表示にする。

## 作る範囲

- コミュニティが持つ、外部のスライドの行(回、URL、題名、発表者名、プレイヤーの URL)。足す・直す・外す画面と経路。
- リンクのページと、コミュニティの「リンク」のタブの、外部の行の表示と、「外部のスライド n 本」。
- Speaker Deck と Docswell のプレイヤーを、行の下に開く仕組み。プレイヤーの URL の形の確かめ。リンクのページの、枠に出せる origin への、2 つのサービスの追加。
- 外部の行の通報と、運営による非表示。いまの通報([知らない人のスライドも、安心して開ける](f17-safe-viewing.md))は、このサービスのスライドだけを対象にしているので、対象を足す。
- MCP の道具(足す、一覧、外す)と、接続の許可の画面の 1 行([AI エージェントから置く](f23-agent-upload.md))。
- ヘルプの記事。
- ほかの文書で変えるもの: ページを出す条件と「まだありません」のページ、外部のスライドだけの回の、元のページへのリンク先([同じリンクでスライドが集まる](f45-link-gathering.md) の F45-AC31〜F45-AC34)、「リンク」のタブに並ぶ回([コミュニティをつくる](f30-communities.md) の F30-AC75)。

## 作らないこと

- 発表者が、自分の URL を置くこと。PDF を受け取ること。管理者が集める形を使ってみてから、次のスコープ以降で決める(issue #113)。
- コミュニティが持つキュレートの記事と、回によらない URL の一覧。見返す人は「あの回の発表」を探すので、回のページに並べる。
- サービスが、題名、発表者名、プレイヤーの URL、oEmbed、OGP を取りに行くこと。取りに行くのは、管理者と、管理者のエージェントの側である。
- 任意のサイトを枠に出すこと。発表者自身のサイトの HTML のスライドは、リンクで元のサイトへ進む。HTML のスライドが、埋め込んでよいことと、めくり方を自分で示す決まりは、別の issue に記録する。
- 外部のスライドごとのページと、表紙の画像。
- 発表者名とアカウントの結びつけ、本人の承認、本人が自分で外す操作。発表者は、このサービスの利用者とは限らない。
- 置かれたスライドと外部の行を照らして、自動で隠すこと。同じ発表かどうかを、サービスは確かめられない。
- フォロワーへのお知らせ。コミュニティの「スライド」のタブ、トップ、プロフィールに出すこと。
- 行の並べ替え。

## 受け入れ条件

- **F46-AC1** コミュニティの管理者は、そのコミュニティに入ったリンク(回)に、外部のスライド(URL、題名、発表者名)を足せる。
- **F46-AC2** 管理者でない人と、ログインしていない人には、足す画面が出ず、足す・直す・外す経路への送信は断られる。
- **F46-AC3** 管理者は、そのコミュニティの紐づけ用リンクに合う回の URL を入れて、このサービスのスライドが 1 本もない回にも、外部のスライドを足せる。
- **F46-AC4** そのコミュニティのどの紐づけ用リンクにも合わない回の URL は、理由が出て断られる。
- **F46-AC5** スライドの URL は、`https:` と `http:` だけを受け取る。ユーザー名やパスワードを含む URL と、URL として読めないものは、理由が出て断られる。
- **F46-AC6** 題名は必須で 100 文字まで、発表者名は任意で 50 文字までで、超えると理由が出て断られる。題名と発表者名の HTML の記号は、文字として出る。
- **F46-AC7** 同じ回に、正規化した URL([関連リンクを紐付ける](f27-related-links.md) の正規化)が同じ外部のスライドは、2 つ足せない。理由が出る。
- **F46-AC8** 1 つの回に足せる外部のスライドは、100 本までである。101 本目は、理由が出て断られる。
- **F46-AC9** 管理者は、外部の行の題名と発表者名を直せ、行を外せる。その行を足した人でない管理者も、できる。
- **F46-AC10** リンクのページで、外部の行は、このサービスのスライドの後ろに、足した順で並ぶ。行には、題名、発表者名、サイト名が出て、表紙は出ない。
- **F46-AC11** 外部の行は、「スライド n 本」に数えない。外部の行が 1 本以上あるとき、「外部のスライド n 本」が、別に出る。
- **F46-AC12** コミュニティの「リンク」のタブの回の下に、その回の外部の行が出る。コミュニティの「スライド」のタブ、トップ、プロフィール、お知らせ、フォローの新着には、外部の行は出ない。
- **F46-AC13** Docswell のスライドの URL の行には、「ここで見る」が出る。押すと、その行の下に、Docswell のプレイヤーが開く。
- **F46-AC14** Speaker Deck の行は、プレイヤーの URL が入っているときだけ、「ここで見る」が出る。画面では、管理者が貼った埋め込みコードから、プレイヤーの URL を読む。
- **F46-AC15** プレイヤーの URL は、Speaker Deck と Docswell のプレイヤーの形だけを受け取る。ほかの形は、理由が出て断られる。
- **F46-AC16** 読者が「ここで見る」を押すまで、ページは、元のサービスへの通信を起こさない。
- **F46-AC17** スクリプトが動くとき、プレイヤーのない行を押すと、[関連リンクを紐付ける](f27-related-links.md) の F27-AC53 と同じ確認の画面が開く。行のリンクには、`rel="noopener nofollow ugc"` が付く。
- **F46-AC18** 外部の行を足しても、直しても、ページを開いても、サービスから外への通信は起きない。
- **F46-AC19** ログインした人は、外部の行を、理由を選んで通報できる。通報は、運営の画面の一覧に出る。
- **F46-AC20** コミュニティを削除する、または回がどの紐づけ用リンクにも合わなくなると、その回の外部の行は、どのページにも出なくなる。
- **F46-AC21** 幅 375px で、外部の行、開いたプレイヤー、足す画面が、横にはみ出さない。
- **F46-AC22** ヘルプに、外部のスライドを足す記事がある(足し方、その場で見られるサービス、載せてほしくない発表者の窓口)。日本語と英語の両方で読める。
- **F46-AC23** MCP の道具で、自分が管理者のコミュニティの回に、外部のスライド(URL、題名、発表者名、プレイヤーの URL)を足せ、一覧でき、外せる。管理者でないコミュニティへの操作は、理由を返して断る。
- **F46-AC24** MCP の接続の許可の画面に、「管理するコミュニティに、外部のスライドを足す」の 1 行が出る。
- **F46-AC25** 運営は、外部の行を非表示にできる。非表示にした行は、どのページにも出ず、「外部のスライド n 本」にも、ページを出す条件([同じリンクでスライドが集まる](f45-link-gathering.md) の F45-AC31)にも数えない。

## 決めたこと

2026-11-28 に、依頼者との相談で、次のように決めた(相談のページ: https://claude.ai/artifact/3XHuqhRGR8EqUxF3nbA2x7)。論点の番号は、そのページのものである。

- 論点 1。最初のスコープでは、コミュニティの管理者が、外部のスライドを集める。発表者は、何もしない。困っているのは、見返したい人と、まとめたい主催者で、発表者ではないためである。前の相談(2026-11-27)で、発表者が URL を置く案について「だれでも他人の URL を置けると、ブックマーク集になる」と決めたが、今回は、置く人と場所が限られる(管理者が、自分のコミュニティに)点が違う。依頼者の言葉: 「1 A」。
- 論点 2。リンクのページ(回のページ)に、外部のスライドの行を足す。キュレートの記事は作らない。依頼者の言葉: 「2 A」。
- 論点 3。題名と発表者名は、管理者が入れる。MCP の道具も用意し、管理者のエージェントが集めて足せる。サービスは取りに行かない。画面を先に、道具を次に作る。依頼者の言葉: 「3 A / 埋め込み可能なら埋め込みもしたいな」。
- 論点 4。埋め込めるもの(Speaker Deck、Docswell)は、その場で見せる。埋め込めないものは、リンクで外へ送る。依頼者の言葉: 「4 B / 埋め込めないケースは A だね。埋め込みできた方が、ユーザーは楽。」
- 論点 5。Speaker Deck のプレイヤーの URL は、管理者の側で得る(画面は埋め込みコードを貼る欄、MCP は道具の引数)。Docswell は、スライドの URL からプレイヤーの URL を作る。サービスは、知っているプレイヤーの形かだけを確かめる。依頼者の言葉: 「5 A」。
- 論点 6。プレイヤーは、リンクのページの中で、行を開くと出る。外部のスライドごとのページは作らない。元のサービスとの通信は、読者が開いたときにだけ起きる。依頼者の言葉: 「6 A」。
- 論点 7。このサービスのスライドが 1 本もない回にも、足せる。足せるのは、紐づけ用リンクに合う URL の回だけである。外部のスライドだけの回も、ページが出る。依頼者の言葉: 「7 A」。
- 論点 8。発表者名は文字で持ち、アカウントと結びつけない。行から通報でき、運営が非表示にできる。依頼者の言葉: 「8 A」。
- 論点 9。発表者があとから同じ発表を置いても、何もしない。両方が並び、管理者が外部の行を手で外せる。依頼者の言葉: 「9 A」。
- 論点 10。1 つの回に足せる外部のスライドは、100 本まで。大きなカンファレンスでも収まる大きさにした。100 という数に、裏付けはない。依頼者の言葉: 「10 A」。
- 論点 11。外部の行は、リンクのページと「リンク」のタブの回の下にだけ出す。このサービスのスライドの後ろに、表紙なしで並べ、数は分ける。「スライド」のタブ、トップ、お知らせには出さない。依頼者の言葉: 「11 A」。
- 論点 12。発表者が URL を置く案と PDF は、次のスコープ以降に回す。issue #113 は開いたままにする。依頼者の言葉: 「12 A」。
- 論点 13。HTML のスライドが、埋め込んでよいことと、めくり方を示す決まりは、別の issue に記録し、最初のスコープには入れない。依頼者の言葉: 「13 A」。

細部は、作業役が決め、着地の案で依頼者に見せた(2026-11-28、「着地おk」)。

- 題名は 100 文字、発表者名は 50 文字まで(コミュニティの名前の 50 文字にそろえた)。
- 外部の行の並びは、足した順。
- 直す・外すは、どの管理者もできる(管理者同士は自由、という [コミュニティをつくる](f30-communities.md) の決まりにそろえた)。
- 通報と非表示は、1 つの条件に混ぜず、F46-AC19 と F46-AC25 に分けた。

受け入れた弱みは、次のとおりである。

- 発表者自身のサイトの HTML のスライドは、その場で見られない。相談のきっかけになった場面だが、最初のスコープではリンクのままにする。
- 題名は人が入れるので、誤りがありうる。元のスライドが消えても、発表者が埋め込み先を絞っても、サービスは取りに行かないので気づけない。直せるのは、管理者だけである。
- 発表者は、自分の名前と発表が載ったことを、知らないことがある。窓口は、通報とお問い合わせである。
- だれでもコミュニティを作れるので、スライドでない URL を並べる場所にも使える。
- 管理者が、回ごとに足す作業を続けるかは、分からない。エージェントを使う管理者がどれだけいるかの数字も、持っていない。
