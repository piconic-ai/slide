# F26 発表を書き起こした記事を添える

状態は実装済みです(第二スコープ)。ただし F26-AC23 と F26-AC24 は保留である(いまの版の総ページ数を取る方法が決まっていないので、働かない。判定の関数と画面の文言までを作ってあり、F26-AC24 のテストはまだない)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に来られなかった人が、あとから公開スライドを開く。スライドには図と短い見出ししかなく、発表者がなぜその設計にしたのかは口頭でしか話されていない。登壇者は、発表を終えたあとで、話した内容を文章に残したい。ただし、記事を書くことをスライドを置く条件にはしたくない。

## 得られる結果

作者は、発表を書き起こした記事を Markdown で書き、viewer のスライドの下に載せられる。読者は、スライドと、話された内容を同じページで読める。記事の中にページ番号つきの共有 URL を書くと、そのページの画像が入り、押すとスライドがそのページに移る。ほかの人のスライドのページを書くと、そのスライドへ移れ、引用として数えられる。

記事は、無くてもスライドは共有できる。置く流れに、入力を挟まない。置いた後に、書きたい人だけが書く。

## 体験の流れ

1. 作者が、スライドの編集の「記事」の枠から「記事を書く」を押し、記事の編集ページを開く。
2. Markdown で書く。「プレビュー」で見え方を確かめ、「下書きを保存」を押す。下書きの間は、作者だけが viewer で記事を読者と同じ見え方で確かめられる。
3. 話した内容のページを指したいときは、ページ番号つきの共有 URL(`https://slide.community/@handle/slug/3`)を、段落に 1 行だけで書く。
4. 「公開する」を押す。スライドが一般公開中なら、ログインしていない人の viewer にも、スライドの下に記事が載る。
5. 公開した後も、編集ページで直して保存すれば、すぐ反映される。載せたくなくなったら「公開を取り下げる」を押す。
6. 読者は、記事の中のページの画像を押す。自分のこのスライドのページなら、上のスライドがそのページに移り、スライドの位置までスクロールする。ほかの人のスライドのページなら、そのスライドのそのページが開く。

AI エージェントは、記事の下書きまで置ける([AI エージェントから置く](f23-agent-upload.md))。公開は、作者が編集ページで押す。

## 作る範囲

- 記事の保存。スライド 1 本につき 1 本で、版ではなくスライドに属する。状態は「下書き」と「公開中」の 2 つ。
- 記事の編集ページ(`/slides/:deck/article`)。「書く」「プレビュー」の切り替え、書き方の注記、下書きの保存、公開、取り下げ。
- スライドの編集の「記事」の枠。状態のタグ、最後に保存した日と字数、「記事を編集する」(記事が無いときは「記事を書く」)。
- viewer の「記事」の節。題名、説明、関連リンク([関連リンクを紐付ける](f27-related-links.md))の下、引用の節の上に置く。中身のないときは見出しごと出さない。
- Markdown の変換。サーバーで HTML にし、許可した要素と属性だけを出す。
- ページの埋め込み。段落にページ番号つきの共有 URL だけが 1 行で書かれているとき、そのページの画像([説明したいページを画像付きで共有する](f05-page-ogp.md))を出す。
- 記事の中の共有 URL へのリンクを、引用として数えること([引用でつながる](f24-citations.md))。

## 作らないこと

- サービスによる記事の生成と翻訳。作者(または作者の AI エージェント)が書く部分だけを作る([話した言葉といっしょに読む](f15-talk-reading.md))。
- 記事でページの画像以外の画像を使うこと。アップロードと保存が要る。ページの画像で足りる。
- 記事を読む間、スライドを横に追従させること。viewer の iframe の扱いの判断が要る。
- 参加者が記事を書くこと。参加者のレポートは、作者が関連リンクの「記事」として足す。
- 公開中の記事に別の下書きを持つこと(公開版と編集版の 2 本立て)。
- AI エージェントが記事を公開する、取り下げること。
- 独自の記法。ページの埋め込みは、共有 URL を 1 行で書くだけにする。

## 受け入れ条件

- **F26-AC1** 作者は、スライドの編集の「記事を書く」から記事の編集ページを開き、Markdown で書いて下書きを保存できる。
- **F26-AC2** 下書きの間、作者は viewer でスライドの下に記事を読者と同じ見え方で見られる。
- **F26-AC3** 下書きの間、作者以外の人の viewer に、記事が出ない。
- **F26-AC4** 「公開する」を押すと、スライドが一般公開中なら、ログインしていない人の viewer のスライドの下にも記事が出る。
- **F26-AC5** スライドが作者のみ限定公開の間は、記事が公開中でも、作者以外の人の viewer に記事が出ない。
- **F26-AC6** 「公開を取り下げる」を押すと、読者の viewer から記事が消え、状態が「下書き」に戻る。
- **F26-AC7** 公開中の記事を直して保存すると、読者の viewer に直した内容がすぐ出る。
- **F26-AC8** スライドの版を差し替えても、記事は残る。
- **F26-AC9** 記事は、スライド 1 本につき 1 本である。同じスライドの編集ページは、いつも同じ記事を開く。
- **F26-AC10** 見出し、段落、箇条書き、引用、コード、表、取り消し線、自動リンクが、記事として表示される。
- **F26-AC11** 本文の生の HTML は、文字として表示される。
- **F26-AC12** 本文の `<script>`、`<iframe>`、`<form>`、イベント属性、`style` 属性は、表示の HTML に入らない。
- **F26-AC13** 本文の `javascript:` など、`https:`、`http:`、`mailto:` 以外のリンクは、リンクとして出ない。
- **F26-AC14** 記事の中のリンクに、`rel="noopener nofollow ugc"` が付く。
- **F26-AC15** 記事の HTML は、viewer の管理 origin で出る。作者の HTML の sandbox の中には入らない。
- **F26-AC16** 本文が 50,000 文字を超えると、保存できず、理由が出る。ちょうど 50,000 文字なら保存できる。
- **F26-AC17** 段落に、その記事のスライドのページ番号つきの共有 URL だけを書くと、そのページの画像が出る。
- **F26-AC18** 記事の中のそのページの画像を押すと、上のスライドがそのページに移り、スライドの位置までスクロールする。
- **F26-AC19** 段落に、ほかの人の一般公開中のスライドのページ番号つきの共有 URL だけを書くと、そのページの画像と、作者名・題名・ページ番号が出る。
- **F26-AC20** ほかの人のスライドの画像を押すと、そのスライドのそのページが開く。
- **F26-AC21** 文の中に書いた共有 URL は、画像にならず、ふつうのリンクになる。
- **F26-AC22** 一般公開されていないスライド、存在しないスライドやページ、運営が非表示にしたスライド、停止中の作者のスライドの共有 URL を段落に書いても、画像も題名も出ず、ふつうのリンクになる。作者のみ限定公開のスライドの題名や存在が、記事から分からない。
- **F26-AC23** いまの版に無いページを指す共有 URL は、編集ページで、どの URL か、いまの版が何ページまでかが作者に伝わる。
- **F26-AC24** いまの版に無いページを指す共有 URL は、読者の viewer では、ふつうのリンクとして出る。
- **F26-AC25** 記事が何も保存されていない間、または下書きしか無い間、読者の viewer に「記事」の節が見出しごと出ない。
- **F26-AC26** スライドの編集に「記事」の枠が出る。記事があるときは、状態のタグ(「下書き」「公開中」)、最後に保存した日、字数が出る。
- **F26-AC27** ほかの人のスライドの記事を、保存、公開、取り下げできない。存在するかどうかも伝わらない。
- **F26-AC28** スライドを削除すると、記事も消える。
- **F26-AC29** 退会すると、その人のスライドの記事も消える。
- **F26-AC30** 編集ページで保存していない変更があるまま離れようとすると、確認が出る。
- **F26-AC31** 編集ページの入力欄の下に、ページ番号つきの共有 URL の書き方の注記が出る。

記事の中の共有 URL を引用として数えることは、[引用でつながる](f24-citations.md) の F24-AC19〜F24-AC21 で確かめる。

## 決めたこと

第二スコープを作るにあたり、次のように決めた(2026-11-22)。

- 記事はスライド 1 本につき 1 本。版ではなくスライドに属し、版を差し替えても残る。
- 記事の状態は「下書き」と「公開中」。読者に見えるのは、スライドが一般公開中で、記事が公開中のときだけ。作者は viewer で、下書きを読者と同じ見え方で確かめられる。
- 公開中の記事を直して保存すると、すぐ反映する。公開中の記事に別の下書きを持つ仕組みは作らない。
- Markdown は CommonMark と、GFM の表・取り消し線・自動リンクまで。生の HTML は使えない(文字として表示する)。表示はサーバーで HTML に変換し、許可した要素と属性だけを出す。依存を足すときは、生の HTML を既定で通さないものを選び、選んだ理由を設計の文書に書く。リンクは `https:` と `http:` と `mailto:` だけ、`rel="noopener nofollow ugc"` を付ける。
- 本文は 50,000 文字まで。
- ページの埋め込みは、段落にページ番号つきの共有 URL(`https://slide.community/@handle/slug/3` の形)だけが 1 行で書かれているときに行う。文の中の URL は、ふつうのリンクにする。独自の記法は作らない。
  - その記事のスライドの URL なら、そのページの画像(第一スコープのページごとの OGP 画像)を出し、押すと viewer の上のスライドがそのページに移る。
  - ほかの一般公開中のスライドの URL なら、そのページの画像と、「△△さんの『□□』3 ページ」の説明を出し、押すとそのスライドのそのページを開く。
  - 一般公開されていないスライド、存在しないスライドやページ、非表示・停止の作者のスライドなら、画像を出さず、ふつうのリンクにする。作者のみ限定公開のスライドの題名や存在を、記事から漏らさない。
- 記事の中の共有 URL へのリンク(埋め込みも、文の中のリンクも)は、スライドの中のリンクと同じく引用として数える。数えるのは記事が公開中の間だけ。自分のこのスライドへのリンクは数えない。
- いまの版に無いページを指す埋め込みは、編集ページで作者に知らせ、読者にはふつうのリンクを出す。
- 記事を書けるのはスライドの作者だけ。
- 記事の HTML は、viewer の管理 origin で出す。作者の HTML と同じ sandbox には入れない。変換の結果に script、`style` 属性、イベント属性、`iframe`、`form` が入らないことをテストで確かめる。
- viewer の並びは、スライド、題名と操作、説明、関連リンク、記事、引用の順。中身のない節は、見出しごと出さない。
- 記事の公開の操作は、AI エージェントには渡さない。下書きまでを置ける。
