# F29 イベントの発表として並ぶ

状態は実装済みです(第三スコープ。統合ブランチ `scope3` に入り、本番にはまだ反映していない。未決事項に、元のページへのリンクのグループを決めるリンクに、下書きのスライドのリンクを数えるかが残る)。2026-11-25 の依頼者の回答で、connpass のイベントの元のページへのリンクを、最初に保存したリンクのグループの URL にした(F29-AC14。issue #411)。実装の設計は [イベントの発表の実装設計](../dev/f29-event-talks.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に出られなかった人が、その回の発表をまとめて見たい。いまは、発表者がそれぞれ自分のスライドを SNS に流すだけで、同じ回の発表がどこにも集まらない。主催者が発表のスライドを集めて一覧を作るのは、手間がかかり、続かない。

発表者は、スライドの関連リンクに、すでにイベントのページの URL を入れている。それだけで、同じ回の発表が 1 つのページに並んでほしい。

## 得られる結果

作者がスライドの関連リンクに、connpass、Doorkeeper、Luma のイベントのページの URL を入れると、そのスライドがイベントの発表として、イベントのページ(`/events/:id`)に並ぶ。主催者は何も登録しない。サービスは、イベントのページを取りに行かない。

## 体験の流れ

1. 作者が、1 本の管理の「関連リンク」に、イベントのページの URL を入れる。URL の形からイベントだと分かるので、種類は「イベント」が選ばれた状態になる。
2. 種類が「イベント」の行の下に、どこに並ぶかが 1 文で出る(「Kanagawa.pm のイベントとして並びます。」)。
3. スライドを一般公開すると、そのイベントのページに、スライドが並ぶ。
4. 同じイベントの URL を入れたほかの作者のスライドも、同じページに並ぶ。
5. 1 本の管理の「発表したイベント」の枠で、自分のスライドが入っているイベントを確かめられる。
6. 外したいときは、関連リンクを消すか、種類を変える。

## 作る範囲

- 関連リンクの種類「イベント」(4 つ目の種類)と、URL の形からの既定。作者は種類を変えられる([関連リンクを紐付ける](f27-related-links.md))。
- イベントの URL を、イベントの鍵へそろえる処理。
- イベントの表と、関連リンクとイベントの対応の表。関連リンクを足す・消す・種類を変える・URL を変えるときに、対応を作り直す。
- イベントのページ `/events/:id`。カバー画像、頭(コミュニティのロゴと名前、イベント名、元のイベントのページへのリンク)、発表の一覧。
- 1 本の管理の「発表したイベント」の枠。
- 運営の画面の「イベント名を直す」。

## 作らないこと

- リンク先を取りに行くこと。イベント名、日時、場所、OGP を含め、取り込まない。connpass の利用規約(第 7 条 1 項 17 号)が、API 以外の方法でのアクセスを禁じているため。
- イベントの日時と場所の表示。持たないので、並び順はスライドの公開日時で決める。
- 主催者によるイベントの登録。URL から自動で決める。
- スライドの本文と記事の中のリンクからの紐づけ。照らすのは関連リンクだけにする。
- Peatix、TECH PLAY など、URL の形でイベントと分からないサービス。種類「イベント」を作者が選べば、ホスト名とパスを鍵にしたイベントになる。
- 「参加した」の申告。

## 受け入れ条件

- **F29-AC1** 1 本の管理の関連リンクに `https://<グループ>.connpass.com/event/<番号>/` か `https://connpass.com/event/<番号>/` を入れると、種類の既定が「イベント」になる。
- **F29-AC2** `https://<グループ>.doorkeeper.jp/events/<番号>` を入れると、種類の既定が「イベント」になる。
- **F29-AC3** `https://luma.com/<文字列>` か `https://lu.ma/<文字列>` を入れると、種類の既定が「イベント」になる。`discover`、`calendar`、`user`、`signin` など、Luma のサイトの経路の語のときは「イベント」にならない。
- **F29-AC4** 作者は、既定で選ばれた種類を変えられる。種類を「イベント」にしたリンクは、URL の形に関わらずイベントの鍵を持つ。
- **F29-AC5** 種類が「イベント」の関連リンクを持つ一般公開中のスライドは、そのイベントの `/events/:id` に並ぶ。
- **F29-AC6** 同じイベントの URL を、クエリ、フラグメント、末尾の `/`、ホスト名の大文字小文字、`http` と `https`、`lu.ma` と `luma.com` を変えて入れても、同じ 1 つのイベントになる。
- **F29-AC7** connpass は、グループの部分が違っても(無くても)、イベントの番号が同じなら同じイベントになる。
- **F29-AC8** イベント名は、そのイベントのリンクの題名のうち、最初に保存されたものである。後から別の題名で足しても変わらない。
- **F29-AC9** 題名のあるリンクが 1 つもないイベントは、サービス名と番号で出る(「connpass のイベント 410635」。Luma は文字列、その他はホスト名とパス)。
- **F29-AC10** イベントの一覧の並び順は、そのイベントで最初に一般公開されたスライドの公開日時の新しい順である。イベントのページの発表は、一般公開の新しい順に並ぶ。
- **F29-AC11** 関連リンクを消すか、種類を「イベント」から変えると、そのスライドはイベントのページから外れる。
- **F29-AC12** 作者のみ限定公開と非公開のスライドは、イベントのページに出ない。一般公開中のスライドが 1 本も無いイベントの `/events/:id` は 404 になる。
- **F29-AC13** スライドの本文や記事の中にイベントの URL があっても、そのスライドはイベントに入らない。
- **F29-AC14** イベントのページの、元のイベントのページへのリンクは、サービス名を入れた文(「connpass で見る」)で、`rel="noopener nofollow ugc"` が付いている。connpass のリンク先は、そのイベントに結びついた関連リンクのうち、最初に保存されたものが書いたグループの `https://<グループ>.connpass.com/event/<番号>/`(グループは小文字)で、そのリンクがグループを含まないときは `https://connpass.com/event/<番号>/` である。最初に保存されたリンクが消されると、残りのうち最も古いものに従う。
- **F29-AC15** 運営は、運営の画面でイベント名を直せる。直した名前が、イベントのページと一覧に出る。運営でない人は、その経路を通れない。
- **F29-AC16** 関連リンクを保存しても、イベントのページを開いても、サービスから外への通信が起きない。
- **F29-AC17** 1 本の管理で、種類が「イベント」の行の下に、どこに並ぶかが 1 文で出る。コミュニティに入るイベントは「(コミュニティ名) のイベントとして並びます。」、入らないイベントは「イベントとして並びます。」。
- **F29-AC18** 1 本の管理の「発表したイベント」の枠に、そのスライドが入っているイベントが、コミュニティ名とともに並ぶ。ここではイベントを選べない。イベントが無いときは、枠の中に、関連リンクから決まることが 1 文で出る。
- **F29-AC19** イベントのページの頭に、コミュニティのロゴと名前(コミュニティのページへのリンク)、イベント名、元のページへのリンク、「発表 n 本」が出る。日時と場所は出ない。コミュニティの無いイベントは、ロゴとコミュニティ名を出さない。
- **F29-AC20** コミュニティの無いイベントで、そのグループのコミュニティを作れる(connpass のグループ、Doorkeeper のグループの)とき、イベントのページに「このグループのコミュニティはまだありません」と「作る」が出る。「作る」は、紐づけ用リンクを入れた状態のコミュニティを作るページへ進む。
- **F29-AC21** イベントのページのカバー画像は、そのイベントが入っているコミュニティのカバー画像である。コミュニティの無いイベントは、イベントの番号から決まる 5 色の 1 つの既定の模様で、開くたびに同じになる。
- **F29-AC22** イベント名は、そのイベントが入っているコミュニティの管理者が直せる。管理者でない人と、ログインしていない人は直せない。コミュニティの無いイベントは、運営だけが直せる。
- **F29-AC23** 1 本のスライドは、いくつのイベントにも入れる。
- **F29-AC24** ログイン中の人が見るイベントのページに、その人がブロックしている人のスライドは出ない。「発表 n 本」の数にも入らない。
- **F29-AC25** 幅 375px で、イベントのページと 1 本の管理の関連リンクの枠が、横にはみ出さない。
- **F29-AC26** ヘルプに、イベントの紐づけの項目がある(関連リンクにイベントの URL を入れると並ぶこと、外し方、イベント名の決まり方)。日本語と英語の両方で読める。

## 決めたこと

第三スコープを作るにあたり、次のように決めた(2026-11-23、第三スコープの指示書)。

- 関連リンクの種類に「イベント」を足し、4 つにする。入れる項目は第二スコープと同じ(種類、URL、題名)(D-20)。
- 次の形の URL は、1 本の管理で種類の既定を「イベント」にする。作者は変えられる(D-21)。connpass: `https://<グループ>.connpass.com/event/<番号>/`、`https://connpass.com/event/<番号>/`。Doorkeeper: `https://<グループ>.doorkeeper.jp/events/<番号>`。Luma: `https://luma.com/<文字列>`、`https://lu.ma/<文字列>`(`discover`、`calendar`、`user`、`signin` など、Luma のサイトの経路の語は除く)。
- 種類が「イベント」のリンクの URL を、次のとおりそろえてイベントの鍵にする。`https` にする、ホスト名を小文字にする、クエリとフラグメントを捨てる、末尾の `/` をそろえる、`lu.ma` を `luma.com` にする。connpass は、グループに関わらずイベントの番号を鍵にする(D-22)。
- 1 つの鍵が 1 つのイベント。一般公開中のスライドが 1 本以上入ったイベントだけを、ページや一覧に出す(D-23)。
- イベント名は、そのイベントのリンクの題名のうち、最初に保存されたものを使う。直せるのは、そのイベントが入っているコミュニティの管理者だけ。コミュニティの無いイベントは、お問い合わせを受けて運営が直す。題名の無いものは、サービス名と番号で出す(D-24)。
- 日時と場所は持たない。イベントの並び順は、そのイベントで最初に一般公開されたスライドの公開日時で決める(D-25)。イベントの中の発表は、第二スコープの基準(一覧は新しい順に並べる)に従い、一般公開の新しい順にする。
- 照らすのは関連リンクだけ。スライド本文と記事の中のリンクは照らさない(D-26)。
- イベントのページの URL は `/events/:id`(サービスが振る番号)(D-27)。
- 1 本のスライドは、いくつのイベントにも入れる。外すときは、関連リンクを消すか種類を変える(D-28)。
- イベントの元のページへのリンクには、`rel="noopener nofollow ugc"` を付ける(D-29)。
- connpass のイベントの元のページへのリンクは、そのイベントに結びついた関連リンクのうち、最初に保存されたもののグループの URL にする。最初のリンクがグループを含まないときは、グループを含まない URL にする。最初のリンクが消されたら、残りのうち最も古いものに従う。鍵(D-22)は変えない(2026-11-25、依頼者の回答)。
- サービスから外のサイトへは取りに行かない(D-02)。例外は [Luma の配信でコミュニティに紐づける](f33-luma-feeds.md) の iCal 配信だけ。
- コミュニティの無いイベントのカバー画像は、イベントの番号から 5 色の 1 つを選んで既定の模様を出す(D-49)。

## 未決事項

- connpass のイベントの元のページへのリンクのグループを決める「最初に保存されたリンク」に、下書きや非公開のスライドのリンクも数えている(イベント名の決まり方と同じ。F29-AC14)。そのため、下書きに書いたグループが、公開中のイベントのページのリンク先に出ることがある。公開中のスライドのリンクだけに絞るかは、依頼者が決める(2026-11-25 の回答の後の確認。第三スコープの指示書の進み具合に記録した)。
