# F29 イベントの発表として並ぶ

状態は実装済みです(第三スコープ。統合ブランチ `scope3` に入り、本番にはまだ反映していない)。2026-11-25 の依頼者の回答で、connpass のイベントの元のページへのリンクを、最初に保存したリンクのグループの URL にし、2026-11-26 の回答で、そのリンクを公開中のスライドのものに絞った(F29-AC14。issue #411)。2026-11-27 に、依頼者との相談で、イベントのページという見せ方をやめ、リンクのページに置き換えると決めた([同じリンクでスライドが集まる](f45-link-gathering.md))。イベントの鍵と種類の仕組みは残る。新しい条件(F29-AC29〜F29-AC31)は未実装。実装の設計は [イベントの発表の実装設計](../dev/f29-event-talks.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に出られなかった人が、その回の発表をまとめて見たい。いまは、発表者がそれぞれ自分のスライドを SNS に流すだけで、同じ回の発表がどこにも集まらない。主催者が発表のスライドを集めて一覧を作るのは、手間がかかり、続かない。

発表者は、スライドの関連リンクに、すでにイベントのページの URL を入れている。それだけで、同じ回の発表が 1 つのページに並んでほしい。

## 得られる結果

作者がスライドの関連リンクに、connpass、Doorkeeper、Luma のイベントのページの URL を入れると、そのスライドが、そのイベントの URL のリンクのページ(`/link/…`。[同じリンクでスライドが集まる](f45-link-gathering.md))に、1 本でも並ぶ。主催者は何も登録しない。サービスは、イベントのページを取りに行かない。

## 体験の流れ

1. 作者が、1 本の管理の「関連リンク」に、イベントのページの URL を入れる。URL の形からイベントだと分かるので、種類は「イベント」になる。
2. 関連リンクの行の下に、どこに並ぶかが 1 文で出る(「Kanagawa.pm のページに並びます。」)。
3. スライドを一般公開すると、そのイベントのリンクのページに、スライドが並ぶ。
4. 同じイベントの URL を入れたほかの作者のスライドも、同じページに並ぶ。
5. 1 本の管理の「このスライドが並ぶページ」の枠で、自分のスライドが並ぶページを確かめられる。
6. 外したいときは、関連リンクを消す。

## 作る範囲

- 関連リンクの種類「イベント」(4 つ目の種類)と、URL の形からの既定。画面では種類を選ばせない(2026-11-27。[関連リンクを紐付ける](f27-related-links.md) の F27-AC87)。
- イベントの URL を、イベントの鍵へそろえる処理。
- イベントの表と、関連リンクとイベントの対応の表。関連リンクを足す・消す・種類を変える・URL を変えるときに、対応を作り直す。
- 1 本の管理の関連リンクの行の下の文と、「このスライドが並ぶページ」の枠(F29-AC29〜F29-AC31)。
- イベントのページ `/events/:id`、運営の画面の「イベント名を直す」、イベント名を直す経路は、作らない(2026-11-27 に、リンクのページに置き換えた。[同じリンクでスライドが集まる](f45-link-gathering.md))。

## 作らないこと

- リンク先を取りに行くこと。イベント名、日時、場所、OGP を含め、取り込まない。connpass の利用規約(第 7 条 1 項 17 号)が、API 以外の方法でのアクセスを禁じているため。
- イベントの日時と場所の表示。持たないので、並び順はスライドの公開日時で決める。
- 主催者によるイベントの登録。URL から自動で決める。
- スライドの本文と記事の中のリンクからの紐づけ。照らすのは関連リンクだけにする。
- Peatix、TECH PLAY など、URL の形でイベントと分からないサービス。種類「イベント」を選べば(いまは AI エージェントの道具だけ)、ホスト名とパスを鍵にしたイベントになる。画面で選べるようにするかは、集約でイベントの形を特別に扱うことになったので、決めなくてよくなった。画面から入れた URL は、種類を問わず、リンクのページに集まる([関連リンクを紐付ける](f27-related-links.md) の F27-AC90)。
- イベントのページ。リンクのページに置き換え、`/events/:id` からの転送だけを残す([同じリンクでスライドが集まる](f45-link-gathering.md))。
- ページの見出し(イベント名)を直す画面と経路。管理者にも運営にも、作らない。
- 「参加した」の申告。

## 決めたこと

第三スコープを作るにあたり、次のように決めた(2026-11-23、第三スコープの指示書)。

- 関連リンクの種類に「イベント」を足し、4 つにする。入れる項目は第二スコープと同じ(種類、URL、題名)(D-20)。
- 次の形の URL は、1 本の管理で種類の既定を「イベント」にする。作者は変えられる(D-21)。connpass: `https://<グループ>.connpass.com/event/<番号>/`、`https://connpass.com/event/<番号>/`。Doorkeeper: `https://<グループ>.doorkeeper.jp/events/<番号>`。Luma: `https://luma.com/<文字列>`、`https://lu.ma/<文字列>`(`discover`、`calendar`、`user`、`signin` など、Luma のサイトの経路の語は除く)。
- 種類が「イベント」のリンクの URL を、次のとおりそろえてイベントの鍵にする。`https` にする、ホスト名を小文字にする、クエリとフラグメントを捨てる、末尾の `/` をそろえる、`lu.ma` を `luma.com` にする。connpass は、グループに関わらずイベントの番号を鍵にする(D-22)。
- 1 つの鍵が 1 つのイベント。一般公開中のスライドが 1 本以上入ったイベントだけを、ページや一覧に出す(D-23。2026-11-27 に改めた。ページは、イベントのページから、リンクのページに変わった。イベントの形のリンクは、1 本でもページを出す。[同じリンクでスライドが集まる](f45-link-gathering.md) の F45-AC3)。
- イベント名は、そのイベントのリンクの題名のうち、最初に保存されたものを使う。直せるのは、そのイベントが入っているコミュニティの管理者だけ。コミュニティの無いイベントは、お問い合わせを受けて運営が直す。題名の無いものは、サービス名と番号で出す(D-24。2026-11-27 に改めた。見出しは、最初に保存された題名か、なければサイト名と URL にし、直す機能はなくした。いまのイベント名は、見出しとして引き継ぐ。F45-AC10、F45-AC11、F45-AC20)。
- 日時と場所は持たない。イベントの並び順は、そのイベントで最初に一般公開されたスライドの公開日時で決める(D-25)。イベントの中の発表は、第二スコープの基準(一覧は新しい順に並べる)に従い、一般公開の新しい順にする(D-25。並び順の基準は、リンクのページの中の並びに引き継いだ。F45-AC1)。
- 照らすのは関連リンクだけ。スライド本文と記事の中のリンクは照らさない(D-26)。
- イベントのページの URL は `/events/:id`(サービスが振る番号)(D-27。2026-11-27 に改めた。リンクのページの URL は `/link/<URL>` で、`/events/:id` は、そこへ転送する。F45-AC9)。
- 1 本のスライドは、いくつのイベントにも入れる。外すときは、関連リンクを消す(D-28。種類を変える方法は、画面から外した)。
- イベントの元のページへのリンクには、`rel="noopener nofollow ugc"` を付ける(D-29)。
- connpass のイベントの元のページへのリンクは、そのイベントに結びついた、公開中のスライドの関連リンクのうち、最初に保存されたもののグループの URL にする(下書きは数えない。2026-11-26、依頼者の回答)。最初のリンクがグループを含まないときは、グループを含まない URL にする。最初のリンクが消されたら、残りのうち最も古いものに従う。鍵(D-22)は変えない(2026-11-25、依頼者の回答)。
- サービスから外のサイトへは取りに行かない(D-02)。例外は [Luma の配信でコミュニティに紐づける](f33-luma-feeds.md) の iCal 配信だけ。
- コミュニティの無いイベントのカバー画像は、イベントの番号から 5 色の 1 つを選んで既定の模様を出す(D-49。2026-11-27 に改めた。コミュニティの無いリンクのページには、カバー画像を出さない。F45-AC17)。

- 第四スコープで、ヘルプは、1 枚のページの節から、したいことごとの記事に分かれる([ヘルプで答えを見つける](f36-help-answers.md))。この文書の「ヘルプの節」「ヘルプの項目」は、対応する記事のことである。ヘルプの節の位置(`/help#<id>`)を指す書き方は、記事の URL を指す書き方に直す。

2026-11-27 に、依頼者が、イベントのページという見せ方をやめると決めた(相談のページ: https://claude.ai/artifact/6R852hRvSHyzKKax8piv8R)。

- イベントを集める仕組み(イベントの鍵、種類「イベント」、Luma の配信)は残す。変えるのは見せ方で、イベントのページを、リンクのページに置き換える。依頼者の言葉: 「今のイベント集約の仕組みは残したいよ。イベントという見せ方ではなく、リンクという見せ方になるだけ。」
- 画面の「イベント」という言葉は、括りの名前としては使わない。関連リンクの種類名「イベント」は残す(F29-AC29、F29-AC30)。
- 元のページへのリンク先の決め方、「このグループのコミュニティはまだありません」と「作る」、イベントの鍵で引く順は、リンクのページに引き継ぐ(F45-AC25、F45-AC27、F45-AC28)。
- 管理者と運営が、イベント名を直せる経路は、なくす。複雑にしないためである。いまのイベント名は、見出しとして引き継ぐ。
