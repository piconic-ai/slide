# F04 発表用と観客用の画面を分ける

状態は保留です。トップページで約束する体験に含めないため、利用場面と優先順位を見直すまで着手しません。

## 利用場面

登壇者がノート PC をプロジェクターにつなぐ。手元では現在・次のページと経過時間を見たいが、観客にはスライドだけを見せたい。発表画面を二つ開いて操作する。

## 得られる結果

同じ資料を使い、次の内容と持ち時間を確認しながら発表を進められる。

## 体験の流れ

1. 一般公開済み、または作者のみ限定公開の対応資料からプレゼンターモードを開始する。
2. 観客用ウィンドウを外部ディスプレイへ移す。
3. 手元の操作でページを進め、観客画面の追従を確認する。

## 作る範囲

- 同じ端末の二つのウィンドウで、ページ・タイマー・現在と次のページを表示する。
- 発表ごとに独立したセッションを作り、片方を開き直したとき現在位置を復元する。
- 発表者ノートは手元のセッションだけに置く。

## 作らないこと

- 別端末の観客をリアルタイム同期すること。
- 秘密のノートを公開 HTML に埋め込み、非表示だけで保護したと扱うこと。

## 受け入れ条件

- 作者のみ限定公開で、作者の同じ端末にある二つの画面を使って発表を終えられる。観客画面を外部ディスプレイへ映しても、第三者への Web 閲覧権限は生じない。
- 発表中のセッションは更新でき、二つの発表を同時に開いても操作が混線しない。
- 未対応資料では同期できると誤表示しない。
- 公開版の置き換えで進行中の発表に影響することを事前に伝え、取得不能時に勝手に別の版へ移らない。

## 操作の例と初期の制約

- 箇条書きを一つずつ表示する資料では、右キーで次の項目を出し、全項目を出してから次のページへ進む。最初の対応ツールで、この操作とスライド送りが二重に動かないことを確認する。
- 発表中に一般公開版を更新しても、発表画面だけは開始時の版を読み続けられる仕組みは後回しにする。初期は発表中の版を更新しない運用とし、更新時には中断の可能性を知らせる。

技術上の制約は [開発設計](../dev/design.md#deployment) を参照してください。
