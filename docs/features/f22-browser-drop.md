# F22 スライドを、ドロップして置く

状態は実装中です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇の前日、エンジニアが AI や作成ツールで HTML スライドを作り終える。置き場を自分で作り込む時間はない。GitHub App の導入、リポジトリの連携、workflow の設定をしている余裕もない。できあがった HTML か zip を、そのまま渡して済ませたい。

## 得られる結果

できあがった HTML か zip をトップページに落とすだけで、スライドが置かれる。置いた時点で、作者だけが見られる URL があり、確かめてから公開できる。直した版は、同じ URL のまま差し替えられる。

## 体験の流れ

1. トップか「スライドの管理」に、HTML 1 ファイルか zip をドロップする(または「ファイルを選ぶ」)。
2. ログイン中なら、そのまま受け取る。ログインしていなければ、ファイルをブラウザの中に預かり、枠を「選んだ後」の表示に変える。「GitHub でログインして続ける」を押すと GitHub へ進み、戻ると預かったファイルを自動で受け取る。
3. 受け取ったスライドは、作者だけが見られる状態で、1 本の管理ページに開く。題名と URL の名前は、HTML の `<title>` とファイル名から決めてある。
4. 表示を確かめ、必要なら URL の名前を直して、「公開する」を押す([作者のみ限定公開で発表し、一般公開する](f02-publication.md))。
5. 直した版は、1 本の管理ページにドロップする。公開中の版は、入れ替えの操作を押すまで変わらない。

## 作る範囲

- トップ、「スライドの管理」、1 本の管理ページ(差し替え)のドロップ枠。
- HTML 1 ファイルと zip の受け取り。zip はブラウザで展開し、受け取りの API はファイル単位のままにする。
- 送る前の、種類・大きさ・数の確認と、断る理由の表示。
- ページを伝える script の 1 行を、送り手(ブラウザ)が足すこと。
- ログイン前に選ばれたファイルを、ブラウザの中に預かること。
- 題名と URL の名前を決めること。公開する前に URL の名前を変えること。
- 受け取りを GitHub から切り離すこと。開始は、ログイン中の作者の session(ブラウザ)か、[AI エージェントから置く](f23-agent-upload.md) の認可で行う。
- 招待制。運営が登録した GitHub アカウントの人だけが置ける。

## 作らないこと

- フォルダのドロップ、PDF、zip 以外の圧縮形式。
- 公開した後に URL の名前を変えること。
- 未ビルドの Markdown を受け取って、サービス側でビルドすること。
- GitHub のリポジトリからスライドを送ること。[GitHub からスライドを更新する](f01-github-deploy.md) は、やめた。
- 中身がスライドかどうかの判定。受け取るのはビルド済みの静的ファイルで、ページを伝える script のない HTML も、そのまま表示する。
- 登録していない人のログインと受け取り。知らない人に開く前に済ませることが残っているためである([サービスの基本の備え](../dev/service-basics.md#知らない人に開く前に済ませること))。

## 受け入れ条件

- **F22-AC1** ログイン中の作者が、トップに HTML 1 ファイルをドロップすると、1 本の管理ページが開き、そのスライドを作者だけが見られる。
- **F22-AC2** 同じことが「ファイルを選ぶ」からでもでき、キーボードだけでもできる。
- **F22-AC3** 画像と CSS を含む zip をドロップすると、プレビューで画像と CSS が読み込まれる。
- **F22-AC4** zip の中身が 1 つのフォルダに入っているとき、そのフォルダの `index.html` が最初のページになる。
- **F22-AC5** `index.html` が決まらない zip は受け取らず、理由を出す。
- **F22-AC6** 上限(1 つの版の大きさ、1 ファイルの大きさ、ファイルの数、スライドの本数)を超えるものは受け取らず、どの上限を超えたかを出す。
- **F22-AC7** 受け取った HTML に、ページを伝える script が 1 つだけ入っている。既に入っている HTML には足さない。
- **F22-AC8** 置いたスライドの viewer で、ページをめくるとアドレスバーのページ番号が変わる(`#6` の綴りのスライドの場合)。
- **F22-AC9** ログインしていない人がファイルを選ぶと、枠が「選んだ後」の表示に変わり、ファイル名と大きさが出る。この時点では、サーバーに何も送らない。
- **F22-AC10** 「GitHub でログインして続ける」からログインして戻ると、預かったファイルが受け取られ、1 本の管理ページが開く。
- **F22-AC11** 預かったファイルが無い状態でログインから戻ると、ふつうのログイン中のトップが出る。エラーは出ない。
- **F22-AC12** 「別のファイルにする」を押すと、預かったファイルが消え、元のドロップ枠に戻る。
- **F22-AC13** 題名は HTML の `<title>` になる。URL の名前は、題名、ファイル名、`slide` の順で元にして決まり、同じ人の中で重ならない。
- **F22-AC14** 公開する前は、1 本の管理ページで URL の名前を変えられる。公開した後は変えられない。
- **F22-AC15** 公開中のスライドに新しい版をドロップしても、共有 URL で見える版は変わらない。入れ替えの操作を押すと、同じ URL で新しい版になる。
- **F22-AC16** 招待されていない人がドロップしても、受け取られず、招待制であることが伝わる。
- **F22-AC17** ほかの人のスライドには、差し替えを送れない。ログインしていない状態で、受け取りの経路に直接送っても受け取られない。
- **F22-AC18** GitHub の OIDC のトークンでは、受け取りを開始できない。
- **F22-AC19** 空の D1 に、migration を最初から最後まで適用できる。
- **F22-AC20** 受け取りの失敗や再送で、公開中の版が途中のファイルに置き換わらない。
- **F22-AC21** 運営が登録した GitHub アカウントの人は、ログインでき、自分のスライドを置き、公開し、管理できる。
- **F22-AC22** 登録していない人がログインしようとすると、ログインできず、招待制であることが伝わる。
- **F22-AC23** 登録した人は、ほかの作者のスライドの管理画面、作者限定の表示、受け取り、公開の操作に届かない。
- **F22-AC24** 登録から外された人は、ログイン・受け取り・公開ができない。公開済みのスライドは残り、運営が 1 つずつ非表示にできる。
- **F22-AC25** 2 人の作者が、同じ URL の名前(slug)のスライドを、それぞれ持てる。それぞれの共有 URL は、それぞれのスライドを開く。
- **F22-AC26** GitHub のログイン名から作る handle が、ほかの人の handle とぶつかる人は、ログインできず、理由と問い合わせ先が伝わる。
- **F22-AC27** ログイン中の作者が、「スライドの管理」のドロップ枠に HTML 1 ファイルか zip をドロップすると、1 本の管理ページが開く。
- **F22-AC28** 1 本の管理ページの版の履歴に、出どころ(ブラウザ、AI エージェント)と受け取った日時が出る。commit や実行番号は出ない。
- **F22-AC29** `POST /slides/connect` は 404 になる。
- **F22-AC30** リポジトリの root に `action.yml` がない。アップロードの確認用の workflow がない。
- **F22-AC31** 空の D1 に migration をすべて適用した後のスキーマに、`repository_bindings` の表と、リポジトリに従う公開のための列がない。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 招待制を続ける(`AUTHOR_GITHUB_IDS`)。招待されていない人がログインしてドロップしたときは、受け取らずに、いまは招待制であることを伝える。
- 受け取るのは、HTML 1 ファイルと zip。フォルダのドロップは対象外にする。
- zip はブラウザで展開し、受け取りの API はファイル単位のままにする。zip の直下に `index.html` がなく、1 つのフォルダの中にあるときは、そのフォルダを根にする。HTML 1 ファイルは `index.html` として置く。`index.html` が決まらない zip は、受け取る前に断る。
- 上限は現行のままにする(`src/uploads/limits.ts`。1 つの版 10MB、1 ファイル 5MB、100 ファイル、1 人 20 本)。超えるものは、送る前にブラウザで断り、どの上限を超えたかを伝える。
- ページを伝える script の 1 行は、送り手が足す(ブラウザの JS、MCP の受け口)。判定は `scripts/page-script.mjs` と同じにし、処理を共有する。Worker が配るときに byte を変えない、という方針は保つ。
- ログイン前に選ばれたファイルは、ブラウザの IndexedDB に預かる。預かるのは 1 件だけで、24 時間たったら捨てる。上限は上と同じ。戻ったときに無ければ、何も出さない。
- URL の名前は、`<title>`、ファイル名、`slide` の順で元にし、既存の slug の規則に合わせて作る。同じ人の中で重なったら `-2`、`-3` を付ける。公開する前は、1 本の管理ページで変えられる。公開した後に変える仕組みは作らない。
- 置いた直後は、作者だけが見られる。公開中のスライドに新しい版をドロップしたときも、公開中の版は自動では入れ替えない。1 本の管理ページで、入れ替える操作を 1 回押す。
- 受け取りを GitHub から切り離す。開始は、ログイン中の作者の session(ブラウザ)か、MCP の認可で行う。GitHub の OIDC での開始はなくす。`deployments` の GitHub 由来の列(`source_sha`、`run_id`、`repository_id` など)は消し、出どころ(ブラウザ、MCP)を表す列に置き換える。
- スライド(deck)は、リポジトリの連携なしで作る。公開の方式は手動だけにし、リポジトリに従う方式(`repository`)はなくす。
- 本番のデータは空にしてよい。GitHub からの更新は、コード、経路、テーブル、文書ごと取り除き、互換のための経路や、使わない列を残さない。既存の行を新しい形へ移す処理は書かない。
- 画面の文言は、日本語と英語の両方を用意する。

[GitHub からスライドを更新する](f01-github-deploy.md) から、次の条件を引き継いだ。意味は変えていない。「アップロード」は「受け取り」に読み替える。

| 元の ID | 引き継いだ ID |
| --- | --- |
| F01-AC2 | F22-AC6、F22-AC17 |
| F01-AC3 | F22-AC20 |
| F01-AC5 | F22-AC21 |
| F01-AC6 | F22-AC22 |
| F01-AC7 | F22-AC23 |
| F01-AC8 | F22-AC24 |
| F01-AC9 | F22-AC25 |
| F01-AC10 | F22-AC26 |

誰が使えるかについては、次のように決めてある(2026-11-17)。

- 作者(運営を兼ねる)のほかに、作者が招いた人も、作者として使えるようにする。招いた人は、GitHub の user ID を設定の一覧に登録する。一覧を変える PR は、誰に権限を与えるかを決める変更なので、作者が確かめてから merge する。
- 招いた人を止めるときは、一覧から外す。アカウントの停止([知らない人のスライドも、安心して開ける](f17-safe-viewing.md))は、理由を本人に伝え、スライドをまとめて読めなくする。
- slug は、作者ごとの名前にする。共有 URL が `/@handle/slug` なので、作者ごとに同じ slug を使えるのが自然である。
- handle がぶつかったときは、ログインを断り、理由と問い合わせ先を伝える。GitHub 側の情報を正しいものとして扱い、運営が handle を手で直す。
