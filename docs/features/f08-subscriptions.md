# F08 利用に合ったプランを契約する

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

継続的に登壇する作者が、自分のドメインと閲覧分析を使いたくなる。個人向け PRO を契約し、組織で限定共有を始める担当者は TEAM を選ぶ。

## 得られる結果

公開共有から始め、必要になった用途に合わせて有料機能を利用できる。

## 体験の流れ

1. プランごとの機能と料金を確認する。
2. 対象の個人またはチームのワークスペースで契約する。
3. 契約状態と更新日を確認し、変更・解約する。

## 作る範囲

- PRO は独自ドメイン・大容量・閲覧分析。TEAM は PRO に加えチーム限定共有・SSO。
- ワークスペース単位の契約と、サーバーでの利用権限の判定。
- 決済通知の再送や順序の違いを処理し、契約状態を照合する。

## 作らないこと

- 生成クレジット、広告非表示を目的にしたプラン。
- 契約失効を理由に資料を削除したり、チーム限定資料を一般公開したりすること。

## 受け入れ条件

- 決済からの戻り先を開いただけでは有料機能が有効にならない。
- 通知が重複しても契約や請求の扱いが重複しない。
- 解約後も既存の資料購入権限は、作者の契約と独立して保持する。

## 未決事項

- 価格・請求周期・TEAM の席数方式。
- Stripe Billing の採用、支払い失敗時の猶予と各機能のダウングレード方針。

技術上の制約は [開発設計](../dev/design.md#billing) を参照してください。
