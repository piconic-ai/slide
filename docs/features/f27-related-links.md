# F27 関連リンクを紐付ける

状態は実装済みです(第二スコープ)。2026-11-25 に、すでにある URL を足すことを断る条件と、入れた URL・整えた URL・正規化した URL を持つ条件、押したときに URL を確かめる画面の条件を足した(F27-AC44〜F27-AC46、F27-AC48〜F27-AC59、[AI エージェントから置く](f23-agent-upload.md) の F23-AC39〜F23-AC41。未実装。正規化の規則は、未決事項にある)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、発表を終えたあとで、録画、ブログの報告、リポジトリを、スライドに添えたい。読者は、スライドを読んで、発表の録画や補足の記事も見たい。いまは、それらがスライドの外に散らばっていて、たどれない。

## 得られる結果

作者が、録画やブログ、その他のリンクをスライドに足すと、viewer の題名の下に並ぶ。読者は、スライドから録画や補足の記事へ進める。リンクは、無くてもスライドは共有できる。置く流れに、入力を挟まない。

## 体験の流れ

1. 作者が、スライドの編集の「関連リンク」の枠を開く。
2. URL(と、あれば題名)を入れて「追加する」を押す。種類(動画、記事、その他)は、URL から決まる。
3. 読者の viewer の、題名の下に、足した順で種類のアイコン、種類名、題名、サイト名が並ぶ。
4. 要らなくなったリンクは、「外す」を押して消す。

AI エージェントは、関連リンクを足す・外すことができる([AI エージェントから置く](f23-agent-upload.md))。

## 作る範囲

- 関連リンクの保存(スライドに属する。種類、URL、題名(任意)、足した順)。種類は URL のホスト名から推定する。
- スライドの編集の「関連リンク」の枠。既存のリンクの行(種類のアイコン、種類名、題名、サイト名、「外す」)と、追加のフォーム(URL、題名(任意)、「追加する」。種類の選択はない)。
- viewer の「関連リンク」の節。スライドの題名の下に、丸いリンクを横に並べ、折り返す。中身のないときは、見出しごと出さない。
- スライドの編集の、差し替えのドロップ枠の注記「記事と関連リンクも残ります。」。

## 作らないこと

- 動画の埋め込み。viewer の CSP を広げないため、リンクだけにする。
- リンク先の題名や画像の自動取得。一度作ったが取り除いた(依頼者の判断 2026-11-23)。connpass などの利用規約が、自動のアクセスを禁じているため、いずれのサイトも取得しない。題名は作者が入れ、入れなければサイト名を出す。
- リンクの並べ替え。足した順に並べる。
- 関連リンクを引用として数えること。共有 URL が入っていても数えない(引用はスライドと記事の中のリンクだけ)。
- 参加者がリンクを足すこと。参加者のレポートは、作者が「記事」として足す。
- イベントの紐付け、同じイベントの発表、イベントのページ。第三スコープでコミュニティと合わせて設計する。

## 決めたこと

第二スコープを作るにあたり、次のように決めた(2026-11-22)。

- 種類は「動画」「記事」「その他」の 3 つ。1 本のスライドに 10 件まで。
- 種類は、作者に選ばせず、URL のホスト名から推定する(依頼者の判断、2026-11-23。入力を減らすため。一覧にないものは「その他」)。推定の一覧は、1 か所の純粋なデータ(`src/links/kind-hosts.ts`)に置く。
- 入れるのは URL(`https:` だけ)と題名(100 文字まで、任意)。サイト名は URL のホスト名から出す。
- リンク先を取りに行かない(D-51)。一度は、題名を空にして足したときだけ取る自動取得を作ったが(2026-11-23)、同じ日に依頼者の判断で取り除いた。connpass の利用規約(第 7 条 17 号。API 以外の方法でのクローリング、スクレイピング、その他のアクセスの禁止)のように、自動のアクセスを禁じるサイトがあり、サイトごとの可否を持ち続けるより、いずれのサイトも取得しないことにした。題名は任意で、入れなければ題名なしで保存し、サイト名(ホスト名)だけを出す。
- 並び順は足した順。並べ替えは作らない。
- viewer では、スライドが一般公開中のときに出す。作者は作者のみ限定公開の間も viewer で確かめられる。
- 関連リンクは引用として数えない。共有 URL が入っていても数えない(引用はスライドと記事の中のリンクだけ)。
- 動画は埋め込まない。viewer の CSP を変えない。
- viewer の並びは、スライド、題名と操作、説明、関連リンク、記事、引用の順([発表を書き起こした記事を添える](f26-article.md))。

第二スコープの確認で、次のように決めた(2026-11-25、依頼者。issue #366 の D10)。

- 1 本のスライドに、すでにある URL を足そうとしたときは、断って「すでに足してあります」と伝える(F27-AC44、AI エージェントの道具では F23-AC39)。これまでは、暫定で許していた。同じリンクが 2 つ並んでも、読者に得るものがないためである。
- 関連リンクは、作者が入れたとおりの URL と、正規化した URL の両方を持つ(2026-11-25、依頼者)。すでにあるかどうかは、正規化した URL で確かめる(F27-AC44〜F27-AC46、F27-AC48)。(画面に出す URL は、同じ日に、入れたとおりの URL から整えた URL に変えた。下を参照)正規化には、ドメインごとの規則を持ってよい。依頼者の言葉: 「これは力をいれる価値があるところ。ドメインごとにルールを用意してもよいくらいだと思う。」
- 上限の 10 件に達したスライドに、すでにある URL を足そうとしたときは、重複の理由(「すでに足してあります」)を出す(2026-11-25、依頼者。F27-AC49、F23-AC40)。作者が知りたいのは、そのリンクがもうあることだからである。
- リンク先の URL は整えてから使い、押したときに URL の全体を確かめられるようにする(2026-11-25、依頼者。URL を押す人の安全のため)。依頼者の言葉: 「入れた通りのURLと言いましたが、sanitizeはした方が良さそうですね。これはURLをクリックする人の安全のため。クリックする時に、フルのURLを提示するのも必要そう。」
  - 1 つの関連リンクは、3 つの形を持つ。作者が入れたとおりの URL(記録として残し、画面には出さない)、整えた URL(href と確認の画面に使う)、正規化した URL(すでにあるかの確かめだけに使う)。
  - 整える内容: ユーザー名やパスワードを含む URL は、足すときに断る(F27-AC50)。国際化ドメイン名は ASCII の表記(punycode)のまま。見えない文字、向きを変える文字は `%` の形で出す(F27-AC52)。追跡用のクエリ(`utm_` で始まるもの、`fbclid`、`gclid`)と、招待の token(Luma の `tk`)を除く(F27-AC51)。除くクエリのほかの候補は、未決事項の正規化の表にある提案のままである。
  - Luma の `tk` は、除く(未決事項に挙げた 3 つの案のうち、足すときに除く案を採った)。招待のリンクを貼っても、token が公開されないようにするためである。
  - viewer で関連リンクを押すと、確認の画面を出し、整えた URL の全体と「開く」「キャンセル」を見せる(F27-AC53〜F27-AC58)。スクリプトが動かないときは、確認せずに移る。
  - 記事の中のリンクにも、同じ整え方と確認の画面を使う([発表を書き起こした記事を添える](f26-article.md) の F26-AC96〜F26-AC99)。
  - いまある関連リンクの、整えた URL と正規化した URL は、migration の中で、いま保存している `url`(URL として読んだ形、`href`)から作る(2026-11-25、依頼者が提案した案を採った)。いまの行は入れたとおりの文字を持たないので、`url` の値を、入れたとおりの URL としても扱う。整える規則か正規化の規則を変えたときは、migration で作り直す。
- 国際化ドメイン名(日本語のドメインなど)のサイト名は、ASCII の表記(punycode)のまま出す(いまのまま。理由は[実装設計](../dev/f27-related-links.md#サイト名))。見た目が似た別のドメインを、本物のサイト名に見せないためである。
