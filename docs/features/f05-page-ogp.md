# F05 説明したいページを画像付きで共有する

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

読者が資料の中の構成図を同僚に紹介する。資料の表紙だけではどの話か伝わらないため、そのページへのリンクを送り、チャット上のプレビューで内容を示す。

## 得られる結果

資料全体ではなく、伝えたいページを相手が開く前から識別できる。

## 体験の流れ

1. 作者は必要ならページ画像を作り、ページ番号とともにアップロードする。画像を用意することは必須にしない。
2. 読者がページ単位の共有リンクを取得する。
3. 作者の画像があれば優先して使う。なければサービスがそのページの画像を初回に生成・保存し、以後は同じ画像を返す。
4. 共有先がリンクのメタデータを取得し、ページ画像と見出しを表示する。

## 作る範囲

- HTTP のページ URL ごとのタイトル・説明・OGP 画像。
- 作者の画像がないときは、公開を許可されたページだけをオンデマンドで撮影する。全ページをアップロード時に一括生成しない。
- 同じ版・ページ・言語・描画設定の生成を重複させず、生成中・失敗時には用意済みの代替画像を返す。
- 有料ページは作者が公開を認めた販売用情報だけでプレビューする。

## 作らないこと

- リンクが開かれるたびに作り直すこと。画像は HTML のスクリーンショットであり、生成 AI は使わない。
- 本文や画像が非公開のページを、OGP から見せること。

## 受け入れ条件

- fragment だけに依存せず、サーバーが共有対象のページを判定できる。
- 別の版や別言語の画像と混ざらない。
- 画像が欠けても資料を開け、購入前の URL から保護されたページ画像を取得できない。

## SNS での表示方針

- X など SNS の大きいカード画像を基準に、初期案は 1200 × 630 px の PNG または JPEG。実際の投稿で切り抜き、文字の可読性、反映速度を確認して確定する。
- SNS が一度取得したカード画像をいつ更新するかは、その SNS が決める。作者が資料を直したり非公開にしても、過去の投稿に古い画像がしばらく残る場合があることを共有設定で説明する。

技術上の制約は [開発設計](../dev/design.md#access-control) を参照してください。

## 未決事項

- 初回生成を待つ時間、生成失敗時の再試行間隔、SNS ごとの推奨比率。
- オンデマンド撮影の実行時間と回数を測り、初期の上限を調整する。
