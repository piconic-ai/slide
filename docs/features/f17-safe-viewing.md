# F17 知らない人のスライドも、安心して開ける

状態は実装中です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

読者が、SNS で見かけた知らない人の公開スライドを開く。動くスライドは JS を実行するので、勝手に別のページへ飛ばされたり、ファイルをダウンロードさせられたり、ログイン中のサービスを操作されたりしないか不安になる。

## 得られる結果

読者は作者を知らなくても、デモを動かしてよいと判断できる。作者は、読む人に警戒されずに動くスライドを届けられる。

## 体験の流れ

1. 読者が公開スライドの URL を開く。
2. スライドのデモをさわる。
3. スライドが親ページの移動、別タブ、ダウンロード、フォーム送信を試みても、ブラウザが止める。
4. 読者は、どのスライドにも共通して止められている操作と、スライドが外部と通信できることを、ヘルプページで確かめる。
5. 読者をだます内容だと思ったら、ログインして通報する。ログインしていなければ、通報を押したときにログインを求められる。
6. 運営は、運営の画面で通報を確かめて、スライドを非表示にする。作者の管理画面には、非表示にされたことと理由が出る。

## 作る範囲

- 作者の HTML を sandbox 付きの iframe で、管理画面とは別の origin から配る。
- 親ページの移動、popup、ダウンロード、フォーム送信、service worker の登録を許さない。
- 外部への通信は止めない。外部と通信できることは、ヘルプページで読者に説明する。
- 読者に、スライドに止めている操作をヘルプページで示す。
- ログインした読者がスライドを通報できる。通報は、運営の画面の一覧に出る。
- 運営がスライドを非表示にし、アカウントを停止できる。
- 運営の画面を `admin.slide.community` に置き、Cloudflare Access で守る。

## 作らないこと

- 作者の JS を静的に解析して、危険なスライドを判定・拒否すること。
- 制限を外して動かすための、読者向けの切り替え。
- 外部への通信の遮断。API を使うデモ、CDN のライブラリ、Web フォント、動画は動くスライドの価値なので、止めずに、ヘルプページで説明する。
- 通報の件数だけで自動的に非表示にすること。
- ログインなしの通報。一旦作らない。通報の保存の形は、あとで足せるように、ログインの有無に依存させない。
- 通報の通知。通知の仕組み(#60)が決まってから載せる。それまで、運営は一覧を見に行く。
- 運営の GitHub ID を、アプリの設定で持つこと。設定を変える PR で運営を増やせてしまうためである。
- 運営の中の役割分け。Cloudflare Access の policy に入っている人が運営、の 1 段だけにする。
- 手元の script で D1 を書き換える運営の操作。記録が人の注意に頼るためである。

## 受け入れ条件

- **F17-AC1** 作者の JS が、slide のログイン情報・管理画面の DOM・別の作者のスライドに届かない。
- **F17-AC2** 判定は JS の戻り値ではなく、外に出た request、開いたページの数、ダウンロードの有無で確かめる。
- **F17-AC3** 外部への通信と、同じスライド内の相対パスのファイルの読み込みは止まらない。
- **F17-AC4** 制限で止めた操作のために、スライドの表示全体が壊れない。
- **F17-AC5** スライドに止めている操作の種類と、外部と通信できることを、読者がヘルプページで確認できる。
- **F17-AC6** 削除。(通報と非表示が 1 つの条件に混ざっていたので、F17-AC7 以降に分けた)
- **F17-AC7** 運営が非表示にしたスライドは、公開中・作者限定・停止中のどの状態からでも、匿名の読者にも作者本人にも、共有 URL とファイルの配信 URL で読めない。
- **F17-AC8** 非表示のスライドは、表紙の画像、トップの一覧、プロフィールの一覧に出ない。
- **F17-AC9** 内部の cache が温まっていても、非表示にした直後の request から読めない。
- **F17-AC10** 非表示の間、作者の公開・再開の操作と、CI からの公開は拒否され、公開状態は変わらない。
- **F17-AC11** 運営が解除すると、非表示にする前の公開状態に戻る。
- **F17-AC12** `admin.slide.community` の画面と操作は、Cloudflare Access が発行した token を Worker が検証できた request にだけ応答する。検証できない request には、存在しないページと同じ応答を返す。
- **F17-AC13** 作者の管理画面のそのスライドに、運営が非表示にしたことと、理由と日時が出る。
- **F17-AC14** 運営の画面に、非表示にしているスライドの一覧が、理由・日時・操作者(Cloudflare Access で確かめた本人)とともに出る。
- **F17-AC15** 運営が停止したアカウントのスライドは、すべて非表示と同じ扱いになり、その作者は新しいアップロードと公開ができない。
- **F17-AC16** ログインした読者が、viewer から理由を選んで通報できる。通報には、開いていた共有 URL と版が添えられる。
- **F17-AC17** 運営の画面に、通報の一覧が出る。
- **F17-AC18** ログインしていない読者が「通報する」を押すと、ログインを求められる。ログインすると、元のスライドに戻る。
- **F17-AC19** 運営の画面と操作は、`admin.slide.community` 以外の hostname(管理画面の origin、配信の origin)からは届かない。
- **F17-AC20** `admin.slide.community` の `robots.txt` は、すべての path を拒否する。
- **F17-AC21** `admin.slide.community` のすべての応答に、`X-Robots-Tag: noindex` と `Cache-Control: no-store` が付く。

## 決めたこと

読者への約束は「外部と通信しない」ではなく、「読者のアカウントに触れず、枠の外に出られない」に置く。外部への通信は止めず、通報を受け、運営が非表示やアカウント停止で対応する。通信先を実測して読者に見せることは、やめた。見た読者に何をしてほしいのかを説明できず、想定する脅威も特定できなかったためである(#133、#139)。次の順に作る。

1. 止めている操作と、外部と通信できることの、ヘルプページでの説明(済み)
2. 運営によるスライドの非表示(#135)
3. アカウントの停止
4. 通報(#134)。読者のログインができてから作る。

通報と運営の操作について、次のように決めた(2026-11-17)。

- 通報できるのは、ログインした人だけにする。ログインした人に向けた機能をこれから作るためである。ログインしていない人が、ログインの必要な機能を使おうとしたら、ログインを求める。
- 通報は、運営の画面の一覧で届ける。通知は作らない。
- 運営の画面は `admin.slide.community` に置き、Cloudflare Access で守る。誰が運営かは Cloudflare 側の policy で決め、アプリの設定やコードの PR では変えられないようにする。Worker は、Access が付ける token を必ず検証する。Access を通らない経路から届いた request を通さないためである。ローカルとテストでは、テスト用の鍵で署名した token で検証を通し、検証を飛ばす設定は作らない。
- Access の application と policy は、infra リポジトリ(非公開。Cloudflare の資源を Pulumi で宣言している)に書く。
- 運営の画面は、検索に載せない(`robots.txt`、`X-Robots-Tag`)。公開側のページと sitemap から、運営の画面へリンクしない。これは検索に載せないための対処で、守りは Access と token の検証に置く。
- F17-AC8 は、サーバーが新しく返す一覧に、非表示のスライドが出ないことを指す。トップの一覧の応答は、ブラウザが最長 60 秒使い回すことがあり、その間は非表示のスライドが一覧に残る。これは受け入れる(2026-11-17)。運営がすすめているように見える時間が短く、一覧から開いても、共有 URL と配信は非表示にした直後から拒否するためである。
