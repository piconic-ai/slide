# F17 知らない人のスライドも、安心して開ける

状態は実装中です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

読者が、SNS で見かけた知らない人の公開デッキを開く。動くスライドは JS を実行するので、勝手に別のページへ飛ばされたり、ファイルをダウンロードさせられたり、ログイン中のサービスを操作されたりしないか不安になる。

## 得られる結果

読者は作者を知らなくても、デモを動かしてよいと判断できる。作者は、読む人に警戒されずに動くスライドを届けられる。

## 体験の流れ

1. 読者が公開デッキの URL を開く。
2. スライドのデモをさわる。
3. スライドが親ページの移動、別タブ、ダウンロード、フォーム送信、外部への通信を試みても、ブラウザが止める。

## 作る範囲

- 作者の HTML を sandbox 付きの iframe で、管理画面とは別の origin から配る。
- 親ページの移動、popup、ダウンロード、フォーム送信、service worker の登録を許さない。
- スライドから外部への通信の制限。作者が必要な通信先を宣言する方式を含め、許す範囲を決める。
- 読者に、このスライドで止めている操作を示す。

## 作らないこと

- 作者の JS を静的に解析して、危険なスライドを判定・拒否すること。
- 制限を外して動かすための、読者向けの切り替え。

## 受け入れ条件

- 作者の JS が、slide のログイン情報・管理画面の DOM・別の作者のデッキに届かない。
- 判定は JS の戻り値ではなく、外に出た request、開いたページの数、ダウンロードの有無で確かめる。
- 外部への通信を制限しても、同じデッキ内の相対パスのファイルは読み込める。
- 制限で止めた操作のために、デッキの表示全体が壊れない。

## 未決事項

- 外部への通信を完全に止めるか、作者が宣言した通信先だけを許すか。宣言する場合の書き方と、読者への見せ方。
- 外部の画像やフォントを読み込むデッキの扱い。

技術上の制約は [開発設計](../dev/design.md#url-と-html-の隔離) と [共有 URL と配信の実装設計](../dev/f03-sharing.md) を参照してください。
