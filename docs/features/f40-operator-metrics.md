# F40 運営が使われ方を知る

状態は未実装の設計案です(第四スコープ。統合ブランチ `scope4` に積み、本番にはまだ反映しない)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

運営は、何が使われ、どこで利用者が詰まっているかを知らないまま、機能を足している。ログインのコードを送っても入れない人が多いのか、スライドを置こうとして断られる人が多いのか、ヘルプで探して見つからない語は何か。問い合わせが来るのを待つしかない。

一方で、利用者のだれが何をしたかを追うことは、したくない。人ごと、端末ごとの追跡はしない。

## 得られる結果

運営は、運営の画面の週ごとの表で、使われているか、どこで詰まるか、何が使われているか、どこから来るか、ヘルプで解決するか、壊れていないかを、数字で知れる。表は CSV で書き出せる。記録には、人や端末を見分ける値が入らない。

利用者には見えない。作者が自分のスライドの読まれ方を見る画面は、作らない。

## 体験の流れ

1. 利用者が、スライドを置く、公開する、開くなどの操作をする。サービスが、応答のついでに、出来事の種類と件数だけを記録する。
2. 1 日 1 回、サービスが、前の日の件数を記録の保管先(Workers Analytics Engine)から読み、D1 の日ごとの集計に写す。
3. 運営が、運営の画面の「計測」を開く。直近 12 週の表が出る。必要なら「CSV で書き出す」を押す。
4. 記録の保管先や、読み取りのトークンが設定されていないときは、「未設定」と、何を設定すればよいかが表に出る。

## 作る範囲

- 出来事の記録(Worker が応答のついでに書く。画面の操作のうちサーバーに届かないものは、同じ origin への短い送信で書く)。
- 日ごとの集計の表(D1)と、1 日 1 回の集計の処理。
- 運営の画面の「計測」のページ(週ごとの表と CSV)。
- 記録の保管先と読み取りのトークンが無い環境の扱い。
- 記録に、人や端末を見分ける値が入らないことを調べるテスト。

## 作らないこと

- 作者が自分のスライドの読まれ方を見る画面([どのページまで読まれたか確かめる](f11-analytics.md) は保留のまま)。
- 人ごと、端末ごとの追跡。訪問の数え方(同じ人かどうかの判定)。
- 外部の解析サービス、外部の script。
- Analytics Engine の dataset を作ること、読み取りのトークンを作ること。依頼者が行う。

## 受け入れ条件

- **F40-AC1** スライドを置くと、「置かれたスライド」の件数が 1 つ増える。
- **F40-AC2** スライドを公開すると、「公開されたスライド」の件数が 1 つ増える。
- **F40-AC3** スライドを開くと、「開かれたスライド」の件数が 1 つ増える。
- **F40-AC4** ログインのコードを送った数と、コードが入れられた数が、別々に数えられる。
- **F40-AC5** スライドを置く操作の、始めた数と終わった数が、別々に数えられる。
- **F40-AC6** 置くのを断ったとき、理由の区分ごとに数えられる。
- **F40-AC7** 置いてから公開するまでの時間が、記録される。
- **F40-AC8** 記事、関連リンク、引用、埋め込み、コミュニティ、フォロー、書き出しのそれぞれの使われた件数が、数えられる。
- **F40-AC9** AI エージェントの道具の呼び出しが、道具ごとに数えられる。
- **F40-AC10** 開かれたページの参照元が、ホスト名だけで記録される。パスとクエリは残らない。
- **F40-AC11** 埋め込みからの閲覧が、ほかの閲覧と分けて数えられる。
- **F40-AC12** ヘルプで結果が 0 件だった検索の語が、50 文字までに切って記録される。結果があった語は記録されない。
- **F40-AC13** ヘルプの記事ごとの閲覧と、記事からお問い合わせに進んだ数が、数えられる。
- **F40-AC14** 画面ごとのエラーの数が、数えられる。
- **F40-AC15** 記録に、IP アドレス、メールアドレス、利用者の番号、Cookie の値が含まれない。端末を見分ける値も含まれない。
- **F40-AC16** 計測のために、外部の script を読まず、CSP に新しい origin を足さない。サーバーに届かない画面の操作の記録は、同じ origin への送信で行う。
- **F40-AC17** 1 日 1 回、前の日の件数が、記録の保管先から読まれ、D1 の日ごとの集計に写される。同じ日を 2 回写しても、件数は 2 倍にならない。
- **F40-AC18** 運営の画面の「計測」に、直近 12 週の表が出る。行は測るもの、列は週である。
- **F40-AC19** 「計測」の表で、詰まるところ(ログイン、置く)は、数と割合が並ぶ。
- **F40-AC20** 「計測」の「CSV で書き出す」で、表の内容を CSV で受け取れる。
- **F40-AC21** 「計測」は、運営でない人には開かない。
- **F40-AC22** 記録の保管先(Analytics Engine)が無い環境では、記録は何もせず、サービスは今までどおり動く。運営の画面の「計測」に「未設定」の注記が出る。
- **F40-AC23** 読み取りのトークンが無い環境では、集計の処理は何もせず、運営の画面の「計測」に「未設定」の注記が出る。
- **F40-AC24** 記録の失敗は、利用者への応答を変えない。
- **F40-AC25** 「計測」の表は、幅 375px で、表の枠だけが横に送れ、ページ全体は横に広がらない。

## 決めたこと

第四スコープを作るにあたり、次のように決めた(2026-11-26、第四スコープの指示書)。

- 記録は Workers Analytics Engine に書く。IP アドレス、メールアドレス、利用者の番号、Cookie や端末を見分ける値を書かない。書くのは、出来事の種類、スライドやコミュニティの番号、理由の区分、参照元のホスト名、表示言語、件数だけである(D-71)。
- 測るものは次のとおり(D-72)。

  | 問い | 測るもの |
  | --- | --- |
  | 使われているか | 置かれたスライド、公開されたスライド、開かれたスライド。作者の数は D1 から数える |
  | どこで詰まるか | ログイン(コードを送った数、入れられた数)、置く(始めた数、終わった数、断った理由)、公開までの時間 |
  | 何が使われているか | 記事、関連リンク、引用、埋め込み、コミュニティ、フォロー、AI エージェントの道具ごとの呼び出し、書き出し |
  | どこから来るか | 開かれたページの参照元のホスト名、埋め込みからの閲覧 |
  | ヘルプで解決するか | 結果が 0 件だった検索の語、記事ごとの閲覧、記事から問い合わせに進んだ数 |
  | 壊れていないか | 画面ごとのエラーの数 |

- 参照元は、ホスト名だけを残す。パスとクエリは捨てる。ヘルプの検索の語は、0 件だったものだけを残し、長さを 50 文字までに切る(D-73)。
- 記録は、Worker が応答のついでに書く。画面の操作のうちサーバーに届かないものは、同じ origin への短い送信で記録する。外部の script を読まず、CSP を広げない(D-74)。
- 1 日 1 回、前の日の件数を Analytics Engine から読み、D1 の日ごとの集計の表に写す。Analytics Engine の記録は 3 か月で消えるが、日ごとの集計は残る。読むためのトークンは secret にする(D-75)。
- 運営の画面に、週ごとの表を置く。D1 の集計から出す。CSV で書き出せる(D-76)。
- 作者が自分のスライドの読まれ方を見る画面は作らない(D-77、D-155)。
- Analytics Engine の binding と、読み取りのトークンの secret が無い環境では、その機能だけが何もせず、ほかは今までどおり動く。足りないものは、運営の画面に「未設定」と出す(D-08)。
- 外部の解析サービスは導入しない(D-159)。
- 画面は、直近 12 週の表を既定にし、行の見出しに `scope="row"`、列の見出しに `scope="col"` を付ける。数字は右にそろえ、割合は数の横にかっこで添える。「未設定」は、何を設定すればよいかの 1 文と、手順の文書の場所とともに出す(02-PAGES.md の 15、05-UI-RULES.md)。
