# F02 作者のみ限定公開で発表し、一般公開する

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

発表前の登壇者が、まだ公開したくない資料を CI でアップロードする。作者のみ限定公開で内容を確認し、そのまま会場の画面に映して発表する。発表終了後に一般公開して参加者へ URL を渡す。誤って公開したときは、CI の完了を待たず公開停止する。

## 得られる結果

次の版を準備しながら公開中の資料を維持し、公開のタイミングを自分で決められる。

## 体験の流れ

1. ダッシュボードで公開候補のコミットと現在公開中の版を見比べる。
2. 作者のみ限定公開で開き、表示とリンクを確認する。
3. 対応する資料ではプレゼンターモードを使い、一般公開しないまま発表する。
4. 発表後に一般公開する。公開後は一般公開 URL を使い、作者限定の閲覧経路は閉じる。更新反映・公開停止・以前の版への差し戻しも選べる。

## 作る範囲

- 作者のみ限定公開は、作者がログインしている間、一般公開前の確認と発表に利用できる。第三者への閲覧権限は渡さない。
- scope1 は作者限定での閲覧、発表者・観客の二画面操作はプレゼンターモードを提供する段階で対応する。
- 発表途中で短い固定期限により中断しないよう、認証と閲覧セッションを維持・更新する。
- 初期値は手動公開。リポジトリ設定に従う自動公開モードも選べる。
- 公開停止は自動公開より優先し、再開まで新しい CI からも公開できない。
- リポジトリモードの published: false は公開中の版も取り下げる。更新だけ下書きに置く場合は手動モードを使う。

## 作らないこと

- 公開予約と、URL を知る人だけが見られる第三者向け限定公開。
- Git のファイル削除を、そのまま資料や購入記録の削除として扱うこと。

## 受け入れ条件

- 公開中の版と次の作者限定の版が混ざらず共存する。
- 作者以外は限定公開の HTML・画像・音声を取得できない。
- 作者限定のまま発表を終えられ、一般公開後は限定公開用のセッションが無効になる。
- 公開停止より前に開始した CI が、停止後に完了しても再公開しない。
- 公開停止後は、匿名の読者が古い HTML・画像・音声の直接 URL からも新規取得できない。購入済みの読者は継続して閲覧できる。取得済みの内容は取り消せない。

## 未決事項

- 公開予約を必要とする具体的な場面。
- 発表中のセッション更新、再ログイン、二画面起動の具体的な方式。
- 購入者がいる資料は、作者が販売・一般公開を止めたり退会したりしても購入者が読めるように保持する。更新時は更新後の内容を提供し、購入時点の版へ戻る機能は作らない。

技術上の制約は [開発設計](../dev/design.md#access-control) を参照してください。
