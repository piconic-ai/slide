# F37 通信が切れても読める

状態は実装済みです(第四スコープ。統合ブランチ `scope4` に積み、本番にはまだ反映しない。設計は [実装設計](../dev/f37-offline-reading.md))。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会の会場で、Wi-Fi が混んでいてつながらない。参加者は、一度開いたスライドを、もう一度開いて見返したい。サービスがメンテナンス中や障害のときも、読者は一度開いたスライドを読み返したい。登壇者も、発表の直前にもう一度開くときに、会場の回線に左右されたくない。

## 得られる結果

一度開いたスライドは、通信が切れても、サービスが止まっていても、1 日は読める。保存した版を見ているときは、そのことが画面の帯に出る。通信できるときは、いつも新しい版が開く。公開を止めた、差し替えた、運営が非表示にした版は、保存したものも使われず、すぐに効く。

## 体験の流れ

1. 読者が、一般公開のスライドを開く。サービスから届いた版が表示され、ブラウザに保存される。
2. 通信が切れた状態(またはサービスが応答しない状態)で、同じ URL をもう一度開く。保存した版が表示され、スライドの枠の上に帯が出る。「接続できないため、保存した版を表示しています。」と、「もう一度読み込む」が並ぶ。
3. 通信が戻ってから「もう一度読み込む」を押す。サービスから新しい版が届き、帯が消える。
4. 通信できるときは、帯は出ない。新しい版が公開されていれば、その版が開く。

## 作る範囲

- 配信の側の Service Worker とその登録、ブラウザの保存の場所への保存。
- 保存した版を見せる条件(取りに行って届かなかったときだけ)、消す条件(`404`、`410`、`403`)、1 日の期限、20 本までの本数の数え方。
- viewer の、保存した版を見せているときの帯(「もう一度読み込む」つき)。
- 別サイトの枠の中で Service Worker と保存の場所が使えるかの、3 つのブラウザでの確認。使えないブラウザでは、何もしない。
- 作者のファイルが自分で Service Worker を登録している場合の扱い(設計で決める)。
- ブラウザの設定で、保存したものを消す方法の案内(設計に書き、ヘルプの記事の材料にする)。

## 作らないこと

- 一度も開いていないスライドを、先に保存すること。
- アプリとして入れられるようにすること(manifest、ホーム画面)。
- 通信できないあいだの操作(置く、直す)。
- 管理 origin のほかのページを保存すること。
- 配信のキャッシュの指定(`no-cache`)と、配ってよいかを毎回確かめる今の仕組みを変えること。
- 保存したものを消す画面のボタン。消し方は、ブラウザの設定での方法を、ヘルプに書く。

## 受け入れ条件

- **F37-AC1** 一般公開のスライドを一度開いた後、通信できない状態で同じ URL を開くと、スライドが表示される。
- **F37-AC2** 保存した版を表示しているとき、スライドの枠の上に、帯が 1 本、「接続できないため、保存した版を表示しています。」と「もう一度読み込む」とともに出る。
- **F37-AC3** サービスが `429` を返すとき、保存した版が表示され、帯が出る。
- **F37-AC4** サービスが `5xx` を返すとき(メンテナンスの `503` を含む)、保存した版が表示され、帯が出る。
- **F37-AC5** 通信できるときは、保存した版ではなく、サービスから届いたものが表示される。新しい版が公開されていれば、新しい版が表示される。帯は出ない。
- **F37-AC6** 保存した版は、通信で新しく取れたものに入れ替わる。
- **F37-AC7** サービスが `404` を返した版は、保存したものが消え、保存した版は表示されない。
- **F37-AC8** サービスが `410` を返した版は、保存したものが消え、保存した版は表示されない。
- **F37-AC9** サービスが `403` を返した版は、保存したものが消え、保存した版は表示されない。
- **F37-AC10** 最後に通信で取れてから 1 日を過ぎた版は、通信できないときも表示されない。
- **F37-AC11** 21 本目のスライドを開くと、いちばん古く開いた 1 本の保存が消える。
- **F37-AC12** 一度も開いていないスライドは、通信できないとき、保存した版が無く、表示されない。
- **F37-AC13** 保存した版を表示しているとき、「もう一度読み込む」を押すと、通信が戻っていれば、サービスから新しく読め、帯が消える。通信が戻っていなければ、保存した版のまま帯が残る。
- **F37-AC14** 帯は、保存した版を表示しているときだけ出る。2 本は重ならない。
- **F37-AC15** 帯は、出たときに読み上げられ(`role="status"` と `aria-live="polite"`)、帯の中のリンクとボタンの押せる範囲は高さ 44px 以上である。
- **F37-AC16** 帯の文言が、日本語と英語の両方で出る。
- **F37-AC17** Service Worker や保存の場所が使えないブラウザでは、今までどおりにスライドが表示され、エラーが出ない。
- **F37-AC18** 作者のファイルの中のパスが、Service Worker のパスに隠れない。
- **F37-AC19** 作者のファイルが自分で Service Worker を登録していて、`404`、`410`、`403` で保存を消す決まりを守れない組み合わせでは、その版は保存されない。
- **F37-AC20** 配信のキャッシュの指定(`no-cache`)と、配ってよいかを毎回確かめる動きは、変更の前と同じである。
- **F37-AC21** 通信できるときに開いた共有 URL が、保存と別の版を見せる(新しい版を保存できなかった場合を含む)か、保存の対象でない見え方(作者の下見)のとき、前の保存は消え、通信できないときに表示されない。

## 決めたこと

第四スコープを作るにあたり、次のように決めた(2026-11-26、第四スコープの指示書)。

- 一度開いたスライドを、通信が切れても 1 日は読めるようにする。仕組みは Service Worker と、ブラウザの保存の場所を使う(D-90)。
- 通信できるときは、必ず先にサービスへ取りに行く。届いたらそれを見せ、保存したものを入れ替える。viewer のページは毎回問い合わせるので、新しい版が公開されていれば、その版が開く(D-91)。
- 保存したものを見せるのは、取りに行って届かなかったときだけ。通信できない、つながらない、`429`、`5xx`(メンテナンスの `503` を含む)のときである。そのとき、画面に「接続できないため、保存した版を表示しています」と出す(D-92)。
- サービスが `404`、`410`、`403` を返した版は、保存したものも消し、見せない。非公開、差し替え、運営による非表示を、すぐに効かせるためである(D-93)。
- 残すのは 1 日、新しい方から 20 本まで。版はそれぞれ別の origin にあるので、本数は viewer のページの側で数え、古いものから捨てる(D-94)。
- 最初に、別サイトの枠の中で Service Worker と保存の場所が使えるかを、Chromium、Firefox、WebKit で試す。使えないブラウザでは、何もせず、今までどおりに動く(D-95)。
- 作者のファイルが自分で Service Worker を登録している場合に何が起きるかを、設計で扱う。サービスの決まり(D-93)を守れない組み合わせがあれば、その版では保存しない(D-96)。
- 配信のキャッシュの指定(`no-cache`)と、配ってよいかを毎回確かめる今の仕組みは変えない(D-97)。
- 一度開いたスライドは、メンテナンス中も保存した版で読める(D-121)。メンテナンス中の `503` の扱いは、[メンテナンスを知らせる](f38-maintenance-notice.md) と合わせる。先に終わった方の形に、後の方が合わせる。
- 画面は、帯をスライドの枠の上に幅いっぱいで 1 本だけ出し、既存のトークンで作る。日時を出すときは `<time datetime="…">` を使う(05-UI-RULES.md)。
- 画面の文言は、日本語と英語の両方を用意する(D-12)。

- 別サイトの枠の中で Service Worker と保存の場所が使えるかを、Chromium 156、Firefox 157、WebKit 27.2 で試した(2026-11-26)。3 つとも使える。結果の表は [実装設計](../dev/f37-offline-reading.md#先に確かめたことd-95) にある。使えない設定(Firefox のサードパーティ Cookie をすべて止める設定など)では、登録が拒否され、何もしない(D-95)。
- 保存の対象は、一般公開の公開中の版だけにする。作者だけが見られる版と、下書き、停止中の版は、対象にしない。
- 通信できないときの viewer のページは、読者によらない小さな「殻」(題名、枠、帯)を保存し、管理 origin の Service Worker が返す。viewer のページそのものは保存しない(読者ごとに中身が変わるため)。
- 新しい版を保存できなかったスライドは、通信できないときに読めない。差し替えたあとの viewer が、保存と別の版を見せたら、前の保存は、新しい版を保存できたかによらず消す。古い版が 1 日のあいだ見えるより、読めないほうを選ぶ(安全側に倒す)(2026-11-27、F37-AC21)。
- 版の Service Worker は、viewer が頼んだ枠の中でだけ登録する。配信の CSP は、一般公開の版について、`worker-src` を、サービスの Service Worker の URL 1 つだけにする。作者のファイルは、自分で Service Worker を登録できない(D-96)。
