# F21 気になる人を、フォローする

状態は実装済みです。2026-11-20 の見直しで、プロフィールに出す GitHub の情報(自己紹介を含む)と、作者向けの操作を置かないことを足した(F21-AC23 から)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

読者が、ある人のスライドを読んで、次のスライドも読みたいと思う。その人がいつ公開するかは、分からない。プロフィールを何度も見に行くのは、続かない。

## 得られる結果

読者は、気になる人をフォローしておけば、その人が新しいスライドを公開したときに、お知らせと、ログイン中のトップの新着で知る。フォローされた人は、だれが読みたがっているかを知る。プロフィールでは、その人がだれをフォローしているか、だれにフォローされているかが見え、次に読む人を見つけられる。

## 体験の流れ

1. 読者が、スライドを読む。作者名のそばの「フォロー」を押す。
2. フォローされた人に、「フォローされました」のお知らせが届く。
3. その人が新しいスライドを公開すると、読者にお知らせが届く。
4. 読者がログインしてトップを開くと、自分のスライドと、フォローしている人の新しいスライドが見える。
5. 読者は、自分のプロフィールの「フォロー中」で、フォローしている人の一覧を見て、解除する。
6. だれでも、プロフィールの「フォロー中」「フォロワー」で、その人のつながりを見られる。

## 作る範囲

- フォローの保存(だれが、だれを)。
- プロフィールと、viewer の作者名のそばの、フォローと解除。
- プロフィールの切り替え「スライド / フォロー中 / フォロワー」と、それぞれの数。`/@handle/following` と `/@handle/followers` の一覧。だれでも見られる。
- 自分のプロフィールの「フォロー中」での解除。
- プロフィールに出す GitHub の情報。顔写真、名前、場所、Web サイト、自己紹介を、GitHub の公開プロフィールから写して出す。ローカルの確認用のデータにも、同じ項目を入れる。
- ログイン中のトップの「自分のスライド」と「フォロー中の人の新着」。
- お知らせ: フォローしている人が、スライドを公開した。フォローされた(受け入れ条件は、[知りたい出来事が、お知らせに届く](f20-notifications.md) の F20-AC5・F20-AC6)。

## 作らないこと

- フォローしている人のスライドだけを並べる、専用の画面。トップの新着(4 件)にとどめる。
- フォローを勧める表示、おすすめの人の一覧。
- お知らせの種類を足すこと、お知らせのページを作り直すこと。
- 一覧が公開に変わることを、既にフォローしている人へ伝える仕組み。本番のデータを空にするので、要らない。
- GitHub でフォローしている人を、slide で自動的にフォローすること。
- フォローの承認(承認されるまでフォローできない形)。スライドとプロフィールは、もとから公開である。
- フォローによって、一覧の並びやおすすめを変えること。
- プロフィールに、作者向けの操作(「スライドを管理する」など)を置くこと。プロフィールは読者に見せる面で、作者は自分のプロフィールでも読者と同じ面を見る。
- プロフィールを、slide の中で書き換えること。GitHub 以外の情報源から写すこと。

## 受け入れ条件

- **F21-AC1** ログインした人は、ほかの人のプロフィールと、viewer の作者名のそばから、その人をフォローでき、解除できる。
- **F21-AC2** 自分自身は、フォローできない。自分のプロフィールと自分のスライドに、フォローの操作は出ない。
- **F21-AC3** 削除。(一覧と解除を、自分のプロフィールの「フォロー中」へ移した。F21-AC12・F21-AC13 で書き直した)
- **F21-AC4** 削除。(フォロー中とフォロワーの一覧、その数を、だれでも見られるようにした。F21-AC8〜F21-AC11 で書き直した)
- **F21-AC5** だれかをミュートすると、その人へのフォローは外れる。ミュートしている人は、フォローできない([見たくない作者を、一覧から外す](f19-mute.md))。
- **F21-AC6** 退会すると、その人がしたフォローと、その人へのフォローが消える。
- **F21-AC7** プロフィールと viewer で、フォローと解除が、確認のページを経ずに、1 回押すだけで切り替わる。viewer では、ページを移らず、読んでいるページは変わらない。script が動かないときと、通信が失敗したときは、確認のページで行える。
- **F21-AC8** ログインしていない人が `/@handle/following` を開くと、その人がフォローしている人の一覧が見える。`/@handle/followers` では、フォロワーの一覧が見える。
- **F21-AC9** プロフィールの切り替えに、スライドの数、フォロー中の数、フォロワーの数が出る。
- **F21-AC10** 一覧と数に、停止中の人と退会した人が入らない。
- **F21-AC11** ログイン中の人が見るとき、その人がミュートしている相手は、一覧に出ず、その人が見る数にも入らない。
- **F21-AC12** 自分のプロフィールの「フォロー中」で解除すると、その人が一覧から消え、相手の「フォロワー」からも自分が消える。
- **F21-AC13** 設定のページに、フォロー中の一覧が出ない。
- **F21-AC14** 存在しないハンドル、停止中の人の `/@handle/following` と `/@handle/followers` は、プロフィールと同じ 404 になる。
- **F21-AC15** ログイン中の人がトップを開くと、「自分のスライド」に、自分のスライドが新しい順に 4 件まで出る。公開していないものには「作者のみ」と出る。
- **F21-AC16** フォローしている人が新しく公開すると、そのスライドが「フォロー中の人の新着」に出る。公開を止めると消える。出るのは、公開が新しい順に 4 件まで。
- **F21-AC17** フォローしている人がいない、またはフォローしている人の一般公開中のスライドが 1 本もないとき、「フォロー中の人の新着」は見出しごと出ない。スライドを 1 本も持たない人には、「自分のスライド」が見出しごと出ない。
- **F21-AC18** ログインしていない人には、どちらの節も出ない。本人のデータを返す経路は、ログインしていない要求に何も返さず、応答を cache させない。
- **F21-AC19** フォロー中とフォロワーの一覧は、フォローが新しい順に、1 ページ 50 人まで出る。それより多いときは、続きへ進める。
- **F21-AC20** `following` と `followers` は、スライドの URL の名前(slug)にならない。自動で決めるときは `-2` を付け、作者が手で変えるときは断る。`/@handle/following` と `/@handle/followers` は、いつも一覧を開く。
- **F21-AC21** 「フォロー中の人の新着」に、見る人がミュートしている作者のスライド、運営が非表示にしたスライド、停止中の作者のスライドは出ない(最近のスライドの一覧と同じ扱い)。
- **F21-AC22** 削除。(自分のプロフィールの要素が読者と同じであることに含まれる。F21-AC23 にまとめた。「スライドを管理する」が出ないことも、F21-AC23 で確かめる)
- **F21-AC23** 自分のプロフィールに出る要素は、読者が見るプロフィールと同じで、「スライドを管理する」などの作者向けの操作が出ない(自分の「フォロー中」の解除のボタンを除く)。
- **F21-AC24** GitHub でログインすると、プロフィールに、GitHub の公開プロフィールの名前と顔写真が出る。
- **F21-AC25** GitHub でログインすると、プロフィールに、GitHub の公開プロフィールの場所と Web サイトが出る。
- **F21-AC26** GitHub でログインすると、プロフィールに、GitHub の公開プロフィールの自己紹介が出る。
- **F21-AC27** 自己紹介に `<script>` や HTML の記号が入っていても、文字として出る。
- **F21-AC28** 自己紹介に URL が入っていても、リンクにならず、文字として出る。
- **F21-AC29** 自己紹介は、改行を 1 つの空白にまとめた後の Unicode のコードポイントで 160 までに切られる。ちょうど 160 のときは切らず、切った印(「…」など)も付けない。
- **F21-AC30** 自己紹介の改行(CR、LF、CRLF、連続した改行)は、まとめて 1 つの空白として出る。空白に置き換えてから、F21-AC29 の長さで切る。
- **F21-AC31** GitHub のプロフィールが空の、場所、Web サイト、自己紹介は、プロフィールに出ない。空の行や見出しも出ない。
- **F21-AC32** 設定の画面に、最後に GitHub と同期した日が出る。
- **F21-AC33** 設定の画面の「GitHub から同期し直す」で、プロフィールが GitHub の最新の内容になる。
- **F21-AC34** ローカルの確認用のデータを入れると、プロフィールに、顔写真(または頭文字)、名前、場所、Web サイト、自己紹介が出る。
- **F21-AC35** ローカルの確認用のデータは、ネットワークに頼らず、固定の値でプロフィールを入れる。
- **F21-AC36** Worker に、認証を迂回してプロフィールを入れる経路がない。
- **F21-AC37** 顔写真がないとき、顔写真の代わりに頭文字が出る(空にはしない)。
- **F21-AC38** 名前がないとき、名前の代わりにハンドルが出る(空にはしない)。
- **F21-AC39** アカウントのメニューの円に、保存された顔写真が出る。ないときは頭文字が出る。
- **F21-AC40** viewer の作者に、保存された顔写真が出る。ないときは頭文字が出る。
- **F21-AC41** フォローの一覧の人の行に、保存された顔写真が出る。ないときは頭文字が出る。
- **F21-AC42** ログインしていない人にも、ほかの人のプロフィールに「フォロー」が出る。押すと、ログインを促すモーダルが開き、フォローは送られない(`POST /follows` を送らず、サーバーの状態は変わらない)。
- **F21-AC43** ログインしていない人にも、フォロー中・フォロワーの一覧の人の行に「フォロー」が出る。読み上げには相手の名前が入る。押すと、F21-AC42 と同じモーダルが開く。
- **F21-AC44** ログインしていない人にも、viewer の作者名のそばに「フォロー」が出る。押すと、F21-AC42 と同じモーダルが開く。ミュートする操作(F03-AC90)も同じ。
- **F21-AC45** ログインしている人の画面は変わらない。自分のプロフィール、自分のスライド、停止中の読者には、これまでどおりフォローが出ない。ログインを促すモーダルの markup も、ログインしている人のページには入らない。
- **F21-AC46** ログインを促すモーダルは、`role="dialog"`、`aria-modal="true"`、`aria-labelledby`(題名)を持つ。開くと、焦点がモーダルの中へ移り、背景のスクロールが止まり、背景は操作できない。
- **F21-AC47** モーダルは、キーボードだけで使える。Tab と Shift+Tab は、モーダルの中で循環する。Esc と「閉じる」で閉じ、閉じると、焦点が押した要素へ戻り、背景のスクロールが戻る。
- **F21-AC48** モーダルの「ログインして続ける」は、`/auth/github?to=<いまの画面>` へ進む。`to` は、プロフィール、一覧、スライドの正規の path に限る(それ以外は `/slides` に戻す。いまのログインの検査に従う)。ログインのあとは、元の画面に戻る。操作の続き(フォローの実行)はしない。
- **F21-AC49** モーダルの文言は、日本語と英語の両方で出る(画面の言語に従う)。題名と本文は、押した操作でログインするとできることを 1〜2 文で書く。
- **F21-AC50** script が動かないときは、「フォロー」は、これまでの確認のページ(401 のログインの案内)へのリンクとして働く。未ログインの `POST /follows` は、`Sec-Fetch` の有無に関わらず 401 で、フォローを保存しない。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。下の 2026-11-18 の決定のうち、食い違うところは、こちらが新しい。

- フォロー中とフォロワーの一覧、その数を、だれでも見られるようにする。「ほかの人に見せない」を改める。
- 見る人がミュートしている相手は、その人が見る一覧に出さない。停止中の人と退会した人は、だれが見ても出さない。数も、出す人だけを数える。
- 設定のページからフォロー中の一覧を外す。解除は、自分のプロフィールの「フォロー中」で行う。
- ログイン中のトップに「フォロー中の人の新着」を出す。公開が新しい順に 4 件。「人ごとの一覧の画面は作らない」は、専用の画面を作らないという意味で残す。
- お知らせは既存のまま使う。入口は、ヘッダーのベルにする。
- 一覧が公開に変わることを、既にフォローしている人へ伝える必要はない(本番のデータを空にするため)。
- 一覧は、フォローが新しい順に、1 ページ 50 人までにする。
- `following` と `followers` は、スライドの URL の名前として予約する。本番のデータは空にするので、既にある名前との衝突は考えない。

ログインしていない人への見せ方について、2026-11-21 に依頼者から次の指示があった。次のように決めた案である(文言と、広げる範囲は、依頼者の確認を待つ)。

- ログインが要る操作は、ログインしていない人にも隠さず見せる。押すと、その操作でログインするとできることを伝えるモーダルを出し、ログインへ進める。操作そのものは行わず、サーバーの状態も変えない。
- 見せる操作: プロフィールと一覧の行と viewer の「フォロー」、viewer の「この作者をミュート」(F03-AC90)、viewer の「通報する」(F03-AC91)。
- 見せない操作: 作者だけの操作(編集する、公開する)、自分自身へのフォロー(F21-AC2)、自分のスライドのミュート、停止中の読者の操作、運営の画面。ログインしている人に対する操作だからである。ヘッダーのお知らせのベルは、ログイン中だけの 3 点(D-110)を保ち、ログインしていない人には出さない案。
- ログインのあとは、元の画面に戻るだけにする。操作の続き(フォローの実行)までは戻さない(依頼者に確認する)。
- 文言の案(ja / en)。題名の次に本文。
  - フォロー: 「フォローするには、ログインしてください」「ログインすると、フォローした人が新しいスライドを公開したときに、ヘッダーのベルのお知らせで受け取れます。トップにも「フォロー中の人の新着」が並びます。」 / "Sign in to follow" "Once you sign in, you get a notification when someone you follow publishes new slides, and their latest appear on your top page."
  - ミュート: 「ミュートするには、ログインしてください」「ログインすると、この作者のスライドを、あなたに表示される一覧から外せます。ほかの読者の画面は変わりません。」 / "Sign in to mute" "Once you sign in, you can take this author’s slides off your lists. Other readers see no change."
  - 通報: 「通報するには、ログインしてください」「ログインすると、読者をだます内容や迷惑なスライドを、運営に通報できます。通報した人がだれかは、運営の一覧にも出ません。」 / "Sign in to report" "Once you sign in, you can report slides that deceive readers or are abusive. Who reported is not shown, even in the operators’ list."
  - ボタン: 「ログインして続ける」「閉じる」 / "Sign in to continue" "Close"
- 登録していない人がログインへ進むと、招待制のページが出る([スライドを、ドロップして置く](f22-browser-drop.md))。下の未決事項は、そのまま残る。

次のように決めた(2026-11-18)。

- slide の中に、フォローの機能を作る。作者の判断で、理由は「ノリ」である。[URL を渡して読んでもらう](f03-sharing.md) で「作らない」としていた「SNS のフォロー関係」を、ここで変える。
- フォローすると、相手が新しいスライドを公開したときに、お知らせに出る。フォローされた人にも、お知らせが出る。どちらも、設定で受け取らないようにできる。
- プロフィールでも viewer でも、作者名のそばでそのままフォロー・解除できる。viewer は読んでいるページを保つため、自身のスクリプトから同じ origin に通信できるようにする（`connect-src 'self'`）。フォーム送信は引き続き `form-action 'none'` で禁止する。viewer でスクリプトが無効なときや通信に失敗したときは、リンク先の確認ページを使う。
- viewer の「⋯」で作者をミュートすると、おすすめの一覧からその作者のスライドが外れ、作者名の横のフォロー操作が消える。同じメニューでミュートを解除すると「フォロー」が再び表示され、読者が改めてフォローできる（[見たくない作者を、一覧から外す](f19-mute.md)）。
- 人ごとの一覧の画面は、作らない。
- GitHub でのフォローと、slide でのフォローは、つながない。

プロフィールについて、第一スコープの見直しで、次のように決めた(2026-11-20)。

- プロフィールに、GitHub の自己紹介(bio)を出す。これまでは意図して出していなかった。出すのは、GitHub の公開プロフィールの文を、そのまま文字として出す(リンクにしない、HTML として解釈しない、改行は 1 つの空白にして、160 文字で切る)。
- プロフィールは、これまでどおり GitHub でログインしたときに保存する。設定の画面の「GitHub から同期し直す」も残す。設定の画面の説明に、自己紹介も GitHub から写すことを書く。
- プロフィールに、作者向けの操作を置かない。自分のプロフィールでも、読者と同じ面にする。ただし、自分の「フォロー中」での解除は残す。
- ローカルの確認用のデータを入れるとき、作者と引用する側の人のプロフィールも入れる。ネットワークに頼らず、固定の値(顔写真の URL、名前、場所、Web サイト、自己紹介)で入れる。Worker に、認証を迂回する経路は足さない。
- 顔写真がないときは頭文字、名前がないときはハンドルを出す。
