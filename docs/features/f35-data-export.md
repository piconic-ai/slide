# F35 データを書き出す

状態は、画面からの書き出し(F35-AC1〜F35-AC31)を実装済みで、AI エージェントからの書き出し(F35-AC32〜F35-AC42)も実装済みです。実際の AI エージェントでの通しと、本番の Workers Logs に取り出すための URL が残るかは、人の確認が残ります(第四スコープ。統合ブランチ `scope4` に積み、本番にはまだ反映しない)。画面からの書き出しの設計は [データの書き出しの実装設計](../dev/f35-export.md)、AI エージェントからの書き出しの設計は [AI エージェントからの書き出しの実装設計](../dev/f35-agent-export.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

作者が、置いたスライドと書いた記事を、手元に残したい。ほかの置き場へ移るとき、バックアップを取りたいとき、退会する前に控えを持ちたいときである。スライドと記事は作者のものなので、預けたものはいつでも全部持ち帰れてほしい。いまは、置いたファイルを取り戻す手段がない。

AI エージェントに頼んで、会話のまま全部を手元に書き出してほしい作者もいる([AI エージェントから置く](f23-agent-upload.md))。

## 得られる結果

作者は、1 本ごとに、置いたままのファイルの zip、記事(Markdown)、スライドの情報(JSON)を受け取れる。受け取った zip をそのまま置き直すと、同じファイルの版ができる。設定の「データを書き出す」からは、すべてのスライド(限定公開、非公開を含む)とアカウントの情報を、1 つの画面から受け取れる。退会の確認の画面から、この画面へ移れる。つないだ AI エージェントは、同じものを、道具を順に呼んで手元に書ける。

## 体験の流れ

1. 作者が、1 本の管理の「ダウンロード」の枠で、「公開中の版(zip)」「準備済みの版(zip)」(あるものだけ)、「記事(Markdown)」(あるときだけ)、「スライドの情報(JSON)」を受け取る。
2. 作者が、設定の「データを書き出す」を開く。「アカウントの情報(JSON)」と、スライドの一覧(1 本につき 1 行)が並ぶ。必要なものを受け取る。
3. 退会を考えている作者は、退会の確認の画面の「退会の前に、データを書き出せます。」から、2 の画面へ移る。
4. AI エージェントを使う作者は、エージェントに「全部を手元に残して」と頼む。エージェントが、`export_account` でアカウントの情報とスライドの一覧を受け取り、スライドごとに `get_slide_files` と `get_article_draft` を呼び、ファイルを取り出して手元に書く。

## 作る範囲

- 1 人の人について、書き出すものを集める 1 つの層(画面と AI エージェントが同じ関数を使う)。他人のものが混ざらないことを、この層で守る。
- スライドの zip(版ごとに 1 つ。置いたままのファイルを、置いたままのパスで入れる。流しながら作る)、記事の Markdown、スライドの情報の JSON(形の版の番号つき)、アカウントの情報の JSON。
- 1 本の管理の「ダウンロード」の枠。設定の「データを書き出す」の枠(アカウントの枠の中、退会より上)。退会の確認の案内。
- 書き出しの経路の守り(ログインしている本人だけ、上限(頻度)、同時に 1 つまで、`Cache-Control: no-store`)。
- AI エージェントの道具 `export_account` と `get_slide_files`、ファイルを取り出すための URL(発行から 1 時間だけ有効)。記事は、すでにある `get_article_draft` で取る。足りない項目(公開中の本文、関連リンク)だけを足す。
- 書き出せるものの形(JSON の項目の名前と型)の設計。

## 作らないこと

- 全部を 1 つにまとめた zip。書き出しを予約して、後でメールで届ける仕組み。Worker のメモリと実行時間の上限に当たらないため、スライドごとのリンクを並べる画面にする。
- 残している過去の版。書き出すのは、公開中の版と、それより新しい準備済みの版だけである。
- 書き出した zip をまとめて取り込む機能。zip を 1 本ずつ置き直すことは、いまの [スライドを、ドロップして置く](f22-browser-drop.md) でできる。
- 利用を止められている人のための書き出しの画面。お問い合わせを受けて、運営が対応する。
- ファイルの中身を、AI エージェントの道具の応答に入れること。zip を返す道具。他人のスライドを読む道具。書き出したものを取り込む道具。
- 作者が自分のスライドの読まれ方を見る画面([どのページまで読まれたか確かめる](f11-analytics.md) は保留のまま)。

## 受け入れ条件

- **F35-AC1** 1 本の管理に「ダウンロード」の枠が出る。置く場所は、公開の操作より下、削除より上である。
- **F35-AC2** 「ダウンロード」の枠に、「スライドのデータをダウンロードできます。」の説明が出る。
- **F35-AC3** 作者は、1 本の管理から「公開中の版(zip)」を受け取れる。zip の中のファイルは、置いたときのファイルと、パスも中身も同じである。
- **F35-AC4** 公開中の版より新しい準備済みの版があるとき、「準備済みの版(zip)」も受け取れる。準備済みの版がないとき、そのリンクは出ない。
- **F35-AC5** 残している過去の版の zip のリンクは、どこにも出ない。
- **F35-AC6** 限定公開と非公開のスライドの zip も、本人は受け取れる。
- **F35-AC7** zip に、サービスが配信のときに足したもの(ページを伝える script など)が入っていない。
- **F35-AC8** zip の中のファイルのパスに `..` や絶対パスがあっても、zip を展開したときに、展開先の外を指さない。
- **F35-AC9** 受け取った zip を、そのまま新しいスライドとして置くと、ファイルごとの SHA-256 が元と同じ版ができる。
- **F35-AC10** ファイルの数が多い版(数百)や、大きさの上限に近い版でも、zip を受け取れる。
- **F35-AC11** 記事があるスライドでは、「記事(Markdown)」を受け取れる。ページの埋め込みは、書いたときの共有 URL のまま入る。記事がないスライドでは、記事のリンクが出ない。
- **F35-AC12** 「スライドの情報(JSON)」に、題名、URL の名前、公開の状態、公開日時、関連リンク、入っているイベント、版ごとのファイルの一覧と SHA-256 が入る。
- **F35-AC13** 「スライドの情報(JSON)」に、形の版の番号が入る。
- **F35-AC14** 設定の「アカウント」の枠の中、退会より上に、「データを書き出す」の枠が出る。
- **F35-AC15** 「データを書き出す」に、自分のすべてのスライドが、限定公開、非公開、運営が非表示にしたものを含めて、1 本につき 1 行で並ぶ。各行に、題名、公開の状態、F35-AC1 と同じリンクが出る。
- **F35-AC16** スライドが 20 本を超えるとき、「データを書き出す」のスライドの一覧は、ページが分かれる。
- **F35-AC17** 「データを書き出す」に、「アカウントの情報(JSON)」のリンクが出る。プロフィール画像があるときだけ、「プロフィール画像」のリンクも出る。
- **F35-AC18** アカウントの情報の JSON に、プロフィールと、本人のメールアドレスが平文で入る。
- **F35-AC19** アカウントの情報の JSON に、フォロー中の人とコミュニティが入る。
- **F35-AC20** アカウントの情報の JSON に、ミュートとブロックの一覧が入る。
- **F35-AC21** アカウントの情報の JSON に、管理しているコミュニティの設定が入る。
- **F35-AC22** アカウントの情報の JSON に、つないでいる AI エージェントの名前と日時が入る。トークンは入らない。
- **F35-AC23** アカウントの情報の JSON に、スライドの一覧が入る。引用しているほかの人のスライドは、URL だけが入る。
- **F35-AC24** ほかの人のスライドの書き出しの URL を開くと、そのスライドが無いときと同じ応答になる。
- **F35-AC25** ログインしていないで書き出しの URL を開くと、ログインに送られる。
- **F35-AC26** 利用を止められている人は、書き出しの経路から何も受け取れない。
- **F35-AC27** 書き出しの応答に、`Cache-Control: no-store` が付く。
- **F35-AC28** 書き出しの経路には、管理 origin の上限(頻度)がかかる。
- **F35-AC29** 同じ人の zip を作る処理が動いている間に、同じ人がもう 1 つ始めると、待つように伝えられる。
- **F35-AC30** 「ダウンロード」と「データを書き出す」の文言が、日本語と英語の両方で出る。
- **F35-AC31** 幅 375px で、1 本の管理の「ダウンロード」と「データを書き出す」が、横にはみ出さない。スライドの一覧は、1 本を 1 つのまとまり(題名、状態、リンクの列)にして縦に並ぶ。
- **F35-AC32** つないだ AI エージェントが `export_account` を呼ぶと、アカウントの情報と、すべてのスライドの一覧(URL の名前、題名、公開の状態)が返る。限定公開と非公開のスライドも入る。
- **F35-AC33** つないだ AI エージェントが `get_slide_files` を呼ぶと、1 本のスライドの、公開中の版と、それより新しい準備済みの版について、ファイルごとのパス、大きさ、SHA-256、取り出すための URL が返る。
- **F35-AC34** `get_slide_files` は、ファイルの数が多いとき、続きを取れる形で返す。
- **F35-AC35** `export_account` と `get_slide_files` の応答に、ファイルの中身が入らない。
- **F35-AC36** 取り出すための URL から取ったファイルは、道具が返した SHA-256 と一致し、置いたままの中身である。
- **F35-AC37** 取り出すための URL は、発行から 1 時間を過ぎると使えない。
- **F35-AC38** 取り出すための URL は、別の人の接続では、その人のものではないファイルを返さない。
- **F35-AC39** 取り出すための URL の値を書き換えると、何も返さない。
- **F35-AC40** 限定公開と非公開のスライドのファイルも、本人の接続からは取り出せる。
- **F35-AC41** 取り出すための URL が、ログに残らない。
- **F35-AC42** `get_article_draft` で、書き出しに足りる内容(編集中の下書き、公開中の本文、関連リンク)が取れる。新しい記事の道具は増えない。

## 決めたこと

第四スコープを作るにあたり、次のように決めた(2026-11-26、第四スコープの指示書)。

- 書き出せるのは、ログインしている本人のものだけ。限定公開と非公開のスライド、運営が非表示にしたスライドも含む。利用を止められている人の書き出しは、画面を作らず、お問い合わせを受けて運営が対応する(D-30)。
- 書き出す版は、公開中の版と、それより新しい準備済みの版。残している過去の版は含めない(D-31)。
- スライドの zip は、版ごとに 1 つ。根に、作者が置いたままのファイルを、置いたままのパスで入れる。サービスが配信のときに足すものは入れない。この zip をそのまま置き直すと、同じスライドになる。記事と情報を同じ zip に入れると、置き直したときに余分なファイルとして公開されてしまうので、別のファイルにする(D-32)。
- 1 本のスライドについて書き出せるものは 3 つ。版ごとの zip、記事(Markdown。ページの埋め込みは、書いたときの共有 URL のまま)、スライドの情報(JSON。題名、URL の名前、公開の状態、公開日時、関連リンク、入っているイベント、版ごとのファイルの一覧と SHA-256)(D-33)。
- アカウントの情報は JSON で書き出す。プロフィール、メールアドレス、フォロー中の人とコミュニティ、ミュートとブロックの一覧、管理しているコミュニティの設定、つないでいる AI エージェントの名前と日時、スライドの一覧を含める。顔写真は別のリンクにする。ほかの人のスライドは、引用していても URL だけを残す(D-34)。
- 全部を 1 つの zip にしない。設定の「データを書き出す」は、スライドごとのリンクと、アカウントの情報のリンクを並べるページにする。zip は、全体をメモリに持たずに、流しながら作る(D-35)。
- 書き出しの経路には、管理 origin の上限(頻度)をかける。zip を作る処理は、1 人につき同時に 1 つまでにする(D-36)。
- AI エージェントの道具は、`export_account`(アカウントの情報と、すべてのスライドの一覧)と `get_slide_files`(1 本のスライドの、版ごとのファイルのパス、大きさ、SHA-256 と、ファイルを取り出すための URL)の 2 つを足す。記事を読む道具(`get_article_draft`)はすでにあるので、新しく作らない(D-37)。
- 取り出すための URL は、発行から 1 時間だけ有効で、その接続の本人のファイルだけを返す。ファイルの中身は、道具の応答に入れない。URL は推測できない値を含み、ログに残さない(D-38)。
- 接続の許可の画面に、「自分のスライドと記事を読み、取り出す」ことを足す。この変更より前につないだ接続は、つなぎ直すまで、足した 2 つの道具を使えない。使おうとしたときは、つなぎ直すように答える([AI エージェントから置く](f23-agent-upload.md) の F23-AC46〜F23-AC51)(D-39)。
- 退会の確認のページに、「退会の前に、データを書き出せます。」と、設定の「データを書き出す」へのリンクを置く([メールのコードでログインする](f28-email-login.md) の F28-AC115)(D-40)。
- 書き出した zip をまとめて取り込む機能は作らない(D-153)。作者が自分のスライドの読まれ方を見る画面も作らない(D-155)。
- zip は無圧縮にする。置かれるのは圧縮済みの画像などが多く、無圧縮にすると全体の長さを送る前に決められ、CPU を使わない。1 つの zip は 500 ファイル、256 MiB までとし、超える版は断る(Worker の subrequest とメモリの上限に当たらないため。見積りは [データの書き出しの実装設計](../dev/f35-export.md))(作業 E の設計、2026-11-26)。
- 書き出しの経路の頻度の上限は、管理 origin の上限(IP ごとに 1 分に 120 回)をそのまま使う。1 人につき同時に 1 つの zip は、R2 の上にリースを置いて守る(表も binding も足さない)(作業 E の設計、2026-11-26)。
- 取り出すための URL は、署名した URL にする。既存の `BETTER_AUTH_SECRET` から用途を分けた鍵(HKDF)を導いて使い、新しい secret は足さない。その secret が無い環境では、`get_slide_files` が「使えない」と答える(D-08)。取り出すたびに、接続の行と停止を確かめるので、接続の取り消しと停止は、1 時間を待たずに効く(作業 G の設計、2026-11-26)。
- `get_slide_files` は、1 回の応答にファイルを 100 個まで返し、続きは `cursor` で取る。形は、版とその版の中で最後に返したパスで、位置の番号ではない(作業 G の設計、2026-11-26)。
- 画面は、書き出しのリンクを `<a href download>` にし、ボタンの形にしない。ファイルの種類を、かっこで添える。スライドの一覧は表にしない(05-UI-RULES.md)。
- 画面の文言は、日本語と英語の両方を用意する(D-12)。
