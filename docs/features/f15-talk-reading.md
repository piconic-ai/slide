# F15 話した言葉といっしょに読む

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に来られなかった人が、あとから公開デッキを開く。スライドには図と短い見出ししかなく、発表者がなぜその設計にしたのかは口頭でしか話されていない。ノートをそのまま載せても、箇条書きのメモでは読みにくい。

## 得られる結果

読者は、スライドと発表で話した内容を 1 本の記事として読める。作者は、ノートから記事を一から書き起こさずに済む。

## 体験の流れ

1. 作者がスライドとスピーカーノートを含む資料を公開する。
2. サービスが、スライドとノートをもとに AI で記事の文章の下書きを作る。作者が自分で書いた記事を渡した場合は、下書きを作らない。
3. 作者が下書きを確認・編集し、読者に見せることを選ぶ。
4. 読者は「ノートで読む」と「スライドでめくる」を切り替える。どちらの表示でも URL は同じで、ページ番号で特定の 1 枚に飛べる。

## 作る範囲

- 資料からスライドごとのノートを読み取る仕組み。最初は 1 つの作成ツールに対応する。生成に使うノートは読者に配信しない。
- ノートとスライドの内容から、ページに対応した段落を持つ記事の下書きを作る。
- 作者による下書きの編集・公開・取り下げ。作者が用意した記事の受け取り。
- 記事表示とスライド表示の切り替え。段落から対応するページへ移動できる。
- 生成回数と文字数の上限。上限はプランと運用設定で決める。

## 作らないこと

- 作者が確認していない下書きを、読者に見せること。
- ノートがない資料について、スライドの内容だけから話していない説明を作ること。
- 登壇動画・音声の文字起こしと、録画の時刻との対応づけ。これは保留とする。
- 生成クレジットの販売。

## 受け入れ条件

- 作者が公開を選ぶまで、下書きは作者以外に届かない。下書きのまま資料を更新しても、読者には新しい版との対応が確かめられた段落だけを含む公開済みの記事か、記事なしの表示が出る。
- 資料を更新したとき、どのページの記事が古いままかを作者が確認できる。古い記事を新しい版のページへ黙って当てはめない。
- 記事表示とスライド表示で、同じページ番号が同じ版の同じページを指す。
- 有料・チーム限定の資料の記事とノートは、本文と同じ閲覧権限で保護する。
- 生成に失敗したり上限に達したりしても、資料の公開と閲覧は止めない。

## 未決事項

- 最初に対応する作成ツールと、ノートを読み取る形式。
- 下書きの文体を作者が指定できるか。生成に使うモデルと、1 回の生成にかかる費用。
- 発表者ノートを公開したくない作者への、生成に使ってよい範囲の確認方法。生成に使うノートは配信しない成果物として受け取る([開発設計](../dev/design.md#発表者ノートと外部録画))。

技術上の制約は [開発設計](../dev/design.md#talk-reading) を参照してください。
