# F33 Luma の配信でコミュニティに紐づける

状態は実装済みです(第三スコープ。統合ブランチ `scope3` に入り、本番にはまだ反映していない。ローカルの模擬配信で確かめた。人の確認として、Luma の実物の配信 1 つでのイベントの URL の位置と応答、本番の Cron Trigger での定期の取得が残る)。実装の設計は [Luma の配信の実装設計](../dev/f33-luma-feeds.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

Luma でイベントを開く勉強会がある。Luma のイベントの URL(`https://luma.com/<文字列>`)には、グループ名が入っていない。そのため、connpass のようにホスト名で照らし合わせられず、発表のスライドがコミュニティ([コミュニティをつくる](f30-communities.md))に集まらない。

## 得られる結果

Luma でイベントを開くコミュニティも、カレンダーの「iCal で購読」の URL を紐づけ用リンクに入れておけば、Luma のイベントの発表が自動でコミュニティに集まる。サービスは、Luma に負担をかけない間隔で配信を読み、何を読んでいるかをヘルプ(`/help/bot`)で明かす。配信の中身は、イベントの URL の照らし合わせにだけ使い、保存しない。

## 体験の流れ

1. コミュニティの管理者が、Luma のカレンダーの「iCal で購読」の URL をコピーし、紐づけ用リンクに入れる。
2. サービスが、その配信を読み、並んでいるイベントの URL を覚える。
3. 作者が、スライドの関連リンクに Luma のイベントの URL を入れる。
4. その URL が配信に並ぶイベントと一致すれば、スライドがそのコミュニティに入る。
5. サービスは、各カレンダーを 1 日 1 回読む。紐づけ用リンクを足したときと、どのカレンダーにも無い Luma のイベントのリンクが保存されたときは、前倒しで読む。

## 作る範囲

- Luma のカレンダーの iCal 配信を読む、1 つの取得の口(ホストとパスの検査、User-Agent、条件付きの取得、大きさと待ち時間の上限、リダイレクトを追わない)。
- 配信ごとの記録の表(最後に読んだ日時、次に読んでよい日時、`ETag`、`Last-Modified`、続けて失敗した回数、止まっているか)。
- 間隔と上限の守り、失敗の扱い、前倒しの依頼。
- iCal の解析と、イベントの URL の照らし合わせ。
- Cron Trigger による 1 日 1 回の実行。
- 運営の画面の「止まった配信」と「再開する」。
- ローカルの起動でだけ有効な、模擬配信の経路。
- `/help/bot` の説明。

## 作らないこと

- Luma のページや API を読むこと。カレンダーのページの URL から番号を調べることもしない。
- 配信の中身(イベント名、日時、場所)を画面に出すこと、保存すること。イベントの URL の鍵だけを持つ。
- Luma 以外の配信(connpass などの iCal を含む)。connpass の利用規約は、API 以外の方法でのアクセスを禁じている。
- 配信から消えたイベントを、コミュニティから外すこと。過去のイベントは配信から落ちることがある。

## 受け入れ条件

- **F33-AC1** Luma のカレンダーの iCal の URL を紐づけ用リンクに持つコミュニティに、その配信に並ぶ Luma のイベントの URL を関連リンクに持つスライドが入る。
- **F33-AC2** 紐づけ用リンクを足すと、その配信が 1 時間以内に読まれていなければ、すぐに読まれる。
- **F33-AC3** どのカレンダーにも無い Luma のイベントのリンクが保存されると、配信が前倒しで読まれる。ただし同じ配信は 1 時間に 1 回までで、前倒しの依頼が何度来ても超えない。
- **F33-AC4** Luma への取得は、同時に 1 本で、1 分に 10 本を超えない。
- **F33-AC5** 2 回目からの取得は、前の応答の `ETag` か `Last-Modified` をもとに、`If-None-Match` か `If-Modified-Since` を付けて行う。`304` のときは、前の結果を保つ。
- **F33-AC6** 取得の User-Agent は `slide.community-bot/1.0 (+https://slide.community/help/bot)` である。
- **F33-AC7** `429` か `503` に `Retry-After` が付いていれば、その時刻まで同じ配信を読まない。
- **F33-AC8** 失敗した配信は、すぐにやり直さず、間隔を倍々に広げて(上限 1 日)読む。
- **F33-AC9** 5 回続けて失敗した配信は読まれなくなり、運営の画面の「止まった配信」に、止まった理由とともに出る。運営が「再開する」を押すと、また読まれる。
- **F33-AC10** `https://api.luma.com/ics/get` 以外の URL には取りに行かない。そのような URL は、Luma の紐づけ用リンクとして入れられない。リダイレクトを追わない。
- **F33-AC11** 2 MB を超える応答、10 秒を超える応答は、打ち切られ、失敗として数えられる。
- **F33-AC12** 配信の中のイベント名や日時は、どの画面にも出ず、保存もされない。
- **F33-AC13** 配信から消えたイベントは、コミュニティから外れない。
- **F33-AC14** Cron Trigger で、1 日 1 回、配信が順に読まれる。
- **F33-AC15** 模擬配信の経路は、ローカルの起動でだけ有効で、本番の設定には、その経路も、模擬配信へ取りに行く許可も無い。
- **F33-AC16** 配信のイベントの URL は、iCal の `URL` の行と `DESCRIPTION` の中の両方から読む。
- **F33-AC17** Luma への取得は、ソースの中の 1 つの関数だけが行う。取得先のホスト(`api.luma.com`)へ `fetch` する箇所が、ソースの 1 か所にしかない。
- **F33-AC18** `/help/bot` が開き、読む対象(Luma のカレンダーの iCal の配信)、間隔(1 日 1 回、同じ配信は 1 時間に 1 回まで)、目的(イベントの URL の照らし合わせ。中身は保存しない)、問い合わせ先が、日本語と英語で書かれている。
- **F33-AC19** 削除。(第四スコープで、ヘルプの目次がなくなり、記事の一覧に替わった。F33-AC21 で書き直した)
- **F33-AC20** 配信の 1 件のイベントに、名前の URL(`https://luma.com/<文字列>`)と、番号の URL(`https://luma.com/event/evt-…`、`LOCATION` の行か `UID` の `evt-…@events.lu.ma`)の両方があれば、番号の URL を関連リンクに入れたスライドも、名前の URL のイベントに並ぶ。配信を読むのがリンクの保存の前でも後でも同じ。番号の URL のイベントだけがあったときは、そのイベントが名前の URL のイベントになり、番号(`/events/:id`)と名前を保つ。両方あったときは、名前の URL のイベントに発表が移り、名前が無ければ番号の URL のイベントの名前を受け継ぐ。どの配信にも無い番号の URL は、それだけで 1 つのイベントになる。
- **F33-AC21** 取得の User-Agent のリンク先の `/help/bot` が、ヘルプの「安全と規約」の一覧から移れる([ヘルプで答えを見つける](f36-help-answers.md) の F36-AC24)。

## 決めたこと

第三スコープを作るにあたり、次のように決めた(2026-11-23、第三スコープの指示書)。

- サービスから外のサイトへ取りに行くのは、Luma のカレンダーの iCal 配信だけにする(D-02)。
- Luma の紐づけ用リンクは、カレンダーの「iCal で購読」の URL(`https://api.luma.com/ics/get?entity=calendar&id=cal-…` の形)にする(D-05)。
- 配信は、イベントの URL の照らし合わせにだけ使う。配信の中身は画面に出さず、保存もしない(D-60)。
- 各カレンダーを 1 日 1 回(Cron Trigger)読む。紐づけ用リンクを足したとき、どのカレンダーにも無い Luma のイベントのリンクが保存されたときは、前倒しで読む(D-61)。
- 同じ配信は 1 時間に 1 回まで(D-62)。取得は同時に 1 本、1 分あたり 10 本まで(D-63)。
- `ETag` と `Last-Modified` を記録し、条件付きで取りに行く。応答の大きさは 2 MB、待ち時間は 10 秒まで(D-64)。
- 失敗したら間隔を倍々に広げる(上限 1 日)。`429` と `503` の `Retry-After` には必ず従う。5 回続けて失敗した配信は読むのを止め、運営の画面に出す(D-65)。
- User-Agent は `slide.community-bot/1.0 (+https://slide.community/help/bot)`(D-66)。
- 取りに行けるのは `https://api.luma.com/ics/get` だけ。ホストとパスを固定で検査し、リダイレクトは追わない(D-67)。
- 配信に並ぶイベントの URL を、[イベントの発表として並ぶ](f29-event-talks.md) の鍵へそろえ、関連リンクの鍵と一致すれば、そのコミュニティに入れる。配信から消えたイベントは外さない(D-68)。
- テストと確認では、Luma に実際に取りに行かない。ローカルの模擬配信で確かめる。iCal の中のイベントの URL の位置は、Luma の公開の説明か実物の配信で確かめるまで、`URL` の行と `DESCRIPTION` の中の両方を読む(D-69)。
- Luma が「iCal で購読」で出す URL のホストは `api.luma.com` だったので、取りに行くホストを `api.lu.ma` から `api.luma.com` に変えた。`api.lu.ma` で入れた紐づけ用リンクは、`api.luma.com` の形にそろえて持つ。`api.lu.ma` へは取りに行かない(2026-11-26、依頼者が実物の URL で確かめた)。
- Luma のイベントの番号の URL(`https://luma.com/event/evt-…`)も Luma のイベントとして受け付け、配信が同じイベントの名前の URL と結びつけたら、名前の URL のイベントにまとめる。結びつきは、配信から読んだ 2 つの URL の鍵だけを持つ(D-60)。一度結びついた番号は、後から変えない(2026-11-26、依頼者の回答)。
