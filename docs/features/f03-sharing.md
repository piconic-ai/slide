# F03 URL を渡して読んでもらう

状態は実装済みです(共有 URL、viewer、ページごとの共有、共有メニュー、ヘルプ。実際のブログサービスでの埋め込みは、人の確認が残る)。viewer の並びの切り替え(F03-AC105 から F03-AC121)は実装中で、実際の画面での人の確認が残る。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会の終了時、登壇者が参加者へ資料の URL を渡す。参加者はログインせずスマートフォンで開き、後日 PC で同じ資料を読み返す。

## 得られる結果

作成ツールをインストールしていない相手にも、ブラウザだけで資料を届けられる。

## 体験の流れ

1. 公開した資料の共有 URL をコピーする。
2. 相手が URL を開き、資料を閲覧・操作する。
3. 読んだ人が、viewer の「共有」から、スライド全体や、いま見ているページを、URL のコピー、SNS への投稿、[ブログへの埋め込み](f25-embed.md)で広める。
4. 使い方を知りたい人は、ヘルプで、置き方から埋め込みまでを 1 か所で読む。

## 作る範囲

- /@handle/slug 形式の資料 URL と、ページ番号つきの URL(`/@handle/slug/6`)。ページごとの画像は [説明したいページを画像付きで共有する](f05-page-ogp.md) で扱う。
- ページ構成。トップをアップロードの入口にし、説明のための LP は置かない。すべての画面に、共通のヘッダーとフッターを付ける。
- viewer の構成。上から、スライド、題名と操作のボタン(「レイアウト」「全画面」「共有」「⋯」。作者本人には、先頭に「編集する」)、作者と「フォロー」、説明、関連リンク([関連リンクを紐付ける](f27-related-links.md))、記事([発表を書き起こした記事を添える](f26-article.md))、引用([引用でつながる](f24-citations.md))。これが「縦並び」で、まだ並びを選んでいない人の見た目である。記事には見出しを付けず、説明と関連リンクのあとに本文が続く。中身のない節は、出さない。公開する前のスライドは、[作者だけが見られる](f02-publication.md)。
- viewer の並びの切り替え。「縦並び」「横並び」「ワイド」の 3 つから、題名の行の右のアイコンのボタンで選ぶ。「横並び」は、左の列にスライド、題名と操作、記事、右の列に作者・説明・関連リンク・引用を置き、右の列は記事を読み進めても見えている。「ワイド」は、スライドを画面の横幅いっぱいに広げ、その下を同じ 2 列にする。選んだ並びは、閲覧中のブラウザに保存する。幅 760px 以下では、選んだ並びに関わらず「縦並び」にし、切り替えのボタンも出さない。
- ログイン中のヘッダー。サービス名、お知らせのベル、アカウントのメニュー(「プロフィール」「スライドの管理」「設定」「ログアウト」)。
- スライドの編集(`/slides/:deck`)。公開、共有 URL、新しい版、引用されたスライド、削除だけを置く画面。中身は [作者のみ限定公開で発表し、一般公開する](f02-publication.md) が受け持つ。
- 画面の移り方。ヘッダーとフッターを残して、本文だけを差し替える。
- 共有メニュー。「URL をコピー」「いま見ているページの URL をコピー」「X に投稿」「Bluesky に投稿」「埋め込みコードをコピー」。
- ヘルプ。置き方、ページごとの共有、引用、ブログへの埋め込み、AI エージェントから置く、フォロー、ログイン、記事、関連リンク、プロフィール、安全について、規約、プライバシー(ログイン、記事、関連リンク、プロフィールは第二スコープで足す)。
- 資料の独自 JS を隔離して動かし、相対パス・ルート相対パスのファイルを読み込む。外部への通信の制限は [知らない人のスライドも、安心して開ける](f17-safe-viewing.md) で扱う。
- ページ認識のアダプターがない HTML も、元の資料として表示する。

## 作らないこと

- コメント欄、独自ドメイン。フォローは、[気になる人を、フォローする](f21-follow.md) で作ることにした(2026-11-18)。
- どんな HTML でもページを自動判定すること。
- トップページでの価値の説明(さわる、わかる、あつまる、クリエイターへ)と、説明用の模型。置く操作そのものが、何をするサービスかを伝える。
- ログインの説明のページ(`/start`)。ログインのボタンは、メールのコードでログインする `/login` へ直接進む([メールのコードでログインする](f28-email-login.md))。
- viewer の SNS の投稿のタイムライン、イベントとコミュニティの表示。
- viewer の並びを、別の端末やアカウントへ引き継ぐこと。選んだ並びは、その人が閲覧しているブラウザの中だけに保存する(サーバーには送らず、アカウントにも結びつけない)。ログインしていない人にも同じに動き、データの置き場や個人情報の扱いが増えない。
- 色面と切り紙の図形を使った見た目の作り込み。第一スコープの画面は、白地、墨の文字、ピルのボタン、トークンだけで組む。

- **F03-AC59** ほかの画面から viewer を開いた(ページ全体の移動)後、表示中のページの番号に合わせて、アドレスバーの URL が 1 回だけ更新される。
- **F03-AC60** viewer を 2 回開いた後も、共有メニュー、コピー、URL の更新が二重に動かない。
- **F03-AC61** JavaScript が動かないブラウザでも、リンクでふつうの画面の移動ができる。
- **F03-AC62** 削除。(「自分のスライド」を外し、ブラウザが形を覚えている場合だけを測る書き方をやめた。測るのは、はじめて開く端末と未ログインを含む 4 つの状態で、F03-AC80〜F03-AC83 で書き直した)
- **F03-AC80** ログイン中の人が、何も覚えていないブラウザ(はじめて開く端末)でトップを開くとき、「フォロー中の人の新着」と最近のスライドが届くまでと届いたあとの Layout Shift の値(CLS)が 0.1 以下である(目標は 0.05 以下)。フォローしている人の新着が 4 件ある、一部だけある、1 件もない、のどれでも、また新着の取得に失敗したときも同じである。ドロップ枠も、ログイン中の人には最初から小さい枠で出て、あとで縮まない。
- **F03-AC81** ログインしていない人がトップを開くとき、CLS が 0.1 以下である。ログイン中の人のための場所を、先に取らない。
- **F03-AC82** ログイン中の人がほかの画面からトップへ移る(ページ全体を読み込まない)とき、CLS が 0.1 以下である。
- **F03-AC83** 最近のスライドの仮の表示は、届いたときの表示(題名 2 行ぶんと日付の行を含む)と同じ高さで、届いた件数が少なくても、題名が長くても、フッターの位置が変わらない。1 本も公開されていないときも、読み込めなかったときも、場所は変わらず、そのことと(失敗のときは)取り直すボタンを同じ場所に出す。
- **F03-AC63** 管理画面の CSP は、router のために広げない。足すものはなく、どのページも、これまでの CSP のままである。(「`connect-src` に `'self'` を足しただけ」を直した。`connect-src 'self'` は `/api/session` のために元からある。)
- **F03-AC71** viewer の作者のスライドの枠が、自分で別の deck の origin へ移ろうとしたとき、viewer の CSP(`frame-src`)が、request を出す前に断る。
- **F03-AC72** viewer(と埋め込み)へのリンクと、viewer からのリンクは、ページ全体の移動になる。理由: viewer は作者のスライドの枠を持ち、CSP がほかの画面と違う(フォームを許さない、枠は 1 つの deck の origin だけ)ため。CSP を広げずに差し替えると、移った先のフォームや枠が動かず、広げると守りが弱まる。作者だけが開ける版の viewer も同じで、router は取りに行かない。
- **F03-AC73** フォームの要る画面へ、フォームを許さない画面(ヘルプ、規約)から移るとき、ページ全体の移動になる。移った先の画面は、移る前の画面の CSP の下で動くので、フォームが送れないままにしないためである。そのほか、移る先が移る前の画面の CSP の許す範囲を超える(たとえば作者のスライドの表紙の画像を出す画面へ、出さない画面から移る)ときも、ページ全体の移動になる。
- **F03-AC75** 共有メニューのコピーのボタンは、押して「コピーしました」に変わっても、メニューの幅、各行の高さと位置が変わらず、行に枠がつかない。幅 1280px と 375px のどちらでも。理由: いちばん長い行(「いま見ているページの URL をコピー」)を押すと、その行が短くなってメニューが狭まり、位置がずれていた(依頼者の指摘、2026-11-21)。ボタンは、ふだんの文言と「コピーしました」の長いほうの大きさを、先に取る。コピーしたことを伝える読み上げ(F03-AC18)は、そのまま保つ。
- **F03-AC76** フッターは、本文が短い画面(お知らせが空、存在しない画面、設定など)でも、画面の下に置かれる。本文が長い画面では、本文の下に続き、重ならない。幅 1280px と 375px のどちらでも。ヘッダーとフッターは `main` の外にあるので、router が `main` の中身を差し替えても崩れない。viewer の枠の高さは変えない。
- **F03-AC74** 単独で置いたリンク(文の中のリンクを除く)の押せる範囲は、幅 1280px と 375px のどちらでも、高さ 44px 以上である。描いた高さが小さいリンクは、見た目を変えずに当たり判定を広げる(`05-UI-RULES.md` の「押せるもの」)。
- **F03-AC64** viewer の作者の HTML の枠の CSP と sandbox は、変わらない。
- **F03-AC65** スライドの編集の戻るリンクの文言が、「スライドの管理」へ戻ることを示し、「1 本の管理」の呼び名が画面に残っていない。
- **F03-AC66** ヘルプの本文に、「1 本の管理」の呼び名が残らず、スライドの編集と書かれている。
- **F03-AC67** 画面を移った後、その画面の CSS が当たっている(計算後のスタイルが、ページ全体を読み込んだときと同じである)。
- **F03-AC68** 画面を移った後、その画面のボタン、共有メニュー、ドロップ枠が、ページ全体を読み込んだときと同じに動く。
- **F03-AC69** ファイルの送信とダウンロードは、ページ全体の移動になる。
- **F03-AC90** ログインしていない人にも、viewer の「⋯」に「この作者をミュート」が出る。押すと、ログインを促すモーダル([F21-AC46](f21-follow.md) から F21-AC49)が開き、ミュートは送られない。自分のスライドと停止中の読者には出ない。
- **F03-AC91** ログインしていない人が viewer の「通報する」を押すと、全画面のログインの案内ページに代えて、ログインを促すモーダルが開く。script が動かないときは、これまでの案内ページ(401)へ進む([F17-AC18](f17-safe-viewing.md))。
- **F03-AC92** 共通のフッターに、GitHub のリポジトリ(https://github.com/piconic-ai/slide)へのリンクが、GitHub のマーク(Octicons の `mark-github`)のアイコンで出る。トップ、プロフィール、ヘルプ、存在しない画面など、共通のフッターを持つどの画面にも、ログインの有無によらず出る。viewer の作者の HTML の枠の中には出ない(枠の外の共通のフッターだけ)。
- **F03-AC93** そのリンクの読み上げの名前は、日本語の画面で「GitHub のリポジトリ」、英語の画面で「GitHub repository」である。アイコンは読み上げの対象から外し、アイコンだけで意味が伝わる。アイコンは画像や外部の CSS でなく、インラインの SVG で、文字の色(`currentColor`)で描く。CSP は変えない。
- **F03-AC94** そのリンクの押せる範囲は、幅 1280px と 375px のどちらでも、幅と高さが 44px 以上である。キーボードの Tab で届き、フォーカスの輪郭が見える。
- **F03-AC95** そのリンクは外のサイトへのリンクなので、router に横取りされず、ページ全体の移動で、同じタブで開く。`rel` は `noopener noreferrer` である。
- **F03-AC96** `/help` の目次に、ログイン、記事、関連リンク、引用、プロフィールの項目があり、それぞれの節へ移れる。ほかの項目(置き方、ページごとの共有、ブログへの埋め込み、AI エージェントから置く、フォロー、安全について、規約、プライバシー)も、そのまま残る。
- **F03-AC97** ヘルプに書いた、記事の本文の文字数の上限、関連リンクの件数の上限、コードの有効期限と入力の回数、顔写真の画像の大きさの上限が、実装の値と一致している。
- **F03-AC98** ヘルプに、GitHub でログインする手順が残っていない。
- **F03-AC99** ヘルプを英語で開くと、ログイン、記事、関連リンク、引用、プロフィールの節も、英語で出る。
- **F03-AC100** ヘルプのログインの節に、メールのコードでログインすること、いまは招待制であること、コードの有効期限と入力の回数、メールが届かないときのこと、メールアドレスの変更や受信箱を失ったときは問い合わせで対応することが書かれている。
- **F03-AC101** ヘルプの記事の節に、書く場所、下書きと公開、ページの埋め込みの書き方(ページ番号つきの共有 URL を 1 行で書く)、記事の中のリンクが引用として数えられること、使える書き方と使えないもの、AI エージェントから下書きを置けることが書かれている。
- **F03-AC102** ヘルプの関連リンクの節に、足し方、種類、件数の上限が書かれている。
- **F03-AC103** ヘルプの引用の節に、プロフィールの「引用した」「引用された」に何が出るか、自分のスライド同士は数えないことが書かれている。
- **F03-AC104** ヘルプのプロフィールの節に、書ける項目、顔写真の順番(アップロード、Gravatar、頭文字)、メールアドレスはほかの人に見えないことが書かれている。
- **F03-AC105** まだ並びを選んでいないブラウザで viewer を開くと、スライド、題名と操作、作者、説明、関連リンク、記事、引用が、この順に 1 列で並ぶ(「縦並び」)。
- **F03-AC106** 幅 761px 以上の viewer の題名の行に、選んでいる並びのアイコンと小さな ▾ を持つボタンが、「全画面」の左に出る。読み上げの名前は「レイアウトを選ぶ(いまは縦並び)」の形で、メニューが閉じている間は `aria-expanded="false"` である。
- **F03-AC107** そのボタンを押すと、`role="menu"` のメニューが開いて `aria-expanded="true"` になり、`role="menuitemradio"` の 3 項目「縦並び」「横並び」「ワイド」が、アイコンと名前だけで並ぶ。選んでいる項目だけが `aria-checked="true"` で、✓ と薄い背景が付く。
- **F03-AC108** メニューで項目を選ぶと、メニューが閉じ、viewer の並びがその並びに変わり、ボタンのアイコンと読み上げの名前もその並びになる。
- **F03-AC109** 開いているメニューは、ボタンをもう一度押す、メニューの外を押す、Escape を押す、のどれでも閉じる。Escape で閉じたとき、フォーカスはボタンに戻る。ボタンで下矢印を押すとメニューが開いて選んでいる項目にフォーカスが移り、矢印キーで項目を移り、Enter で選べる。
- **F03-AC110** 選んだ並びは、そのブラウザの `localStorage` の `slide-viewer-layout` に `stack`・`side`・`wide` のどれかで保存される。ページを読み直しても、ほかのスライドの viewer を開いても、同じ並びで開く。
- **F03-AC111** 保存された値が `stack`・`side`・`wide` のどれでもないとき、値を無視して「縦並び」で開き、そのあと選べる。
- **F03-AC112** `localStorage` を読み書きすると例外になるブラウザでも、viewer は壊れず(ページのエラーが出ない)、選んだ並びがそのページを開いている間だけ切り替わる。
- **F03-AC113** 幅 760px 以下の viewer は、保存された並びに関わらず「縦並び」で、切り替えのボタンが出ない。幅 761px から、ボタンが出る。
- **F03-AC114** 「横並び」で、左の列にスライド、題名と操作、記事が上からこの順に並び、右の列に作者・説明・関連リンク・引用が並ぶ。右の列は幅 280px 以上で、全体の 3 分の 1 ほどである。記事を読み進めてスクロールしても、右の列は上から 16px の位置に残る(`position: sticky; top: 16px`)。
- **F03-AC115** 「ワイド」で、スライドが画面の横幅いっぱい(左右の余白なし、角丸なし)に広がり、その下で、左に題名と操作と記事、右に作者・説明・関連リンク・引用が並ぶ。右の列は「横並び」と同じく残る。
- **F03-AC116** 切り替えても、markup の要素の順は変わらない(読み上げと Tab の順は、どの並びでも同じである)。
- **F03-AC117** viewer に「記事」という見出し(`h2`)がない。記事の節は `aria-label="記事"`(英語では `Article`)で意味を残し、本文は説明と関連リンクのすぐあとに続く。
- **F03-AC118** 関連リンク、記事、引用が 1 件もないスライドは、どの並びでも、その節の見出しも余白も出ず、横にはみ出さない。
- **F03-AC119** どの並びでも、スライドの枠は 16:9(画面の高さに収まらないときの高さの上限は、これまでと同じ)で、記事の中のページの画像を押すと、上のスライドがそのページに移る。
- **F03-AC120** 作者だけが開ける版の viewer でも、「横並び」と「ワイド」で、通知の帯とスライドが画面の中に収まり、横にはみ出さない。
- **F03-AC121** 並びを切り替えても、viewer の CSP は変わらず(`script-src 'self'`、`style-src 'unsafe-inline'`)、CSP の違反が出ない。インラインの script は足さない。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 説明のための LP は置かない。トップページをアップロードの入口にする。トップから外した説明のうち、必要なものはヘルプへ移す。
- `/start` は `/` へ、`/slides/new` は `/slides` へ、303 で送る。
- トップは、静的なファイルを生成して、表示の後にログインの状態で中身を切り替える方式を保つ(`GET /api/session`)。
- viewer のヘッダーは、ほかの画面と同じ共通のものにする。
- 日付は `src/share/dates.ts` の書式にそろえる。日本語は「2026年11月19日」。
- 顔写真がないときは、頭文字を出す。
- トップの最近のスライドは、横に流さず、折り返す格子にする。
- 共有メニューの項目は、上の 5 つ。ブラウザが OS の共有(`navigator.share`)に対応しているときは、「ほかのアプリで共有」を 6 つ目に足す。
- 「X に投稿」「Bluesky に投稿」は、それぞれの投稿画面を新しいタブで開くリンクにする。題名と、いま見ているページの URL を渡す。
- 第一スコープの画面は、`DESIGN.md` の枠の決まり(白地、墨の文字、ピルのボタン、トークン)だけで組む。色面と切り紙の図形は使わない。色を入れる場所は、できた画面を見てから決める。
- 画面の文言は、日本語と英語の両方を用意する。

第一スコープの見直しで、次のように決めた(2026-11-20)。

- ログイン中のヘッダーは、サービス名、お知らせのベル、アカウントのメニューの 3 つにする。「スライドの管理」は、アカウントのメニューの中にだけ置く。ログイン中のトップに「自分のスライド」は置かない(2026-11-21。理由は F21-AC15)。置いた直後の viewer の「編集する」(F03-AC29)も、入口である。
- 作者が自分のスライドの viewer を開くと、操作のボタンの先頭に「編集する」を出す。押すと、スライドの編集へ進む。読者には出さない。作者本人かどうかは、サーバーが判定して出し分ける(viewer は、サービス自身の markup と `/share.js` だけを動かす)。
- `/slides/:deck` の呼び名を「スライドの編集」にする。画面の題、戻るリンク、文言、ヘルプ、文書をそろえる。URL は変えない。
- スライドの管理(`/slides`)の各行の「管理する」は「編集する」にする。行の表紙と題名は、viewer へのリンクにする。
\1
- 英語の題は、スライドの編集が `Edit slide`(1 本のスライドを編集するため、複数にしない)、スライドの管理が `Your slides` にする。スライドの編集の戻るリンク、アカウントのメニュー(「スライドの管理」の行は残る)、ヘルプの本文、エラーの文も、同じ呼び名にそろえる。
- 表紙のカードは、どの画面でも、スライドの 1 ページ目を出す。撮影の結果を待つ間と、撮れなかったときだけ、題名の面を出す。撮影の仕組み(Browser Rendering の使い方)は、[説明したいページを画像付きで共有する](f05-page-ogp.md)に書く。
- 画面を移るときは、`@barefootjs/router` で、ヘッダーとフッターを残して本文だけを差し替える。ログインとログアウト、ファイルの送信、外のサイトへのリンク、ダウンロード、viewer の全画面は、差し替えずにページ全体の移動にする。移った後は、題、`<meta>`、`og:` を新しいページのものにし、フォーカスを本文に移す。ログイン中のトップでは、中身が届く前に同じ大きさの仮の表示を出して、画面がずれないようにする。管理画面の CSP は、router が同じ origin から取りに行くのに必要な分だけ広げ、viewer の作者の HTML の枠の守り(sandbox、別 origin)は変えない。設計は[共有 URL と配信の実装設計](../dev/f03-sharing.md#画面の移り方)に書く。

viewer の並びの切り替えで、次のように決めた(2026-11-22)。

- 並びは「縦並び」「横並び」「ワイド」の 3 つで、まだ選んでいない人は「縦並び」である。理由: いまの見た目を変えず、選んだ人だけが変わる。
- 切り替えは、題名の行のアイコンのボタンとメニューにする。説明文は置かない。理由: 題名の行を増やさず、名前とアイコンだけで違いが分かる。
- 選んだ並びは、閲覧中のブラウザの `localStorage` だけに保存する。理由: 並びは見た目の好みで、アカウントを持たない読者にも同じに効かせたい。サーバーに送ると、読者を覚える仕組みが増える。
- 幅 760px 以下は、保存した値に関わらず「縦並び」にして、ボタンも出さない。理由: 2 列は狭い幅に収まらない。保存した値は消さないので、広い画面で開けば戻る。
- 並びは CSS(コンテナの `data-layout` と `grid-template-areas`)で切り替える。理由: 要素を作り直さないので、スライドの枠(iframe)が読み直されず、ページの移動や全画面を壊さない。
- 「記事」の見出し(`h2`)をなくした。理由: 記事をスライドの直下から読めるようにするため。節の意味は `aria-label` で残す。記事の本文の見出しは、これまでどおり `h3` から始まる。
- 右の列に置く作者・説明・関連リンク・引用は、`.viewer-side` の 1 つの要素にまとめる。理由: 記事を読み進めても右の列を残す(`position: sticky`)には、1 つの要素が要る。そのため、markup では引用が記事より前に来る。縦並びでは、CSS で記事を引用の前に見せる。読み上げと Tab の順だけが、縦並びの見た目と違い、引用が記事の前になる(F03-AC116)。
- 題名の行の操作を、題名と同じ行(同じ要素)に置き、作者は題名の行の下の `.viewer-side` に移した。理由: 並べ替えのために、作者を右の列に置く必要がある。幅 599px 以下では、これまで「題名、作者、操作」の順だったが、「題名、操作、作者」になる。
- 保存した並びは、script(`/share.js`、ページの読み込み後に動く)が適用する。CSP を広げず、インラインの script を足さないため。保存した並びが「縦並び」でないブラウザでは、script が動くまでの短い間、「縦並び」が見え、そのあと切り替わることがある(未決事項)。

## 未決事項

- 色を入れる場所。できた画面を見てから決める。
- 最初に対応するブラウザとモバイル操作の範囲。
- 保存した並びが「縦並び」でないとき、読み込みの直後に「縦並び」が一瞬見えて、並びが切り替わるちらつきを許すか。避けるには、`<head>` で先に動く別の script を 1 つ足す必要がある(読み込みを 1 回増やす)。作者の判断を待つ(F03-AC110 の動きは変わらない)。
