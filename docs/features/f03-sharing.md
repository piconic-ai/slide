# F03 URL を渡して読んでもらう

状態は実装済みです(共有 URL、viewer、ページごとの共有、共有メニュー、ヘルプ。実際のブログサービスでの埋め込みは、人の確認が残る)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会の終了時、登壇者が参加者へ資料の URL を渡す。参加者はログインせずスマートフォンで開き、後日 PC で同じ資料を読み返す。

## 得られる結果

作成ツールをインストールしていない相手にも、ブラウザだけで資料を届けられる。

## 体験の流れ

1. 公開した資料の共有 URL をコピーする。
2. 相手が URL を開き、資料を閲覧・操作する。
3. 読んだ人が、viewer の「共有」から、スライド全体や、いま見ているページを、URL のコピー、SNS への投稿、[ブログへの埋め込み](f25-embed.md)で広める。
4. 使い方を知りたい人は、ヘルプで、置き方から埋め込みまでを 1 か所で読む。

## 作る範囲

- /@handle/slug 形式の資料 URL と、ページ番号つきの URL(`/@handle/slug/6`)。ページごとの画像は [説明したいページを画像付きで共有する](f05-page-ogp.md) で扱う。
- ページ構成。トップをアップロードの入口にし、説明のための LP は置かない。すべての画面に、共通のヘッダーとフッターを付ける。
- viewer の構成。上から、スライド、題名、作者と「フォロー」、操作のボタン(「全画面」「共有」「⋯」)、説明、引用([引用でつながる](f24-citations.md))。
- 共有メニュー。「URL をコピー」「いま見ているページの URL をコピー」「X に投稿」「Bluesky に投稿」「埋め込みコードをコピー」。
- ヘルプ。置き方、ページごとの共有、引用、ブログへの埋め込み、AI エージェントから置く、フォロー、安全について、規約、プライバシー。
- 資料の独自 JS を隔離して動かし、相対パス・ルート相対パスのファイルを読み込む。外部への通信の制限は [知らない人のスライドも、安心して開ける](f17-safe-viewing.md) で扱う。
- ページ認識のアダプターがない HTML も、元の資料として表示する。

## 作らないこと

- コメント欄、独自ドメイン。フォローは、[気になる人を、フォローする](f21-follow.md) で作ることにした(2026-11-18)。
- どんな HTML でもページを自動判定すること。
- トップページでの価値の説明(さわる、わかる、あつまる、クリエイターへ)と、説明用の模型。置く操作そのものが、何をするサービスかを伝える。
- ログインの説明のページ(`/start`)。ログインのボタンは、GitHub でのログインへ直接進む。
- viewer の SNS の投稿のタイムライン、イベントとコミュニティの表示。
- 色面と切り紙の図形を使った見た目の作り込み。第一スコープの画面は、白地、墨の文字、ピルのボタン、トークンだけで組む。

## 受け入れ条件

- **F03-AC1** 閲覧者がサービスのアカウントを持たず公開資料を開ける。
- **F03-AC2** 削除。(URL の形が `/@handle/slug/3` に決まり、総ページ数を取らないことにした。F03-AC4 で書き直した)
- **F03-AC3** 別の登壇者の資料とキャッシュが混ざらず、アップロードされた JS が管理画面の認証情報を読めない。
- **F03-AC4** `/@handle/slug/3` は、ページ番号を `#3` の形で持つスライドを、3 ページ目から開く。作者がページごとの ID を設定する必要はない。1 から 9999 までの整数の綴りでない番号(`0`、`10000`、`03`、`abc`)の URL は、見つからないページになる。
- **F03-AC5** `/start` を開くと `/` へ、`/slides/new` を開くと `/slides` へ移る。
- **F03-AC6** トップ、viewer、プロフィール、スライドの管理、1 本の管理、設定、ヘルプ、お知らせ、規約などの文書、エラーの画面に、共通のヘッダーとフッターがあり、`<main>` が 1 つある。埋め込みのページ([ブログに埋め込む](f25-embed.md))は、対象外である。
- **F03-AC7** viewer に、SNS の投稿のタイムラインとイベントの表示が出ない。
- **F03-AC8** viewer の操作が「全画面」「共有」「⋯」の 3 つで、「⋯」から通報とミュートへ進める。
- **F03-AC9** 1 本の管理ページに、GitHub の連携の設定が出ない。
- **F03-AC10** 表紙の画像が読めないとき、題名の入った面が出て、壊れた画像の印が出ない。
- **F03-AC11** 幅 375px で、トップ、viewer、プロフィール、スライドの管理、1 本の管理、設定が横にはみ出さない。
- **F03-AC12** viewer の「共有」を押すとメニューが開き、もう一度押す、外側を押す、Escape のどれでも閉じる。
- **F03-AC13** 「URL をコピー」で、クリップボードにスライドの共有 URL(ページ番号なし)が入る。
- **F03-AC14** 3 ページ目を見ているときに「いま見ているページの URL をコピー」を押すと、`/@handle/slug/3` が入る。
- **F03-AC15** ページを伝える script のないスライドでは、「いま見ているページの URL をコピー」が出ない。
- **F03-AC16** 「X に投稿」「Bluesky に投稿」は、題名と、いま見ているページの URL を入れた投稿画面を、新しいタブで開く。ページが分からないスライドでは、共有 URL(ページ番号なし)を入れる。
- **F03-AC17** 一般公開されていないスライドの共有メニューに、「埋め込みコードをコピー」が出ない。
- **F03-AC18** コピーしたことが、ボタンの近くに出て、読み上げにも伝わる。
- **F03-AC19** ブラウザが OS の共有に対応しているとき、共有メニューに「ほかのアプリで共有」が出る。対応していないときは出ない。
- **F03-AC20** `/help` に、目次の 9 つの項目(置き方、ページごとの共有、引用、ブログへの埋め込み、AI エージェントから置く、フォロー、安全について、規約、プライバシー)があり、それぞれの節へ移れる。
- **F03-AC21** ヘルプに書いた、置ける形と上限の数字が、実装(`src/uploads/limits.ts`)と一致している。
- **F03-AC22** ヘルプを英語で開くと、同じ節が英語で出る。
- **F03-AC23** 幅 375px で、ヘルプの目次と本文が横にはみ出さない。
- **F03-AC24** ログイン中のヘッダーに、「スライドの管理」、お知らせのベル、アカウントのメニューがあり、「+」のボタンがない。未ログインのヘッダーの「ログイン」は、GitHub でのログインへ直接進む。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 説明のための LP は置かない。トップページをアップロードの入口にする。トップから外した説明のうち、必要なものはヘルプへ移す。
- `/start` は `/` へ、`/slides/new` は `/slides` へ、303 で送る。
- トップは、静的なファイルを生成して、表示の後にログインの状態で中身を切り替える方式を保つ(`GET /api/session`)。
- viewer のヘッダーは、ほかの画面と同じ共通のものにする。
- 日付は `src/share/dates.ts` の書式にそろえる。日本語は「2026年11月19日」。
- 顔写真がないときは、頭文字を出す。
- トップの最近のスライドは、横に流さず、折り返す格子にする。
- 共有メニューの項目は、上の 5 つ。ブラウザが OS の共有(`navigator.share`)に対応しているときは、「ほかのアプリで共有」を 6 つ目に足す。
- 「X に投稿」「Bluesky に投稿」は、それぞれの投稿画面を新しいタブで開くリンクにする。題名と、いま見ているページの URL を渡す。
- 第一スコープの画面は、`DESIGN.md` の枠の決まり(白地、墨の文字、ピルのボタン、トークン)だけで組む。色面と切り紙の図形は使わない。色を入れる場所は、できた画面を見てから決める。
- 画面の文言は、日本語と英語の両方を用意する。
