# F03 URL を渡して読んでもらう

状態は実装済みです(共有 URL、viewer、ページごとの共有、共有メニュー、ヘルプ。実際のブログサービスでの埋め込みは、人の確認が残る)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会の終了時、登壇者が参加者へ資料の URL を渡す。参加者はログインせずスマートフォンで開き、後日 PC で同じ資料を読み返す。

## 得られる結果

作成ツールをインストールしていない相手にも、ブラウザだけで資料を届けられる。

## 体験の流れ

1. 公開した資料の共有 URL をコピーする。
2. 相手が URL を開き、資料を閲覧・操作する。
3. 読んだ人が、viewer の「共有」から、スライド全体や、いま見ているページを、URL のコピー、SNS への投稿、[ブログへの埋め込み](f25-embed.md)で広める。
4. 使い方を知りたい人は、ヘルプで、置き方から埋め込みまでを 1 か所で読む。

## 作る範囲

- /@handle/slug 形式の資料 URL と、ページ番号つきの URL(`/@handle/slug/6`)。ページごとの画像は [説明したいページを画像付きで共有する](f05-page-ogp.md) で扱う。
- ページ構成。トップをアップロードの入口にし、説明のための LP は置かない。すべての画面に、共通のヘッダーとフッターを付ける。
- viewer の構成。上から、スライド、題名、作者と「フォロー」、操作のボタン(「全画面」「共有」「⋯」。作者本人には、先頭に「編集する」)、説明、引用([引用でつながる](f24-citations.md))。公開する前のスライドは、[作者だけが見られる](f02-publication.md)。
- ログイン中のヘッダー。サービス名、お知らせのベル、アカウントのメニュー(「プロフィール」「スライドの管理」「設定」「ログアウト」)。
- スライドの編集(`/slides/:deck`)。公開、共有 URL、新しい版、引用されたスライド、削除だけを置く画面。中身は [作者のみ限定公開で発表し、一般公開する](f02-publication.md) が受け持つ。
- 画面の移り方。ヘッダーとフッターを残して、本文だけを差し替える。
- 共有メニュー。「URL をコピー」「いま見ているページの URL をコピー」「X に投稿」「Bluesky に投稿」「埋め込みコードをコピー」。
- ヘルプ。置き方、ページごとの共有、引用、ブログへの埋め込み、AI エージェントから置く、フォロー、安全について、規約、プライバシー。
- 資料の独自 JS を隔離して動かし、相対パス・ルート相対パスのファイルを読み込む。外部への通信の制限は [知らない人のスライドも、安心して開ける](f17-safe-viewing.md) で扱う。
- ページ認識のアダプターがない HTML も、元の資料として表示する。

## 作らないこと

- コメント欄、独自ドメイン。フォローは、[気になる人を、フォローする](f21-follow.md) で作ることにした(2026-11-18)。
- どんな HTML でもページを自動判定すること。
- トップページでの価値の説明(さわる、わかる、あつまる、クリエイターへ)と、説明用の模型。置く操作そのものが、何をするサービスかを伝える。
- ログインの説明のページ(`/start`)。ログインのボタンは、GitHub でのログインへ直接進む。
- viewer の SNS の投稿のタイムライン、イベントとコミュニティの表示。
- 色面と切り紙の図形を使った見た目の作り込み。第一スコープの画面は、白地、墨の文字、ピルのボタン、トークンだけで組む。

- **F03-AC69** ファイルの送信とダウンロードは、ページ全体の移動になる。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 説明のための LP は置かない。トップページをアップロードの入口にする。トップから外した説明のうち、必要なものはヘルプへ移す。
- `/start` は `/` へ、`/slides/new` は `/slides` へ、303 で送る。
- トップは、静的なファイルを生成して、表示の後にログインの状態で中身を切り替える方式を保つ(`GET /api/session`)。
- viewer のヘッダーは、ほかの画面と同じ共通のものにする。
- 日付は `src/share/dates.ts` の書式にそろえる。日本語は「2026年11月19日」。
- 顔写真がないときは、頭文字を出す。
- トップの最近のスライドは、横に流さず、折り返す格子にする。
- 共有メニューの項目は、上の 5 つ。ブラウザが OS の共有(`navigator.share`)に対応しているときは、「ほかのアプリで共有」を 6 つ目に足す。
- 「X に投稿」「Bluesky に投稿」は、それぞれの投稿画面を新しいタブで開くリンクにする。題名と、いま見ているページの URL を渡す。
- 第一スコープの画面は、`DESIGN.md` の枠の決まり(白地、墨の文字、ピルのボタン、トークン)だけで組む。色面と切り紙の図形は使わない。色を入れる場所は、できた画面を見てから決める。
- 画面の文言は、日本語と英語の両方を用意する。

第一スコープの見直しで、次のように決めた(2026-11-20)。

- ログイン中のヘッダーは、サービス名、お知らせのベル、アカウントのメニューの 3 つにする。「スライドの管理」は、アカウントのメニューの中にだけ置く(ログイン中のトップの「自分のスライド」にも入口がある)。
- 作者が自分のスライドの viewer を開くと、操作のボタンの先頭に「編集する」を出す。押すと、スライドの編集へ進む。読者には出さない。作者本人かどうかは、サーバーが判定して出し分ける(viewer は、サービス自身の markup と `/share.js` だけを動かす)。
- `/slides/:deck` の呼び名を「スライドの編集」にする。画面の題、戻るリンク、文言、ヘルプ、文書をそろえる。URL は変えない。
- スライドの管理(`/slides`)の各行の「管理する」は「編集する」にする。行の表紙と題名は、viewer へのリンクにする。
\1
- 英語の題は、スライドの編集が `Edit slide`(1 本のスライドを編集するため、複数にしない)、スライドの管理が `Your slides` にする。スライドの編集の戻るリンク、アカウントのメニュー(「スライドの管理」の行は残る)、ヘルプの本文、エラーの文も、同じ呼び名にそろえる。
- 表紙のカードは、どの画面でも、スライドの 1 ページ目を出す。撮影の結果を待つ間と、撮れなかったときだけ、題名の面を出す。撮影の仕組み(Browser Rendering の使い方)は、[説明したいページを画像付きで共有する](f05-page-ogp.md)に書く。
- 画面を移るときは、`@barefootjs/router` で、ヘッダーとフッターを残して本文だけを差し替える。ログインとログアウト、ファイルの送信、外のサイトへのリンク、ダウンロード、viewer の全画面は、差し替えずにページ全体の移動にする。移った後は、題、`<meta>`、`og:` を新しいページのものにし、フォーカスを本文に移す。ログイン中のトップでは、中身が届く前に同じ大きさの仮の表示を出して、画面がずれないようにする。管理画面の CSP は、router が同じ origin から取りに行くのに必要な分だけ広げ、viewer の作者の HTML の枠の守り(sandbox、別 origin)は変えない。設計は[共有 URL と配信の実装設計](../dev/f03-sharing.md#画面の移り方)に書く。
