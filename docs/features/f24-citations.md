# F24 引用でつながる

状態は実装済みです(未決事項に、引用が 4 件を超えたときの画面が残る)。第二スコープで、記事の中のリンクを引用に数えること(F24-AC19〜F24-AC21)と、プロフィールの引用の一覧と数(F24-AC22〜F24-AC34)を足す。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、ほかの人のスライドを踏まえて話す。スライドの中に、そのスライドの共有 URL へのリンクを書く。読んだ人は、元のスライドも読みたい。引用された側の作者は、自分のスライドがどこで使われたかを知りたい。

## 得られる結果

スライドの中にリンクを書くだけで、2 つのスライドがつながる。読んだ人は、引用元へ移れる。引用された側の作者は、引用しているスライドを知る。作者に、申請や入力は要らない。

作者が発表の記事を書いたとき([発表を書き起こした記事を添える](f26-article.md))は、記事の中に共有 URL を書いても、つながる。プロフィールには、その人のスライドが引用された・引用した一覧と数が出る。引用されることが、作者の誉れとして見える。

## 体験の流れ

1. 作者が、スライドの中に、ほかのスライドの共有 URL(ページ番号つきも可)へのリンクを書いて置き、公開する。
2. 引用された側の viewer に「このスライドを引用しているスライド」として、引用した側の viewer に「このスライドが引用しているスライド」として、表紙のカードが出る。
3. 読者が、スライドの中のリンクを押すと、viewer が引用元の共有 URL へ移る。
4. 引用された側の作者は、自分のスライドの viewer で、引用しているスライドの一覧を見る。お知らせでも知る([お知らせ](f20-notifications.md))。
5. 記事に共有 URL を書いたときも、記事が公開中の間は、同じように引用として数えられる。
6. 引用された側、した側の作者のプロフィールの「引用された」「引用した」に、引用の行が新しい順に並び、数が出る。

## 作る範囲

- 検出: 受け取りの確定のときに、その版の HTML から共有 URL へのリンクを読んで、版ごとに保存する。表示に使うのは、公開中の版の引用だけである。
- 表示: viewer の下の、表紙のカード。
- 移動: スライドの中の共有 URL へのリンクで、viewer が移る。
- 記事の中の共有 URL へのリンクを、引用として数えること(第二スコープ)。
- プロフィールの「引用した」「引用された」の一覧(`/@handle/citing`、`/@handle/cited`)と、頭の数。数の並びとタブは [気になる人を、フォローする](f21-follow.md) が受け持つ。
- スライドのカードに添える、引用された数。

## 作らないこと

- お知らせに「引用された」を足すこと。
- ページ単位で、どのページがどのページを引用したかを見せること。
- このサービスの外の URL への引用。
- SNS の投稿のタイムライン、イベントとコミュニティの表示。試作にあったが、取り除く。形を変えて残すこともしない。
- 引用を、埋め込み(iframe)で表示すること。引用しただけで、相手のページの上で自分のスライドが動くのを避ける。
- 引用の数の順位、「よく引用される人」の一覧、引用数のバッジ。数を増やすための相互引用を生む。一覧は新しい順に並べ、多い順には並べない。
- 関連リンクを引用として数えること。共有 URL が入っていても数えない([関連リンクを紐付ける](f27-related-links.md))。

## 受け入れ条件

- **F24-AC1** スライド A の HTML が、スライド B の共有 URL(ページ番号つきも含む)へのリンクを持つとき、A を置いて公開すると、B の viewer に A が「このスライドを引用しているスライド」として出る。
- **F24-AC2** 同じとき、A の viewer に B が「このスライドが引用しているスライド」として出る。
- **F24-AC3** A が何ページで B を引用していても、B の一覧に A は 1 回だけ出る。
- **F24-AC4** 同じスライド(同じ handle と slug)へのリンクは、引用として数えない。同じ作者の別のスライドへのリンクは、数える。
- **F24-AC5** A の公開を止めると、B の viewer から A が消える。もう一度公開すると、また出る。
- **F24-AC6** 引用が 5 件以上あるとき、viewer には 4 件が出て、残りの件数が出る。
- **F24-AC7** 引用が 1 件もないとき、その節は見出しごと出ない。
- **F24-AC8** 読む人がミュートしている作者のスライド、運営が非表示にしたスライド、停止中の作者のスライドは、一覧に出ない(最近のスライドの一覧と同じ扱い)。
- **F24-AC9** A の中の B へのリンクを押すと、viewer が B の共有 URL へ移る。ページ番号つきのリンクなら、そのページから開く。
- **F24-AC10** スライドの中のリンクで viewer が移れるのは、このサービスの共有 URL だけである。ほかの URL へは移らない。
- **F24-AC11** 削除。(スライドの編集の画面に、引用しているスライドの一覧を出す条件だった。F24-AC18 で外した)
- **F24-AC12** 反応の管理(`/slides/:deck/reactions`)が 404 になる。
- **F24-AC13** 公開中の版を新しい版に入れ替えると、引用は新しい版の HTML のものに変わる。なくなったリンクの引用は消える。入れ替えの操作を押すまでは、新しい版を受け取っても、viewer に出る引用は変わらない。
- **F24-AC14** viewer の引用の表示は、表紙のカードであり、引用のスライドを iframe で動かさない。
- **F24-AC15** ブラウザから置いたスライド([スライドを、ドロップして置く](f22-browser-drop.md))でも、確定のときに引用が読まれる。
- **F24-AC16** 空の D1 に migration をすべて適用した後のスキーマに、SNS の投稿とイベントのための表がない。
- **F24-AC17** B が一般公開されていない間(作者のみ、公開を止めた)は、A の viewer に B のカードが出ない。B を公開すると出る。
- **F24-AC18** スライドの編集の画面に、「このスライドを引用しているスライド」の一覧が出ない。引用された側の viewer の一覧(F24-AC1)は、そのまま残る。理由: 引用を知らせるお知らせ(F20-AC3)と、viewer の一覧が、すでに作者に伝えており、編集の画面では、置く・公開する・直すという作業の邪魔になるため(依頼者の指摘、2026-11-21)。
- **F24-AC19** 公開中の記事の中に、ほかの人のスライドの共有 URL へのリンク(段落の 1 行の埋め込みも、文の中のリンクも)があるとき、そのスライドの viewer の「このスライドを引用しているスライド」に、記事を書いたスライドが出る。
- **F24-AC20** 記事を取り下げる(下書きに戻す)と、F24-AC19 の引用が、viewer の一覧から消える。もう一度公開すると、また出る。
- **F24-AC21** 記事の中の、自分のこのスライドへのリンクは、引用として数えない。
- **F24-AC22** ほかの人のスライド A が、この人のスライド B を引用すると、この人のプロフィールの「引用された」(`/@handle/cited`)に、A の表紙、A の作者名と題名、「この人の『B の題名』を引用」、引用が生まれた日の行が出る。
- **F24-AC23** 同じとき、A の作者のプロフィールの「引用した」(`/@handle/citing`)に、B の行が出る。
- **F24-AC24** A が B を、スライドの中と記事の中の両方で引用していても、プロフィールの行は 1 つである。
- **F24-AC25** 自分のスライド同士の引用は、プロフィールの一覧にも数にも入らない。viewer の一覧には、これまでどおり出る。
- **F24-AC26** A の公開を止めると、B の作者の「引用された」から A の行が消え、数が減る。
- **F24-AC27** 見る人がミュートしている作者の行は、その人には出ない。数も、その人に見えるものだけを数える。
- **F24-AC28** 運営が非表示にしたスライドと、停止中の作者のスライドの行は、だれにも出ない。数にも入らない。
- **F24-AC29** プロフィールの引用の行は、引用が生まれた日の新しい順に並ぶ。
- **F24-AC30** プロフィールの引用の一覧は、1 ページ 50 件で、51 件目からは次のページに出る。
- **F24-AC31** ログインしていない人も、`/@handle/cited` と `/@handle/citing` を見られる。
- **F24-AC32** 存在しないハンドル、停止中の人の `/@handle/cited` と `/@handle/citing` は、プロフィールと同じ 404 になる。
- **F24-AC33** 引用された数が 1 件以上のスライドのカード(プロフィール、トップ、viewer の引用)に、引用された数が出る。数え方は、プロフィールの数(F24-AC25、F24-AC27、F24-AC28)と同じである。
- **F24-AC34** 引用された数が 0 件のスライドのカードに、引用された数が出ない。
- **F24-AC35** `cited` と `citing` は、スライドの URL の名前(slug)にならない。自動で決めるときは `-2` を付け、作者が手で変えるときは断る。`/@handle/cited` と `/@handle/citing` は、いつも一覧を開く([気になる人を、フォローする](f21-follow.md) の F21-AC20 と同じ扱い)。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 範囲は、検出、表示、スライド内のリンクでの移動の 3 つ。試作の動きを仕様にする。
- viewer での表示は、埋め込み(iframe)ではなく表紙のカードにする。カードは 4 件まで並べ、残りは件数で示す。
- 引用されたことは、スライドの編集の一覧で作者に見せる。お知らせの種類は足さない。(のちに変わった。編集の一覧は外し、お知らせで知らせる。F24-AC18、2026-11-21)
- 数えるのは、引用した側が一般公開されている間だけにする(試作と同じ)。読むのは、公開中の版の HTML である。カードを出すのは、出す相手のスライドも一般公開されている間だけにする。公開していないスライドの題名や表紙を、引用を通して見せない。ミュート、非表示、停止の扱いは、最近のスライドの一覧と同じにする。
- SNS の投稿とイベントに関わるコード、経路、テーブル、管理の画面(`/slides/:deck/reactions`)は、取り除く。引用だけを残す。本番のデータは空にしてよいので、互換のための経路や表を残さない。

第二スコープで、プロフィールの引用について次のように決めた(2026-11-22。issue #313 で未決だった点を含む)。

- 「引用された」は、ほかの人のスライド(または記事)がこの人のスライドを引用したもの。「引用した」は、この人のスライド(または記事)が引用したほかの人のスライド。
- 引用の組(引用した側のスライド → された側のスライド)ごとに 1 行。同じ組が、スライドの中と記事の中の両方にあっても 1 行。
- 並び順は、引用が生まれた日が新しい順。50 件ずつ。
- 自分のスライド同士の引用は、プロフィールの一覧と数に入れない。viewer の一覧には、これまでどおり出る。
- 出さないものは viewer の引用と同じ(両側が一般公開中でない引用、見る人がミュートしている作者、非表示と停止)。数も同じ条件で数える。
- `/@handle/cited` と `/@handle/citing` は、だれでも見られる。
- スライドのカードに、引用された数を、1 件以上のときだけ小さく添える。
- 4 つの数とタブの並びは、フォロー中、フォロワー、引用した、引用された(タブは先頭にスライド)。引用は嬉しい数だが、多くの人では小さい数になる。先頭に大きく出すとかえって少なさが目立つので、見慣れたフォローの数の後ろに置く。
- 記事の中の共有 URL へのリンクは、スライドの中のリンクと同じく引用として数える。数えるのは記事が公開中の間だけ。
- 引用の数の順位や、「よく引用される人」の一覧は作らない(第二スコープの判断の基準。数を競わせない)。

## 未決事項

- F24-AC9・F24-AC10: スライドは読者の操作なしに、自分の iframe を別の共有 URL へ移動できる。その場合も viewer は移動する。読者が押したときだけ移動する形にできるかは、確かめていない。
- 引用の読み取りに失敗した版を、後から読み直す手段。
