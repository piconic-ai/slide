# F24 引用でつながる

状態は実装中です(試作が動いている)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、ほかの人のスライドを踏まえて話す。スライドの中に、そのスライドの共有 URL へのリンクを書く。読んだ人は、元のスライドも読みたい。引用された側の作者は、自分のスライドがどこで使われたかを知りたい。

## 得られる結果

スライドの中にリンクを書くだけで、2 つのスライドがつながる。読んだ人は、引用元へ移れる。引用された側の作者は、引用しているスライドを知る。作者に、申請や入力は要らない。

## 体験の流れ

1. 作者が、スライドの中に、ほかのスライドの共有 URL(ページ番号つきも可)へのリンクを書いて置き、公開する。
2. 引用された側の viewer に「このスライドを引用しているスライド」として、引用した側の viewer に「このスライドが引用しているスライド」として、表紙のカードが出る。
3. 読者が、スライドの中のリンクを押すと、viewer が引用元の共有 URL へ移る。
4. 引用された側の作者は、1 本の管理ページで、引用しているスライドの一覧を見る。

## 作る範囲

- 検出: 受け取りの確定のときに、その版の HTML から共有 URL へのリンクを読んで、版ごとに保存する。表示に使うのは、公開中の版の引用だけである。
- 表示: viewer の下の、表紙のカード。1 本の管理ページの一覧。
- 移動: スライドの中の共有 URL へのリンクで、viewer が移る。

## 作らないこと

- お知らせに「引用された」を足すこと。
- ページ単位で、どのページがどのページを引用したかを見せること。
- このサービスの外の URL への引用。
- SNS の投稿のタイムライン、イベントとコミュニティの表示。試作にあったが、取り除く。形を変えて残すこともしない。
- 引用を、埋め込み(iframe)で表示すること。引用しただけで、相手のページの上で自分のスライドが動くのを避ける。

## 受け入れ条件

- **F24-AC1** スライド A の HTML が、スライド B の共有 URL(ページ番号つきも含む)へのリンクを持つとき、A を置いて公開すると、B の viewer に A が「このスライドを引用しているスライド」として出る。
- **F24-AC2** 同じとき、A の viewer に B が「このスライドが引用しているスライド」として出る。
- **F24-AC3** A が何ページで B を引用していても、B の一覧に A は 1 回だけ出る。
- **F24-AC4** 同じスライド(同じ handle と slug)へのリンクは、引用として数えない。同じ作者の別のスライドへのリンクは、数える。
- **F24-AC5** A の公開を止めると、B の viewer から A が消える。もう一度公開すると、また出る。
- **F24-AC6** 引用が 5 件以上あるとき、viewer には 4 件が出て、残りの件数が出る。
- **F24-AC7** 引用が 1 件もないとき、その節は見出しごと出ない。
- **F24-AC8** 読む人がミュートしている作者のスライド、運営が非表示にしたスライド、停止中の作者のスライドは、一覧に出ない(最近のスライドの一覧と同じ扱い)。
- **F24-AC9** A の中の B へのリンクを押すと、viewer が B の共有 URL へ移る。ページ番号つきのリンクなら、そのページから開く。
- **F24-AC10** スライドの中のリンクで viewer が移れるのは、このサービスの共有 URL だけである。ほかの URL へは移らない。
- **F24-AC11** B の作者が 1 本の管理ページを開くと、B を引用しているスライドの一覧が、件数を切らずに新しい順で出る。
- **F24-AC12** 反応の管理(`/slides/:deck/reactions`)が 404 になる。
- **F24-AC13** 公開中の版を新しい版に入れ替えると、引用は新しい版の HTML のものに変わる。なくなったリンクの引用は消える。入れ替えの操作を押すまでは、新しい版を受け取っても、viewer に出る引用は変わらない。
- **F24-AC14** viewer の引用の表示は、表紙のカードであり、引用のスライドを iframe で動かさない。
- **F24-AC15** ブラウザから置いたスライド([スライドを、ドロップして置く](f22-browser-drop.md))でも、確定のときに引用が読まれる。
- **F24-AC16** 空の D1 に migration をすべて適用した後のスキーマに、SNS の投稿とイベントのための表がない。
- **F24-AC17** B が一般公開されていない間(作者のみ、公開を止めた)は、A の viewer に B のカードが出ない。B を公開すると出る。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- 範囲は、検出、表示、スライド内のリンクでの移動の 3 つ。試作の動きを仕様にする。
- viewer での表示は、埋め込み(iframe)ではなく表紙のカードにする。カードは 4 件まで並べ、残りは件数で示す。
- 引用されたことは、1 本の管理ページの一覧で作者に見せる。お知らせの種類は足さない。
- 数えるのは、引用した側が一般公開されている間だけにする(試作と同じ)。読むのは、公開中の版の HTML である。カードを出すのは、出す相手のスライドも一般公開されている間だけにする。公開していないスライドの題名や表紙を、引用を通して見せない。ミュート、非表示、停止の扱いは、最近のスライドの一覧と同じにする。
- SNS の投稿とイベントに関わるコード、経路、テーブル、管理の画面(`/slides/:deck/reactions`)は、取り除く。引用だけを残す。本番のデータは空にしてよいので、互換のための経路や表を残さない。

## 未決事項

- 引用が 4 件を超えたときに、残りを見る画面。いまは件数だけを示す。
- F24-AC9・F24-AC10: スライドは読者の操作なしに、自分の iframe を別の共有 URL へ移動できる。その場合も viewer は移動する。読者が押したときだけ移動する形にできるかは、確かめていない。
- 引用の読み取りに失敗した版を、後から読み直す手段。
