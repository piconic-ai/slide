# F23 AI エージェントから置く

状態は実装済みです(公式の SDK のクライアントで確かめた。実際の AI エージェントからの接続は、人の確認が残る)。第二スコープで、記事の下書きと関連リンクの道具を足す(F23-AC13 から)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、AI エージェントと会話しながら HTML スライドを作る。できあがったファイルは、エージェントの作業場所にある。それをダウンロードして、ブラウザで置き場に運ぶのは、会話の流れを切る。発表のあとで、書き起こしを記事にしたり、録画のリンクを足したりするときも、同じ会話のまま頼みたい。

## 得られる結果

できたところで「置いて」と頼むと、その会話のまま slide に置かれる。エージェントはスライドの編集の URL を返し、登壇者はそこで確かめて公開する。

## 体験の流れ

1. 作者が、設定ページの MCP の URL をエージェントに登録する。初回だけ、ブラウザで接続を許可する。
2. スライドができたら、エージェントに「置いて」と頼む。
3. エージェントがファイルを渡し、スライドの編集の URL を受け取って作者に伝える。
4. 作者がそのページで表示を確かめ、「公開する」を押す。

## 作る範囲

- slide が `/mcp` で提供する MCP サーバー。接続の許可は OAuth で行う。
- 道具は 4 種類: 自分のスライドの一覧、新しく置く、新しい版に差し替える、状態を見る。
- 小さな HTML(文字のファイルの合計が 1MB まで)は、道具の引数で受け取る。それより大きいものと、画像などを含むものは、道具が送り先と一時の資格情報を返し、エージェントが HTTP で直接送る。
- 道具が返す、スライドの編集の URL と、作者だけが見られるプレビューの URL。
- 設定ページの、接続先の URL と、接続済みのエージェントの一覧・取り消し。
- 記事の下書きを置く道具と、関連リンクを足す・外す道具(第二スコープ。[発表を書き起こした記事を添える](f26-article.md)、[関連リンクを紐付ける](f27-related-links.md))。道具は、編集ページの URL を返す。

## 作らないこと

- 公開する、公開を止める、削除する、URL の名前を変える、設定を変える道具。一般公開は、人が押す操作として残す。
- 記事を公開する道具、取り下げる道具。プロフィールを書く道具。記事の公開は、作者が編集ページで押す。
- 自分のコンピューターで動かす形(stdio)の MCP サーバー、コマンドの配布。
- スライドを作る・直す道具。slide は置き場で、作るのはエージェントである。
- 読者向けの道具(検索、閲覧)。

## 受け入れ条件

- **F23-AC1** 認可していないクライアントが `/mcp` を呼ぶと、認可が要ることを示す応答が返る。道具は呼べない。
- **F23-AC2** 作者がブラウザで接続を許可すると、そのクライアントから道具の一覧が取れる。
- **F23-AC3** 道具の一覧に、公開する、公開を止める、削除する道具がない。
- **F23-AC4** 「新しく置く」に小さな HTML を渡すと、スライドができ、スライドの編集の URL と、作者だけが見られる、スライドを確かめられる URL(`previewUrl`)が返る。そのスライドは作者だけが見られる。
- **F23-AC5** 返ってきたスライドの編集の画面で「公開する」を押すと、共有 URL で見える。
- **F23-AC6** 引数で渡せる大きさを超える HTML は受け取らず、大きいもののための開始と確定を使うように伝える応答が返る。
- **F23-AC7** 開始が返した送り先に、エージェントがファイルを送って確定を呼ぶと、スライドができる。期限の切れた資格情報では送れない。
- **F23-AC8** 「差し替える」に、ほかの人のスライドを指定すると、断られる。存在するかどうかも伝わらない。
- **F23-AC9** 「差し替える」で新しい版を置いても、公開中の版は変わらない。
- **F23-AC10** 上限を超えるもの、接続を許可した後に登録から外された人の要求は断られ、理由が返る。
- **F23-AC11** 設定ページに、接続済みのエージェントが出る。取り消すと、そのエージェントの次の要求が認可エラーになる。
- **F23-AC12** 置いた HTML に、ページを伝える script が 1 つだけ入っている。
- **F23-AC13** 記事の下書きを置く道具に本文を渡すと、そのスライドの記事が下書きとして保存され、記事の編集ページの URL が返る。
- **F23-AC14** 記事の下書きを置く道具は、公開中の記事があるスライドには置かず、断る。編集ページで直すように伝える応答が返る。
- **F23-AC15** 関連リンクを足す道具で足したリンクが、スライドの編集と viewer に出る。
- **F23-AC16** 関連リンクを外す道具で外したリンクが、スライドの編集と viewer から消える。
- **F23-AC17** 上限(50,000 文字)を超える本文を渡すと、断られ、理由が返る。
- **F23-AC18** `https:` 以外の URL の関連リンクを足そうとすると、断られ、理由が返る。
- **F23-AC19** 10 件ある関連リンクに 11 件目を足そうとすると、断られ、理由が返る。
- **F23-AC20** 記事の下書きと関連リンクの道具に、ほかの人のスライドを指定すると、断られる。存在するかどうかも伝わらない。
- **F23-AC21** 道具の一覧に、記事を公開する道具、記事の公開を取り下げる道具がない。
- **F23-AC22** 記事の下書きを置く道具と、関連リンクの道具は、編集ページ(または、スライドの編集)の URL と、次に人がすることを返す。
- **F23-AC23** 道具の説明に、公開できないこと、本文の上限、ページの埋め込みの書き方(ページ番号つきの共有 URL を 1 行で書く)が書かれている。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- slide が MCP サーバーを `/mcp` で提供する。接続の許可は OAuth で行う。実装の前に、MCP の仕様と Cloudflare Workers の現行のドキュメントを読んで、やり方を決める。既存の認証(Better Auth、GitHub でのログイン)と組み合わせられないと分かったら、保留にする。
- 用意する道具は、自分のスライドの一覧、新しく置く、新しい版に差し替える、状態を見る、の 4 種類。公開する、公開を止める、削除する道具は作らない。
- 小さな HTML(文字のファイルの合計が 1MB まで)は、道具の引数で受け取る。それより大きいものと、画像などを含むものは、道具が送り先と一時の資格情報を返し、エージェントが HTTP で直接送る。受け取りは、[スライドを、ドロップして置く](f22-browser-drop.md) と同じ「開始、ファイルごとに送る、確定」の流れを使う。
- 道具は、スライドの編集の URL(`manageUrl`)と、作者だけが見られる、スライドを確かめられる URL(`previewUrl`)を返す。`manageUrl` は、スライドの編集のままにする。`previewUrl` は、作者の viewer の、その版の URL(`/@handle/slug?v=<版>`)にする(2026-11-20)。ハンドルがまだない作者には viewer がないので、`previewUrl` は `manageUrl` と同じにする。
- 招待制と上限は、ブラウザから置くときと同じにする。
- 設定ページに、接続先の URL と、接続済みのエージェントの一覧・取り消しを置く。
- ページを伝える script の 1 行は、MCP の受け口が足す。
- トークンは、ハッシュで保存する。MCP の経路は cookie を読まない。

現行の MCP の仕様(2026-07-28)と Cloudflare Workers、Better Auth の文書を読んで、次のように決めた(2026-11-20、#235)。理由と読んだ文書は [AI エージェントから置くための実装設計](../dev/f23-agent-upload.md) にある。

- MCP の経路は、公式 SDK(`@modelcontextprotocol/server`)の `createMcpHandler` で作る。現行の版の client にも、2025 年の版の client にも答える。
- OAuth の認可サーバーは、slide 自身が D1 の上に持つ。新しい binding と secret は足さない。許可の画面だけが、既存の GitHub でのログインを使う。
- client の登録は、Dynamic Client Registration で受ける。Client ID Metadata Documents は後に回す。
- 道具は `list_slides`、`put_slide`、`replace_slide`、`begin_upload`、`finish_upload`、`get_status`。大きいもののための開始と確定は、「新しく置く」と「差し替える」の両方に使う。
- 大きいものは、エージェントが byte を直接送るので、ページを伝える script の 1 行は、エージェントが入れる。道具の説明で、入れる行を伝える。入っていなくても受け取る。
- 作者だけが見られるプレビューの URL は、「プレビューを開く」のボタン 1 つの画面にする。押すと、既存の作者限定の閲覧が開く。
- 道具が断るときは、エージェントが作者に伝えられるように、理由を道具の結果として返す。

第二スコープで、次のように決めた(2026-11-22)。

- MCP に、記事の下書きを置く道具と、関連リンクを足す・外す道具を足す。記事を公開する道具、取り下げる道具は作らない。
- 記事の下書きを置く道具は、公開中の記事を上書きしない。公開中の記事があるスライドに置かれたときは、断って、編集ページで直すように伝える。
- 道具は、編集ページの URL を返す。
- MCP の接続の許可(OAuth の同意)は、ログインがメールのコードに変わったあとの session で動く。未ログインなら `/login` へ進み、戻ってきて同意の画面を出す([メールのコードでログインする](f28-email-login.md)。F28-AC30)。上の「許可の画面だけが、既存の GitHub でのログインを使う」は、これに置き換わる。
- 招待制は、メールアドレスの一覧で持つ(F22 と同じ)。
