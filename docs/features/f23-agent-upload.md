# F23 AI エージェントから置く

状態は実装済みです(公式の SDK のクライアントで確かめた。実際の AI エージェントからの接続は、人の確認が残る)。第二スコープで、記事の下書きと関連リンクの道具を足す(F23-AC13 から)。2026-11-24 に、記事の下書きを読む道具と、公開中の記事の編集中の下書きへの書き込みを足した(F23-AC25 から)。第三スコープで、関連リンクを足す道具に種類「イベント」を足した(F23-AC42〜F23-AC45。2026-11-25、issue #406。統合ブランチ `scope3` に入り、本番にはまだ反映していない)。第四スコープで、全部を書き出す道具(`export_account`、`get_slide_files`)と、接続の許可の画面の 1 行を足す(F23-AC46 から。設計は [AI エージェントからの書き出しの実装設計](../dev/f35-agent-export.md)。実装を積んでいる途中)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、AI エージェントと会話しながら HTML スライドを作る。できあがったファイルは、エージェントの作業場所にある。それをダウンロードして、ブラウザで置き場に運ぶのは、会話の流れを切る。発表のあとで、書き起こしを記事にしたり、録画のリンクを足したりするときも、同じ会話のまま頼みたい。

## 得られる結果

できたところで「置いて」と頼むと、その会話のまま slide に置かれる。エージェントはスライドの編集の URL を返し、登壇者はそこで確かめて公開する。

## 体験の流れ

1. 作者が、設定ページの MCP の URL をエージェントに登録する。初回だけ、ブラウザで接続を許可する。
2. スライドができたら、エージェントに「置いて」と頼む。
3. エージェントがファイルを渡し、スライドの編集の URL を受け取って作者に伝える。
4. 作者がそのページで表示を確かめ、「公開する」を押す。

## 作る範囲

- slide が `/mcp` で提供する MCP サーバー。接続の許可は OAuth で行う。
- 道具は 4 種類: 自分のスライドの一覧、新しく置く、新しい版に差し替える、状態を見る。
- 小さな HTML(文字のファイルの合計が 1MB まで)は、道具の引数で受け取る。それより大きいものと、画像などを含むものは、道具が送り先と一時の資格情報を返し、エージェントが HTTP で直接送る。
- 道具が返す、スライドの編集の URL と、作者だけが見られるプレビューの URL。
- 設定ページの、接続先の URL と、接続済みのエージェントの一覧・取り消し。
- 記事の下書きを読む道具と書く道具、関連リンクを足す・外す道具(第二スコープ。[発表を書き起こした記事を添える](f26-article.md)、[関連リンクを紐付ける](f27-related-links.md))。書く道具は、記事がなければ下書きの記事を作り、下書きの記事なら本文を置き換え、公開中の記事なら作者の編集中の下書きに書く。道具は、編集ページの URL を返す。
- 書き出しの道具 `export_account`(アカウントの情報と、すべてのスライドの一覧)と `get_slide_files`(1 本のスライドの、版ごとのファイルの一覧と、取り出すための URL)(第四スコープ。[データを書き出す](f35-data-export.md))。接続の許可の画面の、「自分のスライドと記事を読み、取り出す」の 1 行。

## 作らないこと

- 公開する、公開を止める、削除する、URL の名前を変える、設定を変える道具。一般公開は、人が押す操作として残す。
- 記事を公開する道具、取り下げる道具。プロフィールを書く道具。記事の公開は、作者が編集ページで押す。
- 自分のコンピューターで動かす形(stdio)の MCP サーバー、コマンドの配布。
- スライドを作る・直す道具。slide は置き場で、作るのはエージェントである。
- 読者向けの道具(検索、閲覧)。
- 書き出しのための、zip を返す道具、ファイルの中身を道具の応答に入れること、他人のスライドを読む道具、書き出したものを取り込む道具(第四スコープ)。

## 受け入れ条件

- **F23-AC1** 認可していないクライアントが `/mcp` を呼ぶと、認可が要ることを示す応答が返る。道具は呼べない。
- **F23-AC2** 作者がブラウザで接続を許可すると、そのクライアントから道具の一覧が取れる。
- **F23-AC3** 道具の一覧に、公開する、公開を止める、削除する道具がない。
- **F23-AC4** 「新しく置く」に小さな HTML を渡すと、スライドができ、スライドの編集の URL と、作者だけが見られる、スライドを確かめられる URL(`previewUrl`)が返る。そのスライドは作者だけが見られる。
- **F23-AC5** 返ってきたスライドの編集の画面で「公開する」を押すと、共有 URL で見える。
- **F23-AC6** 引数で渡せる大きさを超える HTML は受け取らず、大きいもののための開始と確定を使うように伝える応答が返る。
- **F23-AC7** 開始が返した送り先に、エージェントがファイルを送って確定を呼ぶと、スライドができる。期限の切れた資格情報では送れない。

- **F23-AC10** 上限を超えるもの、接続を許可した後に登録から外された人の要求は断られ、理由が返る。
- **F23-AC11** 設定ページに、接続済みのエージェントが出る。取り消すと、そのエージェントの次の要求が認可エラーになる。
- **F23-AC12** 削除。(ページを伝える script は、サービスが配るときに版のトップへ差し込むことにし、受け口もエージェントも足さなくなった。F23-AC24 で書き直した)

- **F23-AC14** 削除。(理由: 2026-11-24 の依頼者の決定。公開中の記事は断らず、作者の編集中の下書きに書く。読者に見えるものは変えず、読んだときの revision と合わなければ断る。F23-AC31 から F23-AC36 で書き直した)
- **F23-AC15** 関連リンクを足す道具で足したリンクが、スライドの編集と viewer に出る。
- **F23-AC16** 関連リンクを外す道具で外したリンクが、スライドの編集と viewer から消える。
- **F23-AC17** 上限(50,000 文字)を超える本文を渡すと、断られ、理由が返る。
- **F23-AC18** `https:` 以外の URL の関連リンクを足そうとすると、断られ、理由が返る。
- **F23-AC19** 10 件ある関連リンクに 11 件目を足そうとすると、断られ、理由が返る。
- **F23-AC20** 記事の下書きと関連リンクの道具に、ほかの人のスライドを指定すると、断られる。存在するかどうかも伝わらない。
- **F23-AC21** 道具の一覧に、記事を公開する道具、記事の公開を取り下げる道具がない。
- **F23-AC22** 記事の下書きを置く道具と、関連リンクの道具は、編集ページ(または、スライドの編集)の URL と、次に人がすることを返す。
- **F23-AC23** 道具の説明に、公開できないこと、本文の上限、ページの埋め込みの書き方(ページ番号つきの共有 URL を 1 行で書く)が書かれている。
- **F23-AC24** 道具の引数で置いた HTML は、渡したときの byte のまま置かれ、ページを伝える script の 1 行は足されない。道具の説明と応答は、エージェントにその 1 行を入れるよう求めない(サービスが配るときに差し込む。F03-AC143)。
- **F23-AC25** 記事の下書きを読む道具に、記事のないスライドを渡すと、記事がないことと、書くと新しい下書きの記事として作られることが返る。
- **F23-AC26** 記事の下書きを読む道具に、下書きの記事のあるスライドを渡すと、下書きの本文が返る。
- **F23-AC27** 記事の下書きを読む道具に、公開中の記事のあるスライドを渡すと、作者の編集中の下書きがあればその本文が、なければ公開中の本文が返る。
- **F23-AC28** 記事の下書きを読む道具は、本文とともに、状態(下書き、公開中、公開中で未反映の変更あり)、revision、記事の編集ページの URL を返す。読んでも記事は変わらない。
- **F23-AC29** 記事のないスライドに、記事の下書きを書く道具で revision を添えずに本文を渡すと、その本文の下書きの記事が作られる。
- **F23-AC30** 下書きの記事のあるスライドに、読んだときの revision を添えて本文を渡すと、下書きの本文が置き換わる。
- **F23-AC31** 公開中の記事のあるスライドに、読んだときの revision を添えて本文を渡すと、その本文が作者の編集中の下書きに入る。作者が記事の編集ページを開くと、入力欄にその本文があり、状態は「未反映の変更あり」になる。
- **F23-AC32** 公開中の記事に書く道具で書いても、作者が「公開記事を更新」を押すまで、読者の viewer、引用、プロフィールの一覧と数は変わらない。
- **F23-AC33** 公開中の記事に、公開中の本文と同じ本文を書くと、未反映の変更はなくなる(状態は「公開中」)。
- **F23-AC34** 記事のあるスライドに、revision を添えずに書こうとすると、断られ、読む道具で読んでから書くように伝える応答が返る。記事は変わらない。
- **F23-AC35** 読んだ後に作者や別のエージェントが記事を保存していて、添えた revision が記事の revision と違うと、書かずに断られ、読む道具で読み直すように伝える応答が返る。道具の確認と書き込みの間に保存されたときも、上書きしない。
- **F23-AC36** 書く道具で書くと revision が進み、書く前から開いていた記事の編集ページは、他で更新されたことを知らせて自動保存を止める(F26-AC88)。エージェントが書いた本文は残る。
- **F23-AC37** 書く道具は、新しい revision、状態、記事の編集ページの URL、次に人がすること(下書きなら、確かめて公開する。公開中なら、編集ページで確かめて「公開記事を更新」を押す)を返す。
- **F23-AC38** 記事の道具の説明に、書く前に読むこと、読んだ revision を添えること、公開中の記事に書いたものは編集中の下書きに入り読者には見えないことが書かれている。
- **F23-AC39** 関連リンクを足す道具(`add_related_link`)で、そのスライドの関連リンクのどれかと、正規化した形が同じ URL を足そうとすると、断られ、すでに同じ URL があることを伝える理由が返る。関連リンクは増えない([関連リンクを紐付ける](f27-related-links.md) の F27-AC44 と同じ判定)。
- **F23-AC40** 関連リンクが 10 件あるスライドに、関連リンクを足す道具で、そのどれかと正規化した形が同じ URL を足そうとすると、上限の理由(F23-AC19)ではなく、すでに同じ URL があることを伝える理由が返る。
- **F23-AC41** 関連リンクを足す道具に、ユーザー名やパスワードを含む URL を渡すと、断られ、理由が返る([関連リンクを紐付ける](f27-related-links.md) の F27-AC50 と同じ判定)。
- **F23-AC42** 関連リンクを足す道具(`add_related_link`)の `kind` に `event` を選べる。`kind` を省いてイベントの URL を渡すと、種類が「イベント」になる([イベントの発表として並ぶ](f29-event-talks.md) の F29-AC1〜F29-AC3)。
- **F23-AC43** 道具で種類「イベント」の関連リンクを足した一般公開中のスライドは、そのイベントのページに並ぶ。
- **F23-AC44** 道具の一覧に、コミュニティやイベントを作る・直す道具、ブロックの道具が無い。
- **F23-AC45** 関連リンクを足す道具の説明に、イベントのページの URL を入れるとイベントの発表として並ぶことが書かれている。
- **F23-AC46** 接続の許可の画面に、許す操作として「自分のスライドと記事を読み、取り出す」が出る。
- **F23-AC47** 第四スコープの変更より前につないだ接続は、`export_account` と `get_slide_files` を使えない。使おうとすると、つなぎ直すように答えが返る。答えの文は、エージェントが利用者にそのまま伝えられる文である。
- **F23-AC48** 第四スコープの変更より前につないだ接続でも、前からある道具は、今までどおり使える。
- **F23-AC49** 利用を止められている人の接続は、`export_account` と `get_slide_files` を使えない。
- **F23-AC50** 道具の説明に、全部を書き出すときの順番(`export_account`、`list_slides`、スライドごとに `get_slide_files` と `get_article_draft`)が書かれている。
- **F23-AC51** 道具の一覧に、zip を返す道具と、他人のスライドを読む道具が無い。

## 決めたこと

第一スコープを作るにあたり、次のように決めた(2026-11-19)。

- slide が MCP サーバーを `/mcp` で提供する。接続の許可は OAuth で行う。実装の前に、MCP の仕様と Cloudflare Workers の現行のドキュメントを読んで、やり方を決める。既存の認証(Better Auth、GitHub でのログイン)と組み合わせられないと分かったら、保留にする。
- 用意する道具は、自分のスライドの一覧、新しく置く、新しい版に差し替える、状態を見る、の 4 種類。公開する、公開を止める、削除する道具は作らない。
- 小さな HTML(文字のファイルの合計が 1MB まで)は、道具の引数で受け取る。それより大きいものと、画像などを含むものは、道具が送り先と一時の資格情報を返し、エージェントが HTTP で直接送る。受け取りは、[スライドを、ドロップして置く](f22-browser-drop.md) と同じ「開始、ファイルごとに送る、確定」の流れを使う。
- 道具は、スライドの編集の URL(`manageUrl`)と、作者だけが見られる、スライドを確かめられる URL(`previewUrl`)を返す。`manageUrl` は、スライドの編集のままにする。`previewUrl` は、作者の viewer の、その版の URL(`/@handle/slug?v=<版>`)にする(2026-11-20)。ハンドルがまだない作者には viewer がないので、`previewUrl` は `manageUrl` と同じにする。
- 招待制と上限は、ブラウザから置くときと同じにする。
- 設定ページに、接続先の URL と、接続済みのエージェントの一覧・取り消しを置く。
- ページを伝える script の 1 行は、MCP の受け口が足す。(2026-11-24 に変えた。サービスが配るときに差し込むので、受け口は足さない。下の「大きいもの」も同じ)
- トークンは、ハッシュで保存する。MCP の経路は cookie を読まない。

現行の MCP の仕様(2026-07-28)と Cloudflare Workers、Better Auth の文書を読んで、次のように決めた(2026-11-20、#235)。理由と読んだ文書は [AI エージェントから置くための実装設計](../dev/f23-agent-upload.md) にある。

- MCP の経路は、公式 SDK(`@modelcontextprotocol/server`)の `createMcpHandler` で作る。現行の版の client にも、2025 年の版の client にも答える。
- OAuth の認可サーバーは、slide 自身が D1 の上に持つ。新しい binding と secret は足さない。許可の画面だけが、既存の GitHub でのログインを使う。
- client の登録は、Dynamic Client Registration で受ける。Client ID Metadata Documents は後に回す。
- 道具は `list_slides`、`put_slide`、`replace_slide`、`begin_upload`、`finish_upload`、`get_status`。大きいもののための開始と確定は、「新しく置く」と「差し替える」の両方に使う。
- 大きいものは、エージェントが byte を直接送るので、ページを伝える script の 1 行は、エージェントが入れる。道具の説明で、入れる行を伝える。入っていなくても受け取る。(2026-11-24 に変えた。エージェントに入れるよう求めない。サービスが配るときに、版のトップの `index.html` へ差し込む。[URL を渡して読んでもらう](f03-sharing.md)の「決めたこと」)
- 作者だけが見られるプレビューの URL は、「プレビューを開く」のボタン 1 つの画面にする。押すと、既存の作者限定の閲覧が開く。
- 道具が断るときは、エージェントが作者に伝えられるように、理由を道具の結果として返す。

第二スコープで、次のように決めた(2026-11-22)。

- MCP に、記事の下書きを置く道具と、関連リンクを足す・外す道具を足す。記事を公開する道具、取り下げる道具は作らない。
- 記事の下書きを置く道具は、公開中の記事を上書きしない。公開中の記事があるスライドに置かれたときは、断って、編集ページで直すように伝える。(2026-11-24 に変えた。下の「記事の道具は、編集中の下書きを読み書きする」)
- 道具は、編集ページの URL を返す。
- MCP の接続の許可(OAuth の同意)は、ログインがメールのコードに変わったあとの session で動く。未ログインなら `/login` へ進み、戻ってきて同意の画面を出す([メールのコードでログインする](f28-email-login.md)。F28-AC30)。上の「許可の画面だけが、既存の GitHub でのログインを使う」は、これに置き換わる。
- 招待制は、メールアドレスの一覧で持つ(F22 と同じ)。

記事の道具は、編集中の下書きを読み書きする(2026-11-24、依頼者の決定。#366 の試用で、公開中の記事を直そうとしたエージェントが断られた)。

- MCP は、これまでどおり記事を公開できない。公開する、公開を更新する、公開を止める道具は作らない(F23-AC21)。
- 下書きの参照・追加・編集はできてよい。記事の下書きを読む道具(`get_article_draft`)を足す。返すのは、編集ページが開くのと同じ本文(下書きの本文、公開中なら編集中の下書き、なければ公開中の本文)、状態、revision、編集ページの URL。
- 書く道具(`put_article_draft`)は、公開中の記事では作者の編集中の下書きに書く。作者の書きかけがあるなら、それを読んで編集すればよい。状態の決まりは、編集ページの自動保存と同じものを使う(公開中の本文と同じ本文なら、未反映の変更をなくす)。読者に見えるのは、作者が「公開記事を更新」を押した後である。
- 記事があるときは、読んだときの revision を必須にし、記事の revision と違えば書かずに断る。比較は書く文の条件に含め、確認と書き込みの間に保存されても上書きしない。編集ページの自動保存と同じ revision を進めるので、開いている編集ページは古さを検知する(F26-AC88)。
- 採らなかった案: (a) これまでどおり公開中の記事は断る(エージェントが公開中の記事の直しを手伝えない)。(b) 作者の書きかけ(編集中の下書き)があるときだけ断る(書きかけを読んで直したいのに断られ、書きかけがないときは revision の確認なしに書くので、作者の入力と競合する)。(c) revision なしで常に置き換える(作者や別のエージェントが読んだ後に保存したものを、黙って上書きする)。

第三スコープで、次のように決めた(2026-11-23、第三スコープの指示書)。

- 関連リンクを足す道具で、種類「イベント」を選べるようにする。コミュニティやイベントを作る・直す道具は足さない(D-75)。

関連リンクを足す道具は、すでにある URL を断る(2026-11-25、依頼者。issue #366 の D10)。ブラウザの「関連リンク」と同じ判定を使い、上限に達していても重複の理由を返す(F23-AC39、F23-AC40。[関連リンクを紐付ける](f27-related-links.md) の「決めたこと」)。

第四スコープで、次のように決めた(2026-11-26、第四スコープの指示書。D-37〜D-39。道具の入出力と、取り出すための URL の守りは [データを書き出す](f35-data-export.md) の F35-AC32〜F35-AC42)。

- 道具を 2 つ足す。`export_account`(アカウントの情報と、すべてのスライドの一覧)と `get_slide_files`(1 本のスライドの、版ごとのファイルのパス、大きさ、SHA-256 と、ファイルを取り出すための URL)。記事を読む道具(`get_article_draft`)はすでにあるので、新しく作らない。書き出しに足りない項目(公開中の本文、関連リンク)があれば足す。
- 接続の許可の画面に、「自分のスライドと記事を読み、取り出す」ことを足す。この変更より前につないだ接続は、つなぎ直すまで、足した 2 つの道具を使えない。使おうとしたときは、つなぎ直すように答える。
- 取り出すための URL は、発行から 1 時間だけ有効で、その接続の本人のファイルだけを返す。ファイルの中身は、道具の応答に入れない。
- 範囲は、接続の行に持つ(`slides:upload`、`slides:export`)。許可の画面で許すと、画面に並べたすべてを許す。この変更より前につないだ接続は「置く」の範囲だけで、足した道具は `reconnect_required` と、つなぎ直す手順の文で断る(作業 G の設計、2026-11-26)。
- この変更は、セキュリティの観点のレビューを 1 回受ける(他人のデータが出ないこと、取り出すための URL)。
