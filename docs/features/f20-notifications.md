# F20 知りたい出来事が、お知らせに届く

状態は実装済みです。第三スコープで、ブロックしている人の引用のお知らせを届けないこと(F20-AC13)と、フォローしているコミュニティに新しいスライドが入ったお知らせ(F20-AC15〜AC18。2026-11-26、依頼者が「コミュニティのお知らせは作らない」を改めた)を足した。統合ブランチ `scope3` に入り、本番にはまだ反映していない。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

作者が、自分のスライドがほかの人のスライドに引用されたことを、知らないままでいる。フォローしている人が新しいスライドを公開したことや、フォローしているコミュニティに新しいスライドが入ったことを、知らないままでいる。どれも、知っていれば読みに行く。

## 得られる結果

利用者は、slide を開いたときに、自分に関わる出来事を知る。知らせから、そのスライドや人のページへ行ける。受け取る知らせは、種類ごとに自分で選べる。

## 体験の流れ

1. 利用者がログインして、管理画面を開く。未読のお知らせの数が出ている。
2. お知らせの一覧を開く。「@name さんのスライドが、あなたのスライドを引用しました」「@name さんが、新しいスライドを公開しました」「「(コミュニティ名)」に、@name さんのスライド「…」が入りました」が、新しい順に並ぶ。
3. 知らせを押して、そのスライドや、その人のプロフィールを開く。
4. 要らない種類の知らせは、設定のページで受け取らないようにする。

## 作る範囲

- お知らせの保存と、お知らせの一覧のページ。
- 管理画面に出す、未読の数。
- 知らせの種類: 自分のスライドが引用された。slide でフォローしている人が、スライドを公開した。slide でフォローされた(あとの 2 つは、[気になる人を、フォローする](f21-follow.md) ができてから)。フォローしているコミュニティに、新しいスライドが入った([コミュニティをフォローする](f31-community-follow.md))。「GitHub でフォローしている人が、slide を使い始めた」は、第二スコープで取り除いた(F20-AC4)。
- 設定のページの、種類ごとの受け取りの切り替え。

## 作らないこと

- メールでの知らせ。送る仕組みと、止める手段をそろえる必要があり、いまの規模には重すぎる。
- ブラウザの push 通知。
- X や Bluesky の投稿があったことの知らせ。投稿は、作者が自分で載せるもので、「反応があった」という出来事を slide は知らない。
- GitHub の情報を前提にしたお知らせ。第二スコープで、GitHub でのログインをやめた([メールのコードでログインする](f28-email-login.md))。
- 運営からの知らせ(通報の結果、非表示、停止)。非表示と停止は、管理画面に出している([知らない人のスライドも、安心して開ける](f17-safe-viewing.md))。

## 受け入れ条件

- **F20-AC1** ログインした人は、お知らせの一覧のページを開ける。お知らせは、新しい順に並び、それぞれから、関わるスライドや人のページへ行ける。
- **F20-AC2** 管理画面に、未読のお知らせの数が出る。お知らせの一覧を開くと、未読の数は 0 になる。
- **F20-AC3** 自分のスライドの共有 URL へのリンクを含む、ほかの人のスライドが一般公開されると、「引用された」というお知らせが届く。同じスライドの版が更新されても、同じ引用のお知らせは増えない。自分のスライドを自分で引用したときは、届かない。
- **F20-AC4** 削除。(GitHub でのログインと、GitHub のフォローの関係の読み取りをやめた。F28 の GitHub の取り除きで、お知らせの種類ごと無くなる(F28-AC28))
- **F20-AC5** slide でフォローしている人が、スライドを初めて一般公開すると、お知らせが届く。そのスライドの版が更新されても、届かない。
- **F20-AC6** slide でだれかにフォローされると、お知らせが届く。同じ人が、解除してもう一度フォローしても、お知らせは増えない。
- **F20-AC7** 設定のページで、お知らせの種類ごとに、受け取るかどうかを選べる。既定は、すべて受け取る。受け取らないにした種類のお知らせは、届かない。
- **F20-AC8** ミュートしている人についてのお知らせは、届かない([見たくない作者を、一覧から外す](f19-mute.md))。
- **F20-AC9** お知らせは、本人にしか見えない。ほかの人のお知らせの一覧と、未読の数は、読めない。
- **F20-AC10** 運営が非表示にしたスライドと、停止中のアカウントについてのお知らせは、一覧に出ない。
- **F20-AC11** 退会すると、その人のお知らせと、その人についてのお知らせが消える。
- **F20-AC12** お知らせの画面に、「スライドの管理に戻る」のリンクがない。理由: 画面の上のメニューから行けるので重なり、お知らせを読み終えた後の行き先は、人によって違うため(依頼者の指摘、2026-11-21)。画面に残るのは、お知らせの一覧と、受け取るお知らせを選ぶリンクだけである。
- **F20-AC13** ブロックしている人が自分のスライドを引用しても、お知らせは届かない([人をブロックする](f32-block.md))。
- **F20-AC14** 削除。(コミュニティのお知らせは作らない、と決めていたが、依頼者が改めた(2026-11-26)。新しいスライドが入ったことは F20-AC15〜AC18 で書き直した。コミュニティがフォローされても届かないことは、F31-AC19 に移した)
- **F20-AC15** コミュニティをフォローしている人は、そのコミュニティに入るスライドが初めて一般公開されると、お知らせが届く。ブロックでつながる相手(どちらかがもう一方をブロックしている)、ミュートしている相手、受け取らない設定にしている人には届かない。お知らせを押すと、そのスライドが開く。「入る」は、コミュニティの紐づけ用リンクに合うイベントの関連リンクを、スライドが持つことである([コミュニティをつくる](f30-communities.md))。
- **F20-AC16** 一般公開中のスライドに、イベントの関連リンクを足す(または、別の種類のリンクをイベントに変える)と、それでコミュニティに入るなら、フォローしている人にお知らせが届く。ただし、スライドを初めて一般公開してから 7 日以内に限る(ちょうど 7 日は届き、7 日と 1 秒は届かない。日数は `COMMUNITY_NOTICE_WINDOW_SECONDS`)。下書きのスライドと、一時停止中のスライドでは、届かない。
- **F20-AC17** お知らせは、1 人につき 1 つのスライドで 1 件である。版の更新、公開の一時停止と再開、関連リンクの付け直し、複数のコミュニティに入っていること、スライドの作者を人としてもフォローしていること(その知らせとあわせて 1 件)でも、増えない。コミュニティの名前は、その人が最初にフォローしたものを添える。
- **F20-AC18** 自分のスライドが入ったときは、届かない。コミュニティの管理者が紐づけ用リンクを足して過去のスライドが入ったときと、フォローしたときは、届かない。
- **F20-AC19** 読んで 30 日が過ぎたお知らせと、読まないまま届いて 90 日が過ぎたお知らせは、種類を問わず消える(ちょうど 30 日、90 日は残る。日数は `READ_RETENTION_SECONDS`、`UNREAD_RETENTION_SECONDS`)。消すのは毎時の定期処理で、ほかの人のお知らせには触れない。消えるまでに最大 1 時間かかり、その間は一覧と未読数に出る。

## 決めたこと

次のように決めた(2026-11-18)。

- 知らせは、slide の中のお知らせで届ける。メールは送らない。
- お知らせの仕組みは、いま作る。
- 引用されたことの知らせを、最初から載せる。引用は、いまある機能で、登録した人のあいだでも起きるので、お知らせが届くことを本番で確かめられるためである。
- どの知らせを受け取るかは、設定のページで、種類ごとに選べる。既定は、すべて受け取る。
- (2026-11-22)「GitHub でフォローしている人が、slide を使い始めた」知らせは、取り除く。GitHub でのログインをやめ、GitHub のフォローの関係を読まないため。種類、設定、文言、表の値も取り除く。これに伴い、2026-11-18 の決定のうち、GitHub のフォローに関わるものは、無くなった。

第三スコープで、次のように決めた(2026-11-23、第三スコープの指示書)。

- ブロックした相手が書いた引用は、お知らせに届けない(D-71)。コミュニティについてのお知らせは足さない(D-54。下のとおり、2026-11-26 に改めた)。

フォローしているコミュニティのお知らせについて、次のように決めた(2026-11-26、依頼者の決定)。D-54 の「お知らせは足さない」のうち、コミュニティに新しいスライドが入ったことを知らせる部分を改めた。

- 新しいスライドが入ったことは、お知らせで知らせる。契機は 2 つ。スライドの初めての一般公開(F20-AC15)と、一般公開中のスライドへのイベントの関連リンクの追加(F20-AC16)。版の更新、一時停止からの再開、取り消し後の再公開では知らせない。
- コミュニティの管理者が紐づけ用リンクを足したことと、Luma のカレンダーの取り込みで、過去のスライドがコミュニティに入っても、知らせない(F20-AC18)。
- 1 人につき 1 つのスライドで 1 件(F20-AC17)。受け取りの種類は 1 つ足し、既定は受け取る。コミュニティごとの受け取りの切り替えはない。
- コミュニティがフォローされたことは、知らせない(F31-AC19)。管理者は、自分のコミュニティのフォロワーを、お知らせでは知らない。
- メールでの知らせは作らない(D-90)。

次のように決めた(2026-11-26、依頼者の決定)。

- F20-AC16: ずっと前に公開したスライドに、あとからリンクを足しても知らせない。対象は、初めて一般公開してから 7 日以内のスライドだけ(7 日は依頼者の案)。
- F20-AC17: 人のフォローのお知らせを止めている人にも、コミュニティの 1 件は届ける。
- F20-AC17: 複数のコミュニティに入るときに添える名前は、その人が最初にフォローしたもの。
- F20-AC19: お知らせは、読んで 30 日、未読のまま 90 日で消す。種類は問わない(日数は依頼者の案)。依頼者が、お知らせを積極的に廃棄する意向を示したので、これまで「いつまで残すか」を未決にしていたのをやめ、この数字で決める。プライバシーポリシー(#65)に書く期間は、そちらで最終確認する。
- migration 0060 は、表を消して作り直す(いまの利用者が依頼者 1 人のため、いまあるお知らせは消えてよい)。
