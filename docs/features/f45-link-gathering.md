# F45 同じリンクでスライドが集まる

状態は設計中です(未決事項が残る。新しい条件は、どれも未実装)。2026-11-27 の実装の相談で、F45-AC7 と F45-AC28 を F45-AC31〜F45-AC36 に書き直した。2026-11-28 に、レビューの指摘を受けて、F45-AC37、F45-AC38 を足した。2026-11-27 に、依頼者との相談で、イベントという括りをやめ、リンクによる集約に一本化すると決めた。[イベントの発表として並ぶ](f29-event-talks.md) のページの見せ方を、この文書が置き換える(置き換える条件の「削除」への書き換えは、続く別の PR で行う)。相談のページ: https://claude.ai/artifact/6R852hRvSHyzKKax8piv8R。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会に出られなかった人が、同じ回の発表をまとめて見たい。同じ録画、同じ補足の記事、同じリポジトリを添えたスライドを、まとめて見たい人もいる。発表者は、すでにスライドの関連リンク([関連リンクを紐付ける](f27-related-links.md))に URL を入れている。それだけで、同じ URL を添えたスライドが 1 つのページに並んでほしい。主催者は、何も登録したくない。

URL から探す人もいる。録画や記事の URL を知っていて、それを添えたスライドを見たい。

HTML のスライドは、リンクでつながる。スライドの中のリンクで、ほかのスライドを引く引用([引用でつながる](f24-citations.md))も、その一つである。この文書が扱うのは、関連リンクによる集約である。

## 得られる結果

作者がスライドの関連リンクに URL を入れると、同じ URL を添えた、ほかの作者のスライドと一緒に、`/link/<URL>` の 1 つのページに並ぶ。URL の前に `slide.community/link/` を付ければ、だれでもそのページを開ける。

イベントの URL(connpass、Doorkeeper、Luma)と、コミュニティ([コミュニティをつくる](f30-communities.md))の紐づけ用リンクに合うリンクは、特別に扱う。スライドが 1 本でもページがあり、コミュニティのページの「リンク」のタブにも並ぶ。

主催者も作者も、何も登録しない。サービスは、リンク先を取りに行かない。

## 体験の流れ

1. 作者 A が、スライド 1 の関連リンクに URL を入れる。作者 B が、スライド 2 の関連リンクに、同じ URL を入れる。書き方が違っても(`www.` の有無、末尾の `/`、追跡用のクエリなど)、同じ URL とみなされる。
2. 2 本とも一般公開されると、`/link/<URL>` に、2 本が公開の新しい順に並ぶ。
3. viewer の関連リンクの行から、そのリンクのページへ進める。
4. イベントの URL なら、スライドが 1 本でもページがある。コミュニティの紐づけ用リンクに合うリンクも、1 本でもページがあり、そのコミュニティの「リンク」のタブに並ぶ。
5. まだ集まっていない URL で、ページを開くと、「この URL の集まりは、まだありません」と、自分のスライドの関連リンクに足せば集まることの案内が出る。
6. 外したいときは、関連リンクを消す。

## 作る範囲

- リンクのページ `/link/<URL>`。書き方の違う URL を、正規の形へ転送すること。`/events/:id` から、`/link/…` への転送。
- 集める鍵(下の「決めたこと」)と、ページを出す条件(2 人以上の作者、イベントの形のリンク、コミュニティに入ったリンク)。
- ページの見出し、頭、スライドの並び。集まりの無い URL のためのページ。
- viewer の関連リンクの行から、ページへ進むリンク。
- イベントの形のリンクのページの「このグループのコミュニティはまだありません」と「作る」。
- いまあるイベント名を、ページの見出しとして引き継ぐこと。
- ヘルプの記事。
- ほかの文書で変えるもの: コミュニティのタブとページの照らし方([コミュニティをつくる](f30-communities.md))、1 本の管理の関連リンクの文と枠([イベントの発表として並ぶ](f29-event-talks.md))、お知らせの契機([知りたい出来事が、お知らせに届く](f20-notifications.md))。

## 作らないこと

- ページの単位の紐づけの登録と、前方一致の「所有 URL」。コミュニティの紐づけ用リンクは、いまのホスト名の一致のままにする。主催者に、回ごとの作業をさせないためである。
- ページの見出しを直す機能。管理者と運営が、いまイベント名を直せる画面と経路は、なくす。複雑にしないためである。
- スライドと記事の本文の中の、外部の URL へのリンクを集約に数えること。作者が触れただけのリンクで、意図せずほかの人のスライドと並ぶのを避けるためである。数える元は、関連リンクだけ(スライドへのリンクは、引用が本文を数える)。現時点の結論である。
- viewer の下に、イベントの形でないリンクの集まりを並べること。viewer の下の「ほかの発表」は、イベントの形のリンクだけ、いまのまま出す。ほかのリンクは、関連リンクの行から、ページへ進む。
- コミュニティのページとイベントのページをまとめること。イベントのページという見せ方が、この文書でなくなるため、まとめる相手がない。
- リンク先を取りに行くこと。イベント名、日時、場所、OGP を含め、取り込まない(connpass の利用規約が、API 以外の方法でのアクセスを禁じているため。例外は、[Luma の配信でコミュニティに紐づける](f33-luma-feeds.md) の iCal 配信だけ)。

## 受け入れ条件

- **F45-AC1** 2 人以上の作者の、一般公開中のスライドが、集める鍵の同じ関連リンクを持つと、そのリンクのページ `/link/<URL>` に、それらのスライドが一般公開の新しい順に並ぶ。
- **F45-AC2** 1 人の作者のスライドだけが持つリンク(イベントの形でなく、コミュニティにも入らないもの)の `/link/<URL>` は、スライドも本数も出さず、F45-AC12 のページになる。だれも入れていない URL と、応答は同じである。
- **F45-AC3** イベントの形のリンクは、一般公開中のスライドが 1 本でもあれば、`/link/<URL>` にそのスライドが並ぶ。イベントの形のリンクは、[イベントの発表として並ぶ](f29-event-talks.md) の F29-AC1〜F29-AC3 の URL と、種類を「イベント」にしたリンク(F29-AC28)である。
- **F45-AC4** コミュニティに入ったリンク([コミュニティをつくる](f30-communities.md) の紐づけ用リンクに合うもの)は、一般公開中のスライドが 1 本でもあれば、`/link/<URL>` にそのスライドが並ぶ。
- **F45-AC5** YouTube の開始時刻 `t`、ニコニコ動画の開始位置 `from` だけが違う URL を添えたスライドは、同じページに並ぶ。
- **F45-AC6** イベントの形のリンクは、イベントの鍵で集まる。クエリ、フラグメント、末尾の `/`、ホスト名の大文字小文字、`http` と `https`、`lu.ma` と `luma.com`、connpass のグループの有無が違っても、同じページに並ぶ。
- **F45-AC7** 削除。(2026-11-27 に、実装の相談で、ブラウザーが `#` から後ろをサーバーに送らないと分かり、転送の条件を分けた。F45-AC31、F45-AC32 で書き直した)
- **F45-AC8** `/link/<URL>` の URL のクエリ(`?` から後ろ)は、サービスのクエリではなく、リンク先の URL のクエリとして読まれる。
- **F45-AC9** `/events/:id` を開くと、そのイベントの `/link/…` へ、301 で転送される。無い番号と、一般公開中のスライドが 1 本もないイベントは、404 になる。
- **F45-AC10** ページの見出しは、そのリンクの題名のうち、一般公開中のスライドのリンクの、最初に保存されたものである。題名が 1 つもなければ、サイト名と URL である。
- **F45-AC11** いまあるイベント名(運営や管理者が直した名前を含む)は、移したあとも、そのイベントのページの見出しに出る。
- **F45-AC12** 集まりの無い URL(F45-AC1、F45-AC3、F45-AC4 のどれも満たさない URL)の `/link/…` は、404 の応答で、「この URL の集まりは、まだありません」と、関連リンクに足せば集まることの案内を出す。
- **F45-AC13** `https:` と `http:` 以外の URL、ユーザー名やパスワードを含む URL、URL として読めないものの `/link/…` は、その URL を画面に出さない 404 になる。判定は、この条件、F45-AC7 の転送、ページか F45-AC12 か、の順で行う。
- **F45-AC14** 作者のみ限定公開、非公開、取り下げ、運営が非表示にしたスライドと、停止中の作者のスライドは、ページに出ず、F45-AC1 の人数にも、「スライド n 本」にも数えない。
- **F45-AC15** ログイン中の人が見るページに、その人がブロックしている人のスライドは出ず、「スライド n 本」にも入らない。ページが出るかどうかは、見る人によらない。
- **F45-AC16** ページの頭に、見出し、元のページへのリンク、「スライド n 本」が出る。元のページへのリンクは、サイト名を入れた文(「connpass で見る」「example.com で見る」)で、`rel="noopener nofollow ugc"` が付く。日時と場所は出ない。
- **F45-AC17** コミュニティに入ったリンクのページの頭に、そのコミュニティのカバー画像、ロゴ、名前(コミュニティのページへのリンク)が出る。コミュニティに入っていないリンクのページには、出ない。
- **F45-AC18** viewer の関連リンクの行のうち、ページが出ているリンクには、そのページへ進むリンクが添えられる。ページが出ていないリンクには、添えられない。
- **F45-AC19** ページを開いても、関連リンクを保存しても、サービスから外への通信が起きない(Luma の iCal 配信を除く)。
- **F45-AC20** リンクのページの見出しを直す画面と経路は、ない。管理者と運営にも、ない。
- **F45-AC21** 幅 375px で、リンクのページと「まだありません」のページが、横にはみ出さない。
- **F45-AC22** ヘルプに、リンクで集まることの記事がある(集まる条件、`/link/` の開き方、外し方)。日本語と英語の両方で読める。
- **F45-AC23** イベントの形でないリンクは、`www.` の有無、末尾の `/`、追跡用のクエリ、`#` から後ろだけが違っても、同じページに並ぶ。
- **F45-AC24** 関連リンクを消す、またはスライドが一般公開でなくなると、そのスライドは、そのリンクのページから外れる。ページを出す条件(F45-AC1、F45-AC3、F45-AC4)を満たさなくなったページは、F45-AC12 のページになる。
- **F45-AC25** 元のページへのリンク先は、そのリンクに結びついた一般公開中のスライドの関連リンクのうち、最初に保存されたものの整えた URL である。ただし、connpass のイベントの形のリンクは、そのリンクが書いたグループの `https://<グループ>.connpass.com/event/<番号>/`(グループは小文字)で、グループを含まないときは `https://connpass.com/event/<番号>/` である。ほかのイベントの形のリンクは、イベント自身の URL(`https`、クエリ、フラグメント、グループなし)である。最初に保存されたリンクが消されると、残りのうち最も古いものに従う。
- **F45-AC26** Luma の番号の URL(`https://luma.com/event/evt-…`)の `/link/…` は、同じイベントの名前の URL(`https://luma.com/<文字列>`)が配信にあれば、その `/link/…` へ転送される([Luma の配信でコミュニティに紐づける](f33-luma-feeds.md) の F33-AC20)。
- **F45-AC27** コミュニティに入っていないイベントの形のリンクで、そのグループのコミュニティを作れる(connpass のグループ、Doorkeeper のグループの)とき、ページに「このグループのコミュニティはまだありません」と「作る」が出る。「作る」は、紐づけ用リンクを入れた状態のコミュニティを作るページへ進む。
- **F45-AC28** 削除。(2026-11-27 に、実装の相談で、イベントの鍵で引く範囲を決めた。F45-AC35 で書き直した)
- **F45-AC29** F45-AC12 のページには、検索に載せない指示(`noindex`)が付き、入れられた URL は、リンクではなく文字で出る。
- **F45-AC30** スクリプトが動くとき、ページの元のページへのリンクを押すと、リンク先へは移らず、[関連リンクを紐付ける](f27-related-links.md) の F27-AC53 と同じ確認の画面が開く。スクリプトが動かないときは、元のページへ移る。
- **F45-AC31** 書き方の違う URL(`https://` や `http://` を付けた形、`https:/`、ホスト名の大文字小文字、`www.`、末尾の `/`、追跡用のクエリ)で `/link/…` を開くと、scheme を省いた正規の形(`/link/<ホスト名><パス>`)の `/link/…` へ、301 で転送される。
- **F45-AC32** `#` から後ろを付けて `/link/…` を開いても、ブラウザーは `#` から後ろをサーバーに送らないので、転送は起きず、`#` から後ろを除いた URL のページが出る。
- **F45-AC33** `/link/…` では、`lang` を含め、クエリはすべてリンク先の URL のクエリとして読まれ、画面の言語は変わらない。画面の言語は、cookie と `Accept-Language` で決まる。
- **F45-AC34** `/link/…` のフッターの言語の切り替えを押すと、同じリンクのページが、選んだ言語で出る。
- **F45-AC35** `/link/<URL>` は、connpass、Doorkeeper、Luma の URL を、クエリを除いて、まずイベントの鍵で引く。それ以外のサイトのイベント(道具で種類を「イベント」にした URL)は、クエリが無く、ホスト名とパスがイベントの鍵と一致するときだけ、イベントの鍵で引く。どちらにも当たらなければ、集める鍵(F45-AC23)で引く。
- **F45-AC36** `/link/…` の 200 のページは、検索に載せてよい(`noindex` を付けない)。F45-AC12 のページには、F45-AC29 のとおり付ける。
- **F45-AC37** connpass、Doorkeeper、Luma のイベントの形の URL(F29-AC1〜F29-AC3 の形)は、関連リンクの種類にかかわらず、イベントの鍵で集まる(F45-AC6)。種類を「その他」などにしても、同じイベントのページに並び、種類を「その他」にした Luma の URL も、配信の一致でコミュニティに入る([Luma の配信でコミュニティに紐づける](f33-luma-feeds.md))。
- **F45-AC38** イベントの鍵で引いたページには、同じ URL(集める鍵が同じ URL)をイベント以外の種類で添えた、一般公開中のスライドも並ぶ。同じスライドは 1 本と数え、作者の数と「スライド n 本」は、合わせたものである。

## 決めたこと

2026-11-27 に、依頼者との相談で、次のように決めた(相談のページ: https://claude.ai/artifact/6R852hRvSHyzKKax8piv8R)。論点の番号は、そのページのものである。詰めていない。論点 10 は、後の相談で論点 18 になった。

- 方針。テーマは「リンクによる集約」。イベントという括りをやめ、集まりはリンクだけで作る。引用も、リンクによる集約の一つと考える。依頼者の言葉: 「イベントという括りやめよう。リンクによる集約だけにしよう。」「引用もその一つ。HTMLの魅力の一つだから。」
- 論点 1〜4。種類を問わず、すべての関連リンクで集める。集めるときは、動画の開始時刻を無視する。集まりは、イベントのページではなく、リンクのページに出す。コミュニティは、いまの紐づけ用リンクで、種類を問わず入れる。依頼者の言葉: 「全ておすすめ案がいい。希望がすべて合致してよかった。」
- 論点 5。ページを出す条件は、2 人以上の作者(F45-AC1)。同じ人の GitHub やブログの URL が、その人のスライドの一覧になるのを避けるためである。依頼者の言葉: 「5 A」。
- 論点 6。名前を持たない案を選んだが、イベントをやめると、「リンク」のタブが URL の並びになり、どの回か読めなくなるため、論点 13 で置き換えた。依頼者の言葉: 「A or B 複雑なことをしたくない」。
- 論点 7、9。イベントのページをやめたので、なくなった。
- 論点 8。コミュニティから「イベント」を外し、リンクだけに集約する。スライド 1 → リンク A、スライド 2 → リンク A、スライド 3 → リンク B のとき、リンク A で集約されたページができる。コミュニティの紐づけ用リンクにスライドの関連リンクが合えば、コミュニティのリンクに表示される。依頼者の言葉: 「コミュニティからイベントを外し、リンクだけに集約。」
- 論点 11。コミュニティの照らし方は、いまと同じ(ホスト名の一致)。名前(紐づけ用リンク)も変えない。依頼者の言葉: 「今と同じ。名前も変えたいわけじゃない」。
- 論点 12。イベントを集める仕組み(イベントの鍵、Luma の配信、ホストごとの規則)は残す。変えるのは見せ方で、イベントではなく、リンクとして見せる。イベントは、リンクの集約の中で特別に扱い、ホストごとの対応を積み重ねていく。関連リンクの種類「イベント」も残る。依頼者の言葉: 「今のイベント集約の仕組みは残したいよ。イベントという見せ方ではなく、リンクという見せ方になるだけ。イベントはリンクに集約の中でも特別扱いしたいから、hostごとに特別な対応が積み重ねられると良いなと」
- 論点 13。ページの見出しには、題名を出す。最初に保存された題名で、なければサイト名と URL。直す機能は作らず、いまある画面は、なくす。いまのイベント名は引き継ぐ(F45-AC10、F45-AC11、F45-AC20)。依頼者の言葉: 「13 A」。
- 論点 14。集約に数える元は、いまのまま。外部の URL は関連リンクだけ、スライドへのリンクは本文(引用)。現時点の結論である。依頼者の言葉: 「A 。現時点では、Aが良いかなと。」
- 論点 15。リンクのページの URL は `/link/<URL>` にする。URL から探す人が出てくることを狙う。経路の語は、`/l/` ではなく `/link/` とした。後ろに URL がそのまま付くので、縮めても短くならない。依頼者の言葉: 「`/link/https://xxxx.xxx/xxx` と言った形はどうか？こうすれば、URLから探す人が出てくるかなって？」「`/link/...` か `/l/...` か選んで。このケースで選ぶのは前者かな」
- 論点 16〜18。イベントの形のリンクとコミュニティに入ったリンクは、1 本でもページを出す(F45-AC3、F45-AC4)。viewer の下の「ほかの発表」は、イベントの形のリンクだけ、いまのまま出す。イベントでないリンクから入ったスライドも、イベントから入った発表と同じに、フォロワーに届く。依頼者の言葉: 「16 A コミュニティ、イベントは特別扱い」「17 A」「18 A」。
- 論点 19、20。集まりの無い URL は、「まだありません」のページを出す(F45-AC12、F45-AC29)。画面の「イベント」という言葉は、括りの名前としては使わない(タブは「リンク n」、1 本の管理の枠は「このスライドが並ぶページ」など。種類名「イベント」は残す)。依頼者の言葉: 「19 A」「20 A」。
- イベントの形のリンクのページに、「このグループのコミュニティはまだありません」と「作る」を残す(F45-AC27)。論点 12 のホストごとの特別な対応にあたる。依頼者の言葉: 「残す」(選択肢の回答)。
- `/link/http://…` は、`https` の正規の形へ転送する(F45-AC7)。`https:` と `http:` 以外、ユーザー名やパスワードを含むもの、読めないものだけが 404 になる(F45-AC13)。
- 道具で種類を「イベント」にした URL は、まずイベントの鍵で引き、なければ集める鍵で引く(F45-AC28)。

集める鍵は、次のとおり決める。

- イベントの形のリンクは、イベントの鍵(クエリをすべて捨てる。connpass は番号、Luma は名前、そのほかはホスト名とパス)。
- ほかのリンクは、[関連リンクを紐付ける](f27-related-links.md) の正規化した URL から、動画の開始時刻(YouTube の `t`、ニコニコ動画の `from`)を除いたもの。1 本のスライドの中で、すでにあるかを確かめるとき(F27-AC44)は、開始時刻を除かない。
- 鍵は 2 種類になる。サイトごとの規則は、いまの 1 か所のデータに足していく。規則を足すと、すでにあるリンクの集まり方が変わるので、足すたびに、保存した鍵を作り直す。

ページの扱いは、次のとおり決める。

- ページが出るかどうかは、見る人によらない。ブロックは、出ているページから、その人のスライドを外すだけにする(F45-AC15)。
- ページの見出しは、一般公開中のスライドのリンクの題名から決める。下書きの題名を出さないためである(F45-AC10)。
- 元のページへのリンク先の決め方は、[イベントの発表として並ぶ](f29-event-talks.md) の connpass の決め方(2026-11-25、2026-11-26 の依頼者の回答。issue #411)を、すべてのリンクに広げた(F45-AC25)。

受け入れた弱みは、次のとおりである。

- 題名を直す機能がないので、最初に保存された題名が誤っていても、管理者は直せない。困る場面が出たら、お問い合わせで運営がデータを直す。
- 2 つのアカウントで同じ URL を入れれば、ページを作れる。宣伝の URL でも、ページができうる。
- 道具で種類を「イベント」にした URL と、画面から入れた同じ URL は、同じページに並ぶ(F45-AC38。2026-11-28 に直した。それまでは、別のページに並びうるとしていた)。ただし、道具で種類を「イベント」にした、`www.` の有無だけが違う 2 つの URL は、別のイベントで、別のページになる。イベント以外の種類で添えた同じ URL のスライドは、その両方のページに並ぶ。

2026-11-27 に、実装の計画の相談で、次のように決めた(issue #737)。

- 正規の形は、scheme を省いた `/link/<ホスト名><パス>[?クエリ]` にする。`https://`、`http://`、`https:/`、`%` で全体をエンコードした書き方は、正規の形へ 301 で転送する。ローカルで確かめた結果、Hono と workerd(miniflare)は、path の `//`、`%2F`、`%3A`、クエリを、書かれたとおりに届けた。本番の Cloudflare が `//` をまとめるかは、本番では確かめていない。scheme を省く設計は、まとめられても、まとめられなくても動く(F45-AC31)。
- `/link/…` では、`lang` を含め、クエリはすべてリンク先のものとして読む。言語は cookie と `Accept-Language` で決める。フッターの切り替えは、`/link?to=…&lang=…` を経由して、同じページに戻る(F45-AC33、F45-AC34)。
- 受け入れた弱み: path の途中に空の区間を持つ URL(`example.com//a`)は、本番で `//` がまとめられると、別の URL として扱われる。`%41` と `A` のような `%` の書き方の違いは、別の URL として扱う(いまの正規化した URL と同じ)。
- イベントの鍵で引く範囲は、connpass、Doorkeeper、Luma だけをクエリなしで引き、ほかのサイトのイベントは、ホスト名とパスが完全に一致するときだけにする(F45-AC35)。依頼者の回答: 「ホストとパスが完全に一致するときだけ、イベントの鍵で引く」。
- `/link/…` の 200 のページは、検索に載せる(F45-AC36)。「URL から探す人」を狙うためである。依頼者の回答: 「載せる」。宣伝の URL でページが作られ、検索から見つかる悪用は、受け入れる。2 人以上の作者がいなければ、イベントの形でもコミュニティでもないページは出ないので、1 人の宣伝 URL では、ページにならない(F45-AC2)。
- コミュニティの紐づけ用リンクは、`www.` を残して保存し、関連リンクのホスト名と一致するときだけ入る(F30-AC65 のとおり)。依頼者の回答: 「入らない(いまと同じ一致)」。
- `#` から後ろの扱いは、F45-AC32 に書き直した。依頼者の回答: 「条件を『# から後ろを除いた URL のページが出る』に書き直す」。

2026-11-28 に、Pullfrog のレビューの指摘(#738、#741、#745、#746、#751、#752)を受けて、実装で次のように決めた。依頼者の判断ではなく、AI の判断である(依頼者の確認待ち)。

- イベントの形の URL(connpass、Doorkeeper、Luma)は、関連リンクの種類にかかわらず、イベントの鍵で集める(F45-AC37)。種類を「その他」などに変えても、イベントとの結びつきは外さない。種類で鍵を変えると、クエリ付きの URL や先頭が 0 の番号で、保存した鍵と `/link/…` が引く鍵が食い違い、Luma の配信との照合からも漏れるためである。ほかのサイトの URL は、これまでどおり、種類が「イベント」のときだけイベントの鍵を持つ。
- ほかのサイトのイベント(道具で種類を「イベント」にした URL)のページの経路は、書かれたとおりの鍵(`www.` を残したホスト名とパス)にする。比べる形の規則(`www.` を除く、サイトごとの書き換え)は、イベントの識別に使わない。`/link/…` は、書かれた URL の鍵でイベントを引き、当たらなければ、正規の形へ転送して、集める鍵で引く(F45-AC35 の「一致」は、書かれたとおりの鍵との一致である)。
- 同じ URL を、種類「イベント」とそれ以外の種類で添えたスライドは、1 つのページ(イベントの鍵で引いたページ)に並ぶ(F45-AC38)。1 本の管理とコミュニティの「リンク」のタブも、そのページを案内し、同じページを指す行は 1 行にまとめる。
