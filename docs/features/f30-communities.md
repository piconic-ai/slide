# F30 コミュニティをつくる

状態は実装済みです(第三スコープ。統合ブランチ `scope3` に入り、本番にはまだ反映していない。人の確認として、本番の R2 でのロゴとカバー画像の配信と、本番の D1 で既存の人のハンドルが共有の表に写っていることの確認が残る)。実装の設計は [コミュニティの実装設計](../dev/f30-communities.md) と [人とコミュニティが分け合うハンドルの実装設計](../dev/f30-handles.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

勉強会やカンファレンスに通う人が、出られなかった回や前に出た回の発表を、コミュニティの単位でまとめて見返したい。いまは、イベントのページ([イベントの発表として並ぶ](f29-event-talks.md))が回ごとに分かれていて、同じ勉強会の回をたどれない。

主催者や常連は、自分たちの勉強会のページを作っておきたい。ただ、回ごとにスライドを集める作業や、参加者の管理はしたくない。

## 得られる結果

ログインしている人はだれでも、勉強会やカンファレンスのページ(コミュニティ)を作れる。コミュニティには、スライドの自動紐づけ用リンク(connpass のグループのページなど)を入れておく。そのグループのイベントの発表が、自動でコミュニティのページに集まる。管理者が触れるのは、見た目と紐づけだけで、スライドやフォロワーは外せない。

人とコミュニティは、`slide.community/@ハンドル` の同じ並びの URL を分け合う。同じハンドルは 2 つと無い。

## 体験の流れ

1. ログインした人が、ヘッダーのアカウントのメニューの「コミュニティを作る」から `/communities/new` を開き、ハンドル、名前、紐づけ用リンク(`https://kanagawapm.connpass.com/` など)を入れて「作る」を押す。
2. コミュニティのページ `/@ハンドル` に進む。紐づけ用リンクに合う既存のイベントの発表が、すでに並んでいる。カバー画像とロゴは、5 色から選ばれた色の既定の見た目になっている。
3. 管理者は「コミュニティを編集」から、説明、ロゴ、カバー画像、ほかのリンク、紐づけ用リンクを整え、ほかの人を管理者に足す。
4. 読者は、イベントのタブでイベントごとに、スライドのタブで新しい順に、発表を見る。
5. 要らなくなったら、管理者は、ハンドルを入れて削除する。スライドとイベントは残る。

## 作る範囲

- 人とコミュニティが分け合うハンドルの表。既存の人のハンドルを写す migration。予約語の追加。`/@ハンドル` の振り分け。手放されたハンドルの 90 日の保留。運営によるハンドルの変更と、前の URL からの転送。
- コミュニティの表、管理者、紐づけ用リンク、イベントとコミュニティの対応。
- 紐づけ用リンクの判定、重複の守り、イベントとの照らし合わせ。
- コミュニティを作るページ `/communities/new`、コミュニティのページ `/@ハンドル`、編集のページ `/@ハンドル/edit`。
- コミュニティの色(5 色)、既定のカバー画像の模様、ロゴの頭文字。カバー画像とロゴのアップロードと配信。
- 削除。設定の「管理しているコミュニティ」。プロフィールの管理者の印。
- 運営の画面の、コミュニティの一覧、管理者を足す・外す、ハンドルを変える、削除。

## 作らないこと

- グループの主催者であることの確認。connpass などの API での照合。主催者でない人が作っていたときは、お問い合わせを受けて運営が管理者を移す。
- 管理者によるスライドやフォロワーの取り外し。「来るもの拒まず、去るもの追わず」にし、権限を小さくする。もめたときは、お問い合わせを受けて運営が直す。
- 承認や招待による参加。コミュニティに「入る」操作は無く、フォローだけにする([コミュニティをフォローする](f31-community-follow.md))。
- ハンドルの変更の画面。ハンドルは作る人が決め、あとから変えられない。
- Peatix、TECH PLAY など、グループの見分け方が分からないサービスの紐づけ用リンク。
- イベントの日時と場所。
- 説明の URL の自動リンク。

## 受け入れ条件

- **F30-AC1** 人が使っているハンドルは、コミュニティのハンドルとして取れない。理由が画面に出る。
- **F30-AC2** コミュニティが使っているハンドルは、人のハンドルとして(`/welcome` で)取れない。理由が画面に出る。
- **F30-AC3** `communities`、`events`、`blocks`、`edit` は、人のハンドルにもコミュニティのハンドルにも選べない。予約語の一覧は、経路の一覧と突き合わせたテストで確かめる。
- **F30-AC4** 退会した人のハンドルは、90 日の間、だれも(人もコミュニティも)取れない。90 日を過ぎると取れる。
- **F30-AC5** 同じハンドルを同時に取ろうとしても、取れるのは 1 つだけである。
- **F30-AC6** 第二スコープの人のプロフィールの URL(`/@handle` とその下の一覧)は、第三スコープの後も同じページを開く。
- **F30-AC7** 運営がハンドルを変えると、前の `/@ハンドル`(とその下の経路)は、新しい `/@ハンドル` へ 301 で移る。前のハンドルは 90 日の間、だれも取れない。
- **F30-AC8** 削除したコミュニティのハンドルは、90 日の間、だれも取れない。
- **F30-AC9** ログインしている人は、ハンドル、名前、紐づけ用リンク 1 つ以上でコミュニティを作れる。作った人が管理者になり、コミュニティのページへ進む。
- **F30-AC10** ログインしていない人は、コミュニティを作れない。`/communities/new` はログインへ進み、作る経路への送信は断られる。
- **F30-AC11** 紐づけ用リンクに入れられるのは、connpass のグループ(`https://<グループ>.connpass.com/`)、Doorkeeper のグループ(`https://<グループ>.doorkeeper.jp/`)、Luma のカレンダーの iCal(`https://api.lu.ma/ics/get?entity=calendar&id=cal-…`)、自前のサイトのトップ(`https://<ホスト名>/`)だけである。ほかの形は、欄の下に理由が出て断られる。
- **F30-AC12** だれでも使うサイトのホスト名(`connpass.com`、`doorkeeper.jp`、`luma.com`、`lu.ma`、`peatix.com`、`techplay.jp`、`github.com`、`x.com` など)の紐づけ用リンクは、理由が出て断られる。
- **F30-AC13** ほかのコミュニティが使っている紐づけ用リンクを入れると、欄の下に「このリンクは slide.community/@(ハンドル) がすでに使っています。」と出て、そのコミュニティへのリンクになる。保存されない。
- **F30-AC14** 紐づけ用リンクのホスト名と、イベントの URL のホスト名が一致するイベントが、コミュニティに入る。コミュニティを作る前からあるイベントも入る。
- **F30-AC15** 紐づけ用リンクを外すと、そのリンクで入っていたイベントが外れる。
- **F30-AC16** グループ名の無い `https://connpass.com/event/<番号>/` のイベントは、どのコミュニティにも入らない。
- **F30-AC17** 紐づけ用リンクは 10 個まで入れられる。11 個目は断られ、理由が出る。
- **F30-AC18** コミュニティのページは、上から、カバー画像、頭(ロゴ、名前、説明、`@ハンドル`、紐づけ用リンクとほかのリンク、管理者には「コミュニティを編集」、「フォロー」)、タブ(「イベント n」「スライド n」「フォロワー n」)の順に並ぶ。頭に数は出ない。
- **F30-AC19** イベントのタブに、スライドが 1 本以上入ったイベントが、最初に一般公開されたスライドの公開日時の新しい順に並ぶ。1 件ごとに、イベント名(イベントのページへのリンク)、「スライド n 本」、スライドの横に送る枠が出る。枠には 6 本まで並び、それより多いときは最後に「ほか n 本」(イベントのページへのリンク)が出る。
- **F30-AC20** 横に送る枠は、はみ出すときだけ「‹」「›」のボタンが出る。全部が 1 行に収まるときは出ない。枠は `role="region"` と「(イベント名) のスライド」の名前を持ち、キーボードで横に送れる。幅 375px でもページ全体は横に広がらない。
- **F30-AC21** スライドのタブに、コミュニティに入った一般公開中のスライドが、一般公開の新しい順に並ぶ。
- **F30-AC22** コミュニティの色は、作ったときに 5 色(赤、橙、黄、緑、紺)から 1 つ選ばれる。管理者が編集のページで選び直すまで変わらない。再読み込みしても同じ色で出る。
- **F30-AC23** 既定のカバー画像は、その色の 3 段の角丸の正方形を 2 段に並べた模様で、幅 600px を超える画面では横 16 個、600px 以下では横 8 個並ぶ。同じコミュニティでは、開くたびに同じ並びになる。端の正方形が欠けない。`role="img"` と「(コミュニティ名) のカバー画像」の名前を持つ。
- **F30-AC24** ロゴが無いときは、名前の頭文字が、その色の「中」の地に、地との対比 4.5:1 以上の文字の色(白か墨)で出る。
- **F30-AC25** 管理者は、名前、説明、色、ロゴ、カバー画像、ほかのリンク(3 つまで)、紐づけ用リンク、そのコミュニティのイベント名を直せる。
- **F30-AC26** 管理者でない人には、「コミュニティを編集」が出ない。管理者でない人と、ログインしていない人は、`/@ハンドル/edit` を開けず、編集、管理者、削除、イベント名の経路への送信は断られる。
- **F30-AC27** 管理者は、ハンドルを入れて、別の人を管理者に足せる。管理者は、ほかの管理者を外せる。自分も外れられる。
- **F30-AC28** 最後の 1 人の管理者は、外れられない。理由が出る。
- **F30-AC29** 2 MB を超えるカバー画像、1 MB を超えるロゴ、PNG・JPEG・WebP でないファイル(拡張子や種類の名乗りを偽ったものを含む)は、理由が出て断られる。中身の種類は、ファイルの先頭のバイトで確かめる。
- **F30-AC30** アップロードしたカバー画像は 4:1 に切り抜かれ、横 1600px に縮めて配られる(1600px より小さい画像は拡大しない)。ロゴは正方形で配られる。元の画像は保存されない。
- **F30-AC31** 編集のページの「頭文字に戻す」でロゴが頭文字に、「既定の模様に戻す」でカバー画像が既定の模様に戻る。
- **F30-AC32** 削除の「削除する」は、ハンドルの入力が一致するまで押せない。一致しない入力の送信は、サーバーが断る。
- **F30-AC33** 削除すると、`/@ハンドル` は 404 になり、フォローと紐づけ用リンクがなくなる。スライド、関連リンク、イベントのページは残る。
- **F30-AC34** 管理者のプロフィールの「コミュニティ」のタブで、そのコミュニティの名前の横に鍵の印が付き、読み上げで「管理者」と読まれる。
- **F30-AC35** 設定に「管理しているコミュニティ」の枠があり、自分が管理者のコミュニティと、それぞれの「コミュニティを編集」が並ぶ。
- **F30-AC36** 運営は、運営の画面で、コミュニティの一覧を見て、管理者を足す・外す、ハンドルを変える、削除ができる。運営でない人は、その経路を通れない。
- **F30-AC37** 名前は 50 文字まで、説明は 160 文字までで、超えると理由が出て断られる。説明はプレーンテキストで出し、URL を自動でリンクにしない。HTML の記号は文字として出る。
- **F30-AC38** ログイン中の人が見るコミュニティのページの一覧(イベントのタブ、スライドのタブ)と数に、その人がブロックしている人のスライドは出ない。
- **F30-AC39** 作るページと編集のページの紐づけ用リンクの欄は、1 行が URL の欄と「外す」だけで、「リンクを足す」で 10 行まで増やせる。問題がある欄だけ、枠が赤になり、下に赤字で理由が 1 文出て、`aria-invalid` と `aria-describedby` が付く。入力した値は消えない。
- **F30-AC40** イベントのページの「作る」から進んだとき、作るページの紐づけ用リンクの欄に、そのグループのリンクが入っている。
- **F30-AC41** 幅 1280px と 375px で、コミュニティのページ、作るページ、編集のページが、横にはみ出さない。
- **F30-AC42** ヘルプに、コミュニティの項目がある(作り方、紐づけ用リンク、管理者、削除、お問い合わせで頼めること(ハンドルの変更、管理者の移し替え、イベント名の修正))。日本語と英語の両方で読める。作るページから、その項目へリンクしている。
- **F30-AC43** 保留中のハンドルは、選べない。理由が画面に出る。
- **F30-AC44** ログインした人のヘッダーのアカウントのメニューに「コミュニティを作る」があり、`/communities/new` を開く。ログインしていない人のヘッダーには出ない。
- **F30-AC45** 編集のページの色は、5 色の見本から 1 つを選ぶ radio で、いまの色が選ばれた状態で出る。見本は色の名前(日本語のページでは「赤」「橙」「黄」「緑」「紺」、英語のページでは「Red」「Orange」「Yellow」「Green」「Navy」)で読み上げられ、矢印のキーで選べ、押せる範囲は 44px 四方以上ある。選んで保存すると、既定のカバー画像の模様、ロゴの頭文字の地、フォローの新着のカードの印(F31-AC4)がその色になる。どれも選ばれていないときは、ブラウザーが送る前に止める。5 色のどれでもない値、色の無い送信は、理由が出て断られ、何も保存されない。
- **F30-AC52** 管理者が 1 人だけのとき、編集のページのその人の「管理者から外れる」は押せない状態で出て、ボタンのすぐ下に理由(日本語のページでは「最後の管理者は外れられません。ほかの管理者を足してから外れてください。」、英語のページでは「The last admin cannot leave. Add another admin before leaving.」)が出て、ボタンの説明として読み上げられる。管理者が 2 人以上のときは押せる。送信されたときは、F30-AC28 のとおりサーバーが断る。

## 決めたこと

第三スコープを作るにあたり、次のように決めた(2026-11-23、第三スコープの指示書)。

- 人とコミュニティは 1 つのハンドルの並びを分け合う。ハンドルの一意を 1 つの表(ハンドルと、それが人のものかコミュニティのものか)で守る。`/@ハンドル` は、その表を引いて人のプロフィールかコミュニティのページを出す(D-03)。
- 本番のデータは残す。migration は足すだけにする。既存の人のハンドルは、共有の表へ写す migration を書く(D-04)。
- 人とコミュニティのハンドルの決まりは同じ。英小文字、数字、`-`、1〜39 文字、`-` で始まらない(D-14)。
- 予約語に、第三スコープの経路の先頭の語を足す: `communities`、`events`、`blocks`、`edit`(D-15)。
- 手放されたハンドル(退会、コミュニティの削除、運営によるハンドルの変更)は、90 日間だれも取れない(D-16)。
- ログインしている人は、だれでもコミュニティを作れる。作った人が最初の管理者になる(D-30)。作るときに入れるのは、ハンドル、名前、紐づけ用リンク(1 つ以上、10 個まで)(D-31)。
- 紐づけ用リンクに入れられるのは、connpass のグループ、Doorkeeper のグループ、Luma のカレンダーの iCal、自前のサイト(ホスト名だけ)の 4 つ。だれでも使うサイトのホスト名は断る。一覧は設計の文書に書く(D-32)。
- Luma は、カレンダーのページの URL ではなく、カレンダーの「iCal で購読」の URL を入れてもらう。カレンダーのページの URL からはカレンダーの番号が分からず、ページを取りに行かないため(D-05)。
- connpass、Doorkeeper、自前のサイトは、イベントの URL のホスト名と紐づけ用リンクのホスト名が一致すれば入る。グループ名の無い URL は、どのコミュニティにも入らない。Luma は [Luma の配信でコミュニティに紐づける](f33-luma-feeds.md)(D-33)。
- 1 つの紐づけ用リンクは、1 つのコミュニティにだけ属する(D-34)。作ったとき、足したときは、合う既存のイベントがすべて入る。外したときは、そのリンクで入っていたイベントが外れる(D-35)。
- ハンドルはあとから変えられない。変える必要があるときは、お問い合わせを受けて運営が変える。前の URL は新しい URL へ転送する(D-36)。転送は、前のハンドルをだれも持っていない間だけ行う。90 日の保留(D-16)が明けて、だれかが前のハンドルを取ったら、その人のページを出す。
- 管理者ができるのは、名前、説明、色、ロゴ、カバー画像、ほかのリンク(3 つまで)、紐づけ用リンク、そのコミュニティのイベント名の編集と、管理者を足す・外す、コミュニティの削除。スライドとフォロワーを外す権限はない(D-37)。
- 管理者同士は、足すのも外すのも自由。最後の 1 人は外れられない(D-38)。
- 削除は、ハンドルの入力が一致するまで押せない。削除すると、コミュニティのページ、ハンドル、フォロー、紐づけ用リンクがなくなる。スライド、関連リンク、イベントは残る(D-39)。
- グループの主催者であることは確かめない。運営が管理者を移す操作を作る(D-40)。
- 説明は 160 文字まで、名前は 50 文字まで。説明はプレーンテキストで、URL を自動でリンクにしない(D-41)。
- 色は 5 色(赤 `#e8848a`/`#c8242e`/`#9a1b22`、橙 `#f2a06b`/`#e2692b`/`#b9501e`、黄 `#f7d46a`/`#f2b71c`/`#d4961a`、緑 `#6fae84`/`#2f7a4a`/`#1f5a36`、紺 `#6e86b8`/`#26407a`/`#1a2c57`。明・中・暗)から作ったときにランダムに選ぶ。管理者は、編集のページで 5 色の見本から選び直せる(2026-11-26 の依頼者の決定で、D-45 の「変えない」を改めた)。値はデザインのトークンに置く(D-45)。
- 既定のカバー画像は、その色の 3 段の角丸の正方形を 2 段に並べた帯。幅 600px を超える画面では横 16 個、以下では横 8 個。色の並びはコミュニティの番号から決まる乱数で選ぶ。画像を生成して保存せず、HTML と CSS で描く(D-46)。
- 差し替えるカバー画像は、PNG、JPEG、WebP、2 MB まで。4:1 に切り抜いて横 1600px に縮め、R2 に置いて配る。元の画像は保存しない(D-47)。
- ロゴは、PNG、JPEG、WebP、1 MB まで。正方形に縮めて R2 に置く。無いときは、名前の頭文字を、その色の「中」の地に出す。文字の色は、地との対比が 4.5:1 以上になる方(D-48)。
- 色面を使ってよいのは、カバー画像の既定の模様と、ロゴの頭文字の地と、フォローの新着のカードの印(F31-AC4)と、編集のページの色の見本の中だけ。ほかの部品にコミュニティの色を広げない(D-13)。
