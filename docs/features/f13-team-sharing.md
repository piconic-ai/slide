# F13 社内のメンバーだけに共有する

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

社内勉強会の担当者が、外部へ出せない構成図を含む資料を同僚へ配る。GitHub の権限がない同僚にも、チームのメンバーとして資料を読んでもらいたい。

## 得られる結果

リポジトリの利用者とは別に、資料を読める組織の範囲を管理できる。

## 体験の流れ

1. TEAM のワークスペースを用意し、所有者・管理者・メンバーを管理する。
2. 資料の閲覧対象をチーム限定にして公開する。
3. 参加者がログインして閲覧する。退職・異動時にはメンバーから外す。

## 作る範囲

- TEAM には PRO の独自ドメイン・大容量・分析も含める。
- チーム限定の資料と、メンバーごとの閲覧資格。
- 限定 HTML だけでなく、画像・翻訳・音声の権限確認。

## 作らないこと

- 同じメールドメインであることだけを根拠にメンバーへ追加すること。
- 無料ページ設定や解約を理由に社内資料を一般公開すること。

## 受け入れ条件

- 非メンバーが共有 URL やファイル URL を受け取っても読めない。
- メンバー削除後は発行済みの閲覧セッションでも新しくファイルを取得できない。
- TEAM を失効しても資料が公開されず、購入権限と組織の会員資格を混同しない。

## 未決事項

- 招待・承認・メンバーの上限と、TEAM の席数課金方式。
- 所有者の引き継ぎと、失効後に管理者が取れる復旧操作。

技術上の制約は [開発設計](../dev/design.md#access-control) を参照してください。
