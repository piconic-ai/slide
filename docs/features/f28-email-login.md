# F28 メールのコードでログインする

状態は一部を実装済みです(第二スコープ)。ログイン、利用者の識別子の切り替え、招待の一覧、メールの送信、GitHub の取り除き(F28-AC1〜F28-AC34)は実装した。プロフィールを書くこと、顔写真(F28-AC35〜F28-AC54)は未実装。実装の設計は [メールのコードでログインする実装設計](../dev/f28-email-login.md)。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇者が、GitHub のアカウントを持っていない。あるいは、持っていても、スライドの置き場に GitHub の情報を渡したくない。運営から招待されたメールアドレスなら、持っている。パスワードを新しく作って覚えることはしたくない。

また、作者は、自分のプロフィール(名前、自己紹介、顔写真、リンク)を、GitHub の公開プロフィールの写しではなく、自分で決めて出したい。

## 得られる結果

運営に招待されたメールアドレスがあれば、メールに届く 6 桁のコードだけでログインして、スライドを置ける。GitHub のアカウントは要らない。初めての人は、ハンドルと表示名を自分で決める。プロフィールは、設定で自分で書く。顔写真は、何もしなければ Gravatar の画像が出て、アップロードすれば上書きできる。

## 体験の流れ

1. ヘッダーの「ログイン」(またはトップの「ログインして続ける」、フォローなどのログインを促す表示、MCP の接続の許可)から、戻り先をつけて `/login` を開く。メールアドレスを入れ、「コードを送る」を押す。
2. 6 桁のコードがメールに届く。画面は、コードの入力に変わる。コードを入れて「ログイン」を押す。
3. 初めての人は、`/welcome` でハンドルと表示名を決める。決めるまで、ほかの画面へ進めない。
4. ログインを始めた元のページへ戻る。トップでファイルを預けていた場合は、[スライドを、ドロップして置く](f22-browser-drop.md) と同じく、受け取りに進む。
5. 設定で、表示名、自己紹介、場所、Web サイト、SNS のリンク、顔写真を書く。プロフィールに出る。

## 作る範囲

- `/login`(メールアドレスの入力、コードの入力)と、`/welcome`(ハンドルと表示名)。
- メールで送る 6 桁のワンタイムコード。期限、入力の回数、送信の回数の上限、ボットを防ぐ確認(Turnstile)。
- 招待の一覧(メールアドレス)と、運営の画面での足す・外す・一覧。
- 送信の口。ローカルでは、送らずに送信箱(ローカルの表やログ)に書く。本番の送信の実装は作る。
- 利用者の識別子を、GitHub の利用者番号から、サービスが発行する番号に切り替えること。
- ハンドルの決まりと予約語。
- GitHub でのログイン、GitHub からのプロフィールの同期、「GitHub でフォローしている人が参加した」お知らせの取り除き。古い経路は `/login` へ送る。
- ログインに進む入口(ヘッダー、トップ、フォローなどのログインを促す表示、MCP の接続の許可)の、`/login` への切り替え。
- 設定の「プロフィール」(表示名、自己紹介、場所、Web サイト、SNS のリンク 3 つまで、顔写真)と「アカウント」(ハンドルとメールアドレスの表示)の枠。
- 顔写真の配信(アップロードした画像、Gravatar の画像、頭文字の順)。運営の画面の、アップロードした画像を外す操作。

## 作らないこと

- パスワード、マジックリンク、Google、GitHub でのログイン。メールのコードだけにする。
- ログインをだれにでも開くこと。利用規約とプライバシーポリシーに、メールアドレスの扱いをまだ書けていない。ログインは招待制のまま。
- 「ログインはできるが置けない人」。ログインできた人は、全員スライドを置ける。
- メールアドレスの変更の画面、受信箱を失ったときの戻し方の画面。問い合わせ(helpdesk)で個別に対応し、ヘルプにそのことを書く。
- ハンドルの変更。
- 読者が顔写真を通報する専用の窓口。既存の通報の窓口で受ける。
- 利用規約とプライバシーポリシーの本文の更新。

## 受け入れ条件

- **F28-AC1** 招待されたメールアドレスを `/login` に入れると、そのアドレスに 6 桁のコードが送られ、画面がコードの入力に変わる。
- **F28-AC2** 送られるメールの本文に、コードとサービス名だけが入り、追跡のリンクが入らない。
- **F28-AC3** 正しいコードを入れると、ログインできる。
- **F28-AC4** 初めてログインした人は、`/welcome` に進み、ハンドルと表示名を決めるまで、ほかの画面へ進めない。ログアウトはできる。
- **F28-AC5** ハンドルと表示名を決めると、ログインを始めた元のページへ戻る。
- **F28-AC6** 戻り先にほかの origin の URL を渡しても、そこへは移らない。戻り先は同じ origin の path だけを受け付ける。
- **F28-AC7** 招待されていないメールアドレスを入れても、画面と応答は招待されている場合と同じ「コードを送りました」になる。
- **F28-AC8** 招待されていないメールアドレスには、コードが送られない。
- **F28-AC9** 招待されているかどうかを、応答の内容や応答までの時間で知ることができない。
- **F28-AC10** 違うコードを 5 回入れると、そのコードではログインできなくなる。
- **F28-AC11** コードを送ってから 10 分を過ぎると、そのコードではログインできない。
- **F28-AC12** 一度使ったコードは、もう一度は使えない。
- **F28-AC13** 同じメールアドレスへの送信が上限を超えると断られる。断られたことと、いつ再び送れるかが画面に出る。
- **F28-AC14** 同じ接続元からの送信が上限を超えると断られる。断られたことと、いつ再び送れるかが画面に出る。
- **F28-AC15** 送信の上限の値を、運用設定で変えられる。
- **F28-AC16** Turnstile の確認を通らない要求では、コードが送られない。Turnstile の site key と secret が無いローカルでは、確認を通す。
- **F28-AC17** `/login` の説明に、いまは招待制であること、運営が登録したメールアドレスでだけログインできることが出る。
- **F28-AC18** ハンドルは、英小文字、数字、`-` だけで、1〜39 文字、`-` で始まらない。これに合わないハンドルは選べず、理由が画面に出る。
- **F28-AC19** 予約語のハンドルは選べず、理由が画面に出る。予約語の一覧は、経路の一覧と突き合わせたテストで確かめる。
- **F28-AC20** すでに使われているハンドルは選べず、理由が画面に出る。
- **F28-AC21** 決めたハンドルは、あとから変えられない。
- **F28-AC22** メールアドレスは、本人の設定ページと運営の画面(招待の一覧)以外のどの画面にも出ない。
- **F28-AC23** メールアドレスは、どの API の応答にも出ない(本人の設定ページを組み立てる応答を除く)。ログにも出ない。
- **F28-AC24** 運営の画面で、メールアドレスを招待の一覧に足せる。
- **F28-AC25** 運営の画面で、招待の一覧を見られ、メールアドレスを外せる。
- **F28-AC26** 招待の一覧から外された人は、次の操作でログイン済みの状態が切れる。
- **F28-AC27** `/auth/github` など、GitHub でのログインの経路は `/login` へ移る。GitHub でログインする手段は残っていない。
- **F28-AC28** お知らせの種類に、「GitHub でフォローしている人が参加した」がない。お知らせの設定にも出ない。
- **F28-AC29** 未ログインでトップにファイルを選び「ログインして続ける」を押すと `/login` に進み、メールのコードでログインして戻ると、預かったファイルの受け取りが始まる。
- **F28-AC30** 未ログインで MCP の接続を許可しようとすると `/login` に進み、ログインして戻ると、許可の画面が出る。
- **F28-AC31** ヘッダーの「ログイン」は、`/login` に戻り先をつけて進む。
- **F28-AC32** 空の D1 に migration をすべて適用した後のスキーマに、GitHub の利用者番号を前提にした列がない。
- **F28-AC33** ログアウトすると、session が消え、スライドの管理の画面が開けない。
- **F28-AC34** 退会すると、これまでどおり、自分のスライドと記録が消える。
- **F28-AC35** 設定で書いた表示名、自己紹介、場所、Web サイト、SNS のリンクが、プロフィールに出る。
- **F28-AC36** 表示名を空にして保存すると、断られ、理由が出る。
- **F28-AC37** 表示名が 50 文字、自己紹介が 160 文字、場所が 50 文字を超えると、保存できず、理由が出る。ちょうどの長さなら保存できる。
- **F28-AC38** Web サイトと SNS のリンクに、`https:` 以外の URL を入れると、保存できず、理由が出る。
- **F28-AC39** SNS のリンクは 3 つまで。4 つ目は保存できず、理由が出る。
- **F28-AC40** 自己紹介に HTML を書いても、文字として出る。
- **F28-AC41** 画像をアップロードすると、ヘッダー、プロフィール、viewer の作者の顔写真が、その画像になる。
- **F28-AC42** PNG、JPEG、WebP 以外のファイルは、アップロードできず、理由が出る。
- **F28-AC43** 1 MB を超えるファイルは、アップロードできず、理由が出る。
- **F28-AC44** 画像として読めないファイルは、アップロードできず、理由が出る。
- **F28-AC45** アップロードした画像は、サービスで正方形に縮められて保存される。元の画像は保存されない。
- **F28-AC46** アップロードした画像を外すと、Gravatar に画像があればその画像に、なければ頭文字に戻る。
- **F28-AC47** 「Gravatar の画像を使う」を切ると、アップロードした画像が無いとき、頭文字になる。「Gravatar の画像を使う」の既定は入である。
- **F28-AC48** どのページの HTML にも、メールアドレス、そのハッシュ、Gravatar の URL が出ない。
- **F28-AC49** 顔写真の配信の経路は、ほかの人の顔写真を、その人の id で取れる。メールアドレスは推測できない。
- **F28-AC50** Gravatar に画像が無いとき、または Gravatar が応答しないとき、頭文字が出る。
- **F28-AC51** 運営の画面で、その人のアップロードした画像を外せる。外すと、その人の顔写真は Gravatar か頭文字に戻る。外したことは、運営の記録に残る。
- **F28-AC52** 退会すると、アップロードした画像が R2 から消える。
- **F28-AC53** 設定に、「GitHub から同期し直す」と、最後に同期した日が出ない。
- **F28-AC54** 設定の「アカウント」に、ハンドルとメールアドレスが出る。ハンドルは変えられないと注記され、メールアドレスは自分にだけ見えると注記される。

## 決めたこと

第二スコープを作るにあたり、次のように決めた(2026-11-22)。

- 招待するメールアドレスは D1 の表に持ち、運営の画面(Cloudflare Access で守られた画面)で足す・外す。運用設定の値には持たない。後でログインをだれにでも開き、置くことだけを招待制に残すときも、同じ表を「置ける人」の一覧として使える。
- メールの送信は「送信の口」を 1 つ作り、ローカルでは送らずに送信箱に書く。本番の送信の実装は作るが、secret、DNS(SPF、DKIM、DMARC)、送信サービスの登録は依頼者が行う。送信のサービスは、設計の文書で候補を比べて決める。
- 利用者の識別子を、GitHub の利用者番号から、サービスが発行する番号(Better Auth の利用者の id)に切り替える。所有者・フォロー・ミュート・お知らせ・通報・MCP など、利用者の識別子を持つすべての表が対象。本番のデータは空にしてよいので、既存の行を移す処理は書かない。
- ログインはメールに送る 6 桁のコードだけ。Better Auth の現行のドキュメントを読み、メールのワンタイムコードの仕組みがあればそれを使う。記憶で決めない。
- コードの有効期限は 10 分。1 つのコードへの入力は 5 回まで。5 回間違えるとそのコードは無効になる。
- コードの送信には、メールアドレスごとと接続元ごとの回数の上限を置く。値は設計の文書で決め、運用設定で変えられるようにする。ボットを防ぐ確認(Turnstile)を置く。
- 招待されていないメールアドレスが入力されても、画面と応答は同じ「コードを送りました」にし、コードは送らない。招待されているかどうかを、応答の内容・時間で知られないようにする。
- ログインそのものを招待制にする。ログインできた人は、全員スライドを置ける。
- 初めてログインした人は、`/welcome` でハンドルと表示名を決めるまで、ほかの画面へ進めない(ログアウトはできる)。
- ハンドルの決まりは、いまの `accounts` の制約(英小文字、数字、`-`、1〜39 文字、`-` で始まらない)を保つ。予約語を足す: 既存と新しい経路の先頭の語(`login`、`welcome`、`settings`、`slides`、`help`、`auth`、`api`、`mcp`、`embed`、`events`、`notifications`、`operator`、`_preview` など)と、`admin`、`slide`、`support`、`me` のような紛らわしい語。一覧は設計の文書に書き、テストで経路の一覧と突き合わせる。ハンドルは変えられない。
- メールアドレスは、本人の設定ページ以外のどの画面、どの API 応答、どのログにも出さない。
- メールアドレスの変更、受信箱を失ったときの戻し方の画面は作らない。ヘルプに、問い合わせで個別に対応することを書く。
- MCP の接続の許可(OAuth の同意)は、新しいログインの session で動くようにする。未ログインなら `/login` へ進み、戻ってきて同意の画面を出す。
- プロフィールは本人が設定ページで書く。表示名(必須、50 文字まで)、自己紹介(160 文字まで)、場所(50 文字まで)、Web サイト(1 つ)、SNS のリンク(3 つまで)。URL は `https:` だけを受け付ける。
- 顔写真は、アップロードした画像、Gravatar の画像、頭文字の順に使う。「Gravatar の画像を使う」の切り替えを置き、既定は入にする。
- Gravatar の画像は、サービスが取りに行って配る。ページにメールアドレスのハッシュや Gravatar の URL を載せない。viewer と管理画面の CSP を広げない。取りに行った画像は cache し、Gravatar に画像が無いときは頭文字にする。
- アップロードできる画像は PNG、JPEG、WebP、1 MB まで。サービスで正方形に縮めて R2 に置き、サービスから配る。元の画像は保存しない。
- 不適切な顔写真への対応は、運営の画面から、その人のアップロードした画像を外せる操作だけを作る。読者からの通報の種類は足さない。
- 自己紹介とリンクは、第二スコープでは公開中のスライドの有無にかかわらず出す(ログインが招待制なので、広告目的の登録は起きない)。ログインをだれにでも開くときに、出す条件を見直す。
- 「GitHub でフォローしている人が参加した」お知らせは、GitHub の情報を前提にするので、取り除く([知りたい出来事が、お知らせに届く](f20-notifications.md))。
- メールアドレスの正規化は、前後の空白を取って小文字にするだけにする。`+` つきのアドレスは、元のアドレスとは別のアドレスとして扱う。運営は、人が入力するとおりのアドレスを招待する(2026-11-22、作業 A1 が実装の設計で決めた)。
- 送信の回数の上限の既定は、メールアドレスごとに 1 時間 5 通、接続元ごとに 1 時間 20 通。環境の値 `LOGIN_CODE_LIMITS` で変える(2026-11-22、同上)。
- 運営の画面の招待の一覧には、招待したメールアドレスが出る。メールアドレスを出さない範囲(F28-AC22、F28-AC23)は、読者と本人に向けた画面と API で、運営の画面は含まない。
- 本番のデータは空にしてよい。本番の唯一のアカウントは、いまの GitHub でのログインのまま退会し、新しい方法で作り直す(issue #331)。

## 未決事項

- 退会した人のメールアドレスを、招待の一覧に残すか、外すか。退会した人が、同じメールアドレスで入り直せるかに関わる。
- 停止中の人が退会して入り直したときに、停止のままにする条件(F17-AC30)を、何の値で持つか。GitHub の利用者番号をやめるので、メールアドレスで持つか、別の方法にするかを決める。[知らない人のスライドも、安心して開ける](f17-safe-viewing.md) の未決事項にも挙げた。
- 自己紹介の改行の扱い。GitHub の文を写していたころは、改行を 1 つの空白にまとめていた。自分で書くようになったあと、改行を残すか。F21 の削除した条件に含まれていた。
- Gravatar にメールアドレスのハッシュを送ることを、プライバシーポリシーにどう書くか(本文の更新は第二スコープの範囲外。人の確認に挙げる)。
