# F16 良かったデッキに投げ銭を送る

状態は未実装の設計案です。実装する段階は [ストーリーマップ](../story-mapping.canvas) で確認できます。

## 利用場面

登壇を聞いた参加者や、あとから公開デッキを読んだ読者が、「良かった」を言葉だけでなく形にして作者に渡したい。作者はデッキを売るつもりはないが、手間をかけた発表への反応を受け取れると、次も共有しようと思える。

## 得られる結果

読者は公開デッキからその場で少額のお礼を送れる。作者は金額とひとことを受け取り、知を共有しあう循環にお金が流れる。

## 体験の流れ

1. 作者が Stripe Connect の販売者登録を行い、投げ銭の受け取りを有効にする。
2. 読者がデッキの閲覧画面から「お礼を送る」を開き、用意された 3 つの金額か任意の金額を選び、ひとことを添える。
3. 決済事業者の画面で支払う。確定後、作者に通知が届き、受け取り履歴に金額とひとことが残る。

## 作る範囲

- 一回ごとの都度決済。サービス内にポイント・ウォレット・残高を持たない。
- 金額のプリセット 3 つと任意額、上限と下限。ひとこと(任意)。
- 対象は一般公開中のデッキ。作者限定・チーム限定・有料コース内のデッキには出さない。
- 作者への通知と受け取り履歴。作者が有効・無効を切り替えられること。
- Stripe Connect による手数料と、作者への精算。

## 作らないこと

- ポイントの購入、ユーザー間のポイント譲渡、受け取った投げ銭をそのまま別の人に送る機能。恩を送りたい人は自分で投げ銭する。
- 投げ銭による閲覧権限・特典・バッジ。
- 月額の継続支援(将来の候補にとどめる)。
- 読者都合の返金。決済事業者の不正対応は別に扱う。

## 受け入れ条件

- 支払いの確定前に通知・履歴を作らず、通知の重複で二重に記録しない。
- 金額・通貨・送金先はサーバーが決め、クライアントが送る値では決めない。
- 作者が受け取りを無効にするか、デッキを公開停止したあとは、新しい支払いを始められない。開いたままの支払い画面は失効させ、古い画面から支払いを始め直せない。
- 無効化や公開停止の前に読者が支払いを確定させていた分は、決済がその後に完了しても受け取りとして記録し、作者に通知して精算する。返金はしない。
- 作者がデッキを公開停止・削除しても、確定済みの受け取り履歴は残る。
- ひとことは作者だけが読める。公開する機能は初期対象外。

## 未決事項

- 金額の下限・上限と初期のプリセット、手数料率、対応する作者の地域。
- ログインしていない読者から受け付けるか。
- 作者が受け取った金額や件数をデッキに表示するか。
- コースに含まれる無料デッキを対象にするか。初期案では対象外。

技術上の制約は [開発設計](../dev/design.md#billing) を参照してください。
