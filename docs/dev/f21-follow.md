# フォローの実装設計

[気になる人を、フォローする](../features/f21-follow.md)ための保存処理と、フォロー・初公開のお知らせを扱う。

## 保存するもの

| テーブル・列 | 内容 |
| --- | --- |
| `follows.follower_user_id` | フォローした人の GitHub ユーザー ID |
| `follows.followee_user_id` | フォローされた人の GitHub ユーザー ID |
| `follows.created_at` | 現在のフォローを始めた時刻（Unix 秒） |
| `decks.first_published_at` | 初めて一般公開した時刻（Unix 秒）。まだ公開の記録がなければ NULL |

フォローの主キーは両者の ID の組で、自分自身へのフォローは CHECK 制約で拒む。`follows_followee` 索引は、作者のスライドを初公開するときに受け手を引くために使う。

## フォロー、ミュート、退会

| 操作 | 保存・読み取りの条件 |
| --- | --- |
| フォローする | 両者のアカウントが存在し、別人で、フォローする人が相手をミュートしていないことを挿入と同じ文で確かめる。すでにある組の時刻は保つ |
| フォローを解除する | 指定した向きの組を消す。相手に届いたお知らせは残る |
| 自分がフォローしている人を読む | 相手の現在のハンドルを、フォロー時刻の新しい順で返す。停止中の人とアカウントがない人は一覧から外す |
| 相手をミュートする | ミュートの保存と同じ D1 バッチで、その人へのフォローを消す。ミュートを解除してもフォローは復元しない |
| 退会する | アカウントを削除するバッチで、本人がしたフォローと本人へのフォローを消す |

## 初公開の判定

手動公開と CI 公開は、どちらも `saveTransition` を通る。公開状態の更新と同じ D1 バッチで、更新直前の `first_published_at` を読む。一般公開への更新では、まだ NULL の場合だけ公開時刻を保存する。その更新が成立し、直前の値が NULL で、かつ直前の状態が下書き(または、再開先のない公開停止)だったときにだけ、フォロワーへの配信を呼ぶ。この列ができる前の Worker が公開したスライドは、時刻が NULL のまま公開中でありうるので、列だけでは版の更新と区別できないためである。配信の文は、その時点で公開中かどうかを見ない。直後に公開が止まっても行は入り、一覧と未読件数の表示条件が、公開中のあいだだけ見せる。版の更新、公開停止、再開を経ても最初の時刻を保つ。同じ秒に複数の更新が成立しても、初公開は一度だけである。

移行 0028 は、既存の一般公開中のスライドには公開版の `deployments.ready_at` を、停止中で再開先が残るスライドには再開先の版の `ready_at` を入れる。これは移行前の初公開時刻に代えて使う値である。どちらの版も残っていなければ NULL を保ち、次の一般公開を初公開として扱う。

旧 Worker は移行後もスライドを保存・公開できる。移行後から新 Worker への切り替えまでに旧 Worker が初公開した場合、この列は NULL のまま残り、新 Worker が次に公開状態を更新したときに初公開として扱う。

配信時のミュート・受信設定と、一覧・未読件数に含める条件は[お知らせの実装設計](f20-notifications.md)を参照する。
