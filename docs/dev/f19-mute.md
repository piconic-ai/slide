# ミュートの実装設計

[見たくない作者を、一覧から外す](../features/f19-mute.md) を実装するための契約。ここでは、ミュートの保存と、どの一覧に効かせるかを扱う。

## 保存

表 `mutes` に、「だれが、だれを」を 1 行で持つ。

| 列 | 内容 |
| --- | --- |
| `muter_user_id` | ミュートした人。利用者の id(Better Auth の `auth_user.id`) |
| `muted_user_id` | ミュートされた人。利用者の id(`decks.owner_user_id` と同じ値) |
| `created_at` | ミュートした日時 |

主キーは 2 つの組である。同じ相手を 2 度ミュートしても、行は 1 つで、最初の日時を保つ。自分自身の行は、CHECK で拒否する。

ミュートが成立したら、同じ D1 バッチで自分から相手へのフォローも外す。相手のアカウントが存在しなければフォローには触れない。相手から自分へのフォローは保つ。ミュート中は相手をフォローできず、解除後は改めてフォローできる（[フォローの実装設計](f21-follow.md)）。

退会すると、その人がしたミュートと、その人へのミュートを消す(`src/decks/deletion-store.ts` の `markAccountDeleted`)。

## 効かせる一覧

すすめる一覧を作る検索に、条件 `notMutedBy(viewer)`(`src/mutes/store.ts`)を付ける。見ている人がミュートした作者のスライドを外す条件で、見ている人がいなければ(ログインしていなければ)、条件なしになる。

| 一覧 | ミュート |
| --- | --- |
| トップページの「最近公開されたスライド」(`/api/public/slides`) | 効く |
| スライドのページの、引用している・引用されている一覧と、「ほか N 件」の数 | 効く |
| プロフィール(`/@handle`)の、その人のスライドの一覧 | 効かない(直接開いたので) |
| 共有 URL、配信、表紙 | 効かない(直接開いたので) |
| 作者の管理画面の「引用されたページ」(`readCitedPages`) | 効かない。自分のスライドがだれに引用されているかの記録で、すすめる一覧ではない |

件数は、表示する数に絞る前に条件を付けて数える。ミュートした作者のスライドは、「ほか N 件」にも数えない。

ミュートは、ミュートした人の応答にだけ効く。ほかの読者と、ログインしていない読者には、これまでどおり出る。

## 付け忘れを見つける

すすめる一覧は、運営が非表示にしたスライドを外す条件 `notHidden` を、必ず使う。そこで、`src/share/takedown-readers.test.ts` が、`notHidden` を使う source のうち、`notMutedBy` を使っていないものを見つけて失敗する。例外は、テストの中の一覧に、理由とともに書く(いまは、`notHidden` を定義する `takedown-store.ts`、作者自身の公開を変える `publication/store.ts`、直接開いたスライドの配信を決める `preview/access-store.ts`)。

このテストは、ファイルの単位で見る。同じファイルの中に、`notMutedBy` を付けた一覧と付けていない一覧があっても、見つけられない(いまの `readCitedPages` が、意図した例である)。`notHidden` を使わない一覧も、見えない。付け忘れを減らすためのもので、なくす保証ではない。

すすめる一覧を足すときは、見ている人を引数に取り、`notMutedBy` を付ける。すすめる一覧ではないと判断したときは、例外の一覧に理由を書く。

## 見ている人を引く

スライドのページと、トップページの一覧の API は、だれでも読める。ログインしている人には、その人のミュートを効かせるので、見ている人を引く(`currentOwner(c, { allowSuspended: true })`)。停止中の人も、公開のページは読めるためである([アカウントの停止の実装設計](f17-suspension.md#停止中の本人))。

`/api/public/slides` は、ログインしていない人には、だれにでも同じ応答を返す(`Cache-Control: public, max-age=60`)。ログインした人には、その人のミュートを反映し、`private, no-store` で返す。どちらの応答にも `Vary: Cookie` を付ける。付けないと、ログインする直前に取得した一覧を、ブラウザがログインのあとも最長 60 秒使い回す。

スライドのページは、ログインした人には `Cache-Control: private, no-cache` で返す(その人のミュートで一覧が変わるため)。ログインしていない人には、これまでどおり `no-cache` で返す。

## 入口と解除

| 経路 | 内容 |
| --- | --- |
| viewer の「⋯」メニュー | ログイン中の読者が別の作者のスライドを開くと「この作者をミュート」を表示する。リンクのタイトルで一覧から外れることを説明する。ミュート中は「ミュート中」と「解除」を表示する。停止中の読者にはどちらの操作も出さない |
| `GET /mutes/new?handle=<handle>&slide=<共有 URL の path>` | だれをミュートするかと、ミュートすると何が起きるかを示すページ。ここに送信の form がある。ログインしていなければ、ログインの案内(戻り先は、そのスライド)を 401 で返す。存在しない handle、形の違う handle、自分自身は 404 |
| `POST /mutes` | ミュートを保存する。通常のフォーム送信では 303 で元のスライドへ戻る。戻り先は、共有 URL の形だけを受け付け、それ以外は `/slides` にする |
| `POST /mutes/:handle/release` | 自分がしたミュートを消す。通常のフォーム送信では 303 で `/settings` へ戻る |
| 設定のページ(`/settings`) | ミュートしている人の一覧と、解除のボタン |

viewer の `/share.js` は、フォローと同じように、リンクを押すと同じ origin にフォーム形式で POST する。サーバーは `Accept` に `application/json` があれば、操作後の保存状態を 200 と `{"muted":true}` または `{"muted":false}` で返す。ミュート先が停止中・不明・自分自身なら `false`、未ログインなら 401 と `{"error":"sign_in"}` を返す。これらの JSON 応答には `Cache-Control: no-store` を付ける。

要求した状態が応答で確認できたら、ページ番号、開いたメニュー、操作したリンクのフォーカスを保ったまま表示を切り替える。ミュート中は作者名の横のフォロー操作を隠し、解除したら「フォロー」を再表示する。再読み込み時は、サーバーが保存状態から同じ表示を作る。

ミュート・解除に成功したら、viewer は読んでいるページの URL から、ログイン中の読者に返す HTML をキャッシュを使わずに再取得する。スライドの下にある引用元・引用先の置き場所(`data-reader-lists`)を、一覧ごとに差し替える。読んでいるスライドとメニューはそのまま残る。一覧は表紙のカード(リンクと画像)だけで、枠で動くスライドは含まない。取得した HTML に枠があれば、差し替える前に取り除く。カードと「ほか N 件」の数が入れ替わることは、`src/share/viewer.browser.test.ts` がブラウザで確かめる。更新が終わるまで、次のミュート・フォロー操作を待つ。

viewer の CSP は、許可する配信元を `frame-src` に列挙する。ページを開いたときに全 iframe の配信元を記録し、一覧を差し替える際は、記録済みの配信元だけを読み込む。ページのポリシーで許可を確認できない配信元の iframe は読み込まず、サービスに表紙があれば表紙を、なければ同じ大きさの空枠を表示し、どちらも発表へのリンクを残す。表紙（`/covers/<deployment id>.jpg`）の取得に失敗した場合も空枠を保つ。読者がスライド内のリンクで別のページへ進み、その位置が viewer の URL に反映されていなくても、一覧の差し替えで読む位置は変わらない。

一覧の HTML を取得できない場合、応答が 200 以外の場合、必要な一覧の領域がそろわない場合に限り、同じ URL を開き直す（`location.replace(location.href)`）。この場合はスライド内の位置を失うことがあるが、保存済みのミュートに合った一覧を表示できる。Firefox は `location.reload()` で各 iframe の前の文書を枠の位置に従って復元するため、一覧の順序が変わると別の発表を復元しようとする。同じ URL を開き直すことで、新しい HTML どおりに各枠を読み込む。

スクリプトが無効なとき、操作の POST に失敗したとき、その応答で要求した状態を確認できないときは、リンク先で操作できる。ミュートのリンクは読んでいるページを戻り先にした確認ページ、解除のリンクは `/settings#mutes` を開く。

どちらの POST もフォームの本文だけを受け付け、ほかの形式は 415 で返す。フォームの送信には CSRF の検査とログインが要る。停止中の人は、ログインしている人を引く所で拒否される([アカウントの停止の実装設計](f17-suspension.md#停止中の本人))。頻度の制限は、`management` の組に入る。

ミュートされた人の画面と応答は、ミュートの前後で変わらない。`src/mutes/routes.test.ts` が、ミュートされた人が開く 5 つの画面(自分のスライド、相手のスライド、自分のプロフィール、設定、管理画面)を、前後で比べる。
