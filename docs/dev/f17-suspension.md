# アカウントの停止の実装設計

[知らない人のスライドも、安心して開ける](../features/f17-safe-viewing.md) のうち、運営がアカウントを停止する部分を実装するための契約。スライドごとの非表示は [運営による非表示の実装設計](f17-takedown.md) を使い、ここでは停止の状態と、それが何を止めるかを扱う。

## 停止の状態

停止は、表 `suspensions` の行で持つ。行があれば停止中、なければ通常である。

| 列 | 内容 |
| --- | --- |
| `user_id` | 利用者の id(Better Auth の `auth_user.id`)。主キー。`decks.owner_user_id` と同じ値 |
| `reason` | 運営が書いた理由 |
| `suspended_at` | 停止した日時 |
| `suspended_by` | 操作者(Cloudflare Access で確かめた本人) |

`accounts` を参照しない。退会すると `accounts` の行は消えるが、停止の行は残す。同じ利用者の id で入り直しても、停止中のままにするためである。

スライドの公開状態と、スライドごとの非表示(`decks.hidden_at` など)は、停止しても変えない。停止の行を消すと、スライドは停止の前の状態に戻る。運営が個別に非表示にしたスライドは、非表示のままである。

## 止めるもの

読者向けの query は、すべて `src/publication/takedown-store.ts` の条件 `notHidden` を付けている。この条件に、「持ち主が停止中でない」(`src/publication/suspension-store.ts` の `notSuspended`)を含めた。読者向けの経路は、1 か所で止まる。

| 経路 | 停止中の結果 |
| --- | --- |
| 共有 URL、配信、表紙、公開スライドの一覧、引用の一覧 | スライドごとの非表示と同じ。内部の cache が温まっていても、直後の request から拒否する |
| プロフィール(`/@handle`) | 存在しない handle と同じ応答 |
| CI のアップロード(開始、受信、finalize) | 拒否する。登録から外した人と同じ扱い |
| 作者の公開・再開の操作 | 公開状態は変わらない。応答は `not_publishable` になる |

運営の画面の検索(非表示の一覧、通報の一覧)は、`notHidden` を使わないので、停止中の人のスライドも出る。

読者向けの query を足すときは、`notHidden` を付ける。付けていない source は、`src/share/takedown-readers.test.ts` が見つける。

## 運営の画面

運営の画面([運営による非表示の実装設計](f17-takedown.md#運営の画面))に、次の経路がある。守り方(Cloudflare Access の token の検証、`Origin` の検査)は、非表示と同じである。

| 経路 | 内容 |
| --- | --- |
| `GET /` | 停止の form と、停止中のアカウントの一覧(アカウント、理由、日時、操作者)。新しい順に、すべて出す。解除は一覧からしか行えないので、件数で切らない |
| `POST /suspensions` | `@handle`、またはプロフィールの URL で指したアカウントを、理由を付けて停止する |
| `POST /suspensions/:user/release` | 利用者の id で指したアカウントの停止を解除する |

- 理由の決まりは、非表示の理由と同じである(前後の空白を除いて 1〜500 文字)。
- 停止中のアカウントをもう一度停止しても、変わらない。最初の理由・日時・操作者を保つ。2 人の運営が同時に停止しても、行は 1 つである。
- 解除は、行を消す。履歴は残さない。解除は、判定のもとにした停止(理由・日時・操作者)と一致する行だけを消す。解除の判定のあとに、別の解除と新しい停止が入っても、新しい停止は消えない。
- 退会した人は `accounts` に行がないので、一覧には利用者の id で出す。handle では指せないが、一覧から解除できる。退会した人を、あとから停止することはできない。

判定は `src/publication/suspension.ts` の純粋な関数で行い、保存は `src/publication/suspension-store.ts` が行う。入力の解析は `src/operator/suspension-target.ts` にある。

## 停止中の本人

停止中の人は、ログインできる。ログインしている人がだれかを引く関数(`src/auth/owner-middleware.ts` の `currentOwner` と `requireOwner`)が、停止中の人を既定で拒否する。経路ごとに検査を足す必要はなく、あとから足す経路も、何もしなければ停止中の人を拒否する。

拒否は、型のついたエラー(`SuspendedOwnerError`)を投げて行い、`src/app/routes.tsx` の `onError` が応答に変える。

| 経路 | 応答 |
| --- | --- |
| ページと form | 403 と、停止中のページ(`src/auth/suspension-pages.ts`)。停止中であること、理由、日時、問い合わせ先、退会の form、ログアウトを出す。操作者は出さない |
| `/api/` の下 | 403 と `{ "error": "Account suspended" }` |

停止中でも通すのは、明示して許可した次の経路だけである(`allowSuspended`、`requireOwnerEvenSuspended`)。

| 経路 | 理由 |
| --- | --- |
| `POST /account/delete` | 退会できるようにする。処理は、停止していない人の退会と同じ |
| プロフィール(`/@handle`)の表示 | 「自分のプロフィールか」を見るだけ。停止中の人も、ほかの人のページを読める |
| スライドのページ(`/@handle/slug`)と、トップページの一覧の API(`/api/public/slides`) | だれでも読めるページで、見ている人のミュートを効かせるために、だれかを見るだけ([ミュートの実装設計](f19-mute.md)) |

ログアウト(`POST /auth/logout`)は、この関数を通らないので、停止中でも使える。`owner-session.ts` の `ownerSession` を直接使う経路は、ない。

退会しても、停止の行は残る。同じメールアドレスでログインし直すと(利用者の id は変わらない)、同じ理由で停止中のページになる。

経路を足して、停止中の人にも使わせたいときは、明示して許可し、上の表に足す。
