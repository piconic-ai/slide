# お知らせの実装設計

[知りたい出来事が、お知らせに届く](../features/f20-notifications.md)ための配信と、本人が一覧・未読件数・受信設定を確認する画面を扱う。

## 保存するもの

| テーブル | 内容 |
| --- | --- |
| `notifications` | 1 行が 1 件のお知らせ。`recipient_user_id` は受け手、`actor_user_id` は出来事を起こした人の利用者の id。`created_at` は到着時刻で、`read_at` が NULL の間は未読。 |
| `notification_opt_outs` | ユーザー ID と受け取らない種類の組。行がなければ、その種類を受け取る。 |

引用のお知らせ（`cited`）では、`deck_id` が引用したスライド、`target_deck_id` が引用されたスライドを指す。受け手、種類、相手、双方のスライド ID の組に一意索引を置く。ページ番号と版はこの組に含めない。スライドを持たない種類でも重複を防げるよう、索引では NULL の ID を空文字列として扱う。

## 公開時に引用を知らせる条件

1. アップロードの確定時に、HTML から見つけた共有 URL を版ごとに `citations` に記録する。
2. 作者または CI の公開状態の更新が成立し、更新後が一般公開なら、その時点の公開版の引用を読む。リンクの handle から作者を特定し、その作者と slug から削除されていない引用先を特定する。引用先が下書きでも、作者には届く。
3. 自分のスライドへの引用、受け手が引用元の作者をミュートしている場合、受け手が引用のお知らせを止めている場合は記録しない。対象の選択と通知の挿入は 1 つの SQL 文で行う。

同じスライドの複数ページを引用した場合も、版の更新や公開の再開で同じ組が再び見つかった場合も、最初の 1 件を保つ。通知の書き込みに失敗した場合は `notifications_unrecorded` と引用元のスライド ID、エラー名をログに残す。公開の更新はそのまま成立する。

## slide でフォローされたときと、相手が初公開したとき

| 種類 | 配信する時点と宛先 | 重複を防ぐ単位 |
| --- | --- | --- |
| `followed` | フォローを新しく保存したら、フォローされた本人へ届ける。相手はフォローした人 | 受け手とフォローした人。解除後に再びフォローしても、すでに届いた行を保つ |
| `followee_published` | 手動または CI でスライドを初めて一般公開したら、配信時点でその作者をフォローしている人へ届ける。`deck_id` は公開したスライド | 受け手、作者、スライド。版の更新や公開再開では配信しない |

どちらも、受け手が相手をミュートしている場合と、その種類を受け取らない設定にしている場合は、挿入の時点で除く。通知の失敗は `notifications_unrecorded` として記録し、成立したフォローと公開は保つ。引用と初公開の通知は個別に試みる。[フォローの実装設計](f21-follow.md)に、初公開を判定するバッチと移行前のスライドの扱いがある。

## コミュニティに新しいスライドが入ったとき

種類 `community_published`(migration `0060_community_notifications.sql`)。`deck_id` は入ったスライド、`actor_user_id` はその作者、`community_id` は文に添えるコミュニティ(F20-AC15〜AC18)。`notifications` に列 `community_id`(`communities.id` を参照)を足すため、CHECK を変えられない SQLite の事情で、表を作り直した(全行を写す)。第三スコープの「足すだけ」(D-04)の例外で、`src/db/scope3-migrations.test.ts` に名前を挙げて許している。行は消えないが、migration の扱いは依頼者の確認を待つ。

`notifyCommunityPublished`(`src/notifications/store.ts`)は、1 つの INSERT … SELECT で、次を行う。

- 受け手は、`community_follows` の人。コミュニティが「入る」かは、読むときに `inCommunity`(`src/communities/store.ts`。D-35。保存しない)で判断する。
- 対象は、`deckId` のスライドのうち、準備のできた公開の版があり、削除も非表示もされていないもの。
- 作者本人は除く(`cf.user_id <> decks.owner_user_id`)。作者がコミュニティを作ると、そのコミュニティを自動でフォローする(F31-AC17)ため、除かないと `notification_other_user` の CHECK で文全体が失敗する。
- ミュート、ブロック(受け手が作者を、または作者が受け手を)、受け取らない設定の人は除く。ブロックは、コミュニティのフォローを外さない(F31-AC12)ため、作者から受け手へのブロックも、ここで見る。
- 同じ人が複数のコミュニティをフォローしていても、1 件にする。添えるコミュニティは、受け手が最初にフォローしたもの(`ROW_NUMBER()` の並びは、トップの新着の `feed-store.ts` と同じ)。
- 重複は、部分一意索引 `notifications_deck_once`(受け手とスライド。`followee_published` と `community_published` にだけ)と `ON CONFLICT DO NOTHING` で防ぐ。人としてフォローしている作者のスライドは、先に届いた方の 1 件だけになる。

呼び出す場所は 2 つ(経路は 4 つ)。

| 契機 | 場所 | 失敗 |
| --- | --- | --- |
| 初めての一般公開 | `saveTransition`(`src/publication/store.ts`)の、`followee_published` を配信する分岐の直後 | ログ(`notifications_unrecorded`)だけで、公開は成立する |
| 一般公開中のスライドへの、イベントの関連リンクの追加と、種類の変更 | `src/decks/routes.ts` の `POST /my/slides/:deck/links` と `/links/kinds`、`src/mcp/article-api.ts` の `add_related_link`(`notifyCommunityPublishedQuietly`) | ログだけで、リンクの追加は成立する |

リンクの追加と種類の変更では、そのイベントのキー(`eventKey`)を渡し、そのイベントでコミュニティに入る場合だけ知らせる。スライドが前から入っているコミュニティに、あとからフォローした人へは、無関係なリンクの追加では届けない。初公開では、スライドのすべてのイベントを見る。

コミュニティの管理者の紐づけ用リンクの追加、Luma のカレンダーの取り込みは、呼び出さない(F20-AC18)。版の更新、再開、取り消し後の再公開でも呼び出さない。`inCommunity` の結合は、`related_link_events` の `host` の索引(`related_link_events_host`)を使う(`src/notifications/community-published.test.ts` が EXPLAIN で確かめる)。

一覧と未読件数では、`community_published` を `followee_published` と同じ条件(スライドが一般公開中で、削除も非表示もされていない)で表示する(F20-AC10)。一覧は、コミュニティの名前とハンドルを左結合で読む。コミュニティを削除すると、そのお知らせも消える(`deleteCommunity`)。退会は、既存の削除(受け手または相手のお知らせ)で足りる。

## 取り除いた種類

「GitHub でフォローしている人が参加した」お知らせは、第二スコープで取り除いた(F28-AC28。migration `0038`)。GitHub のログインがなくなったため、種類、設定の項目、文言、`notifications` の種類の値を残さない。slide でのフォローと GitHub のフォロー関係はつなげない。

## 一覧と未読件数

どちらも受け手の ID で絞り、同じ表示条件を使う。

- 相手のアカウントがあり、相手が停止中でなく、受け手が相手をミュートしていないこと。
- 引用、初公開、コミュニティの場合、お知らせから開くスライドが一般公開中で、削除も運営による非表示もされていないこと。引用の場合は引用先も、削除されておらず、運営の非表示の対象でないこと。

一覧は到着の新しい順に読む。題名は読み取った時点の各スライドの公開版から取得し、公開版や題名がなければ NULL になる。未読件数は表示できる行のうち `read_at` が NULL のものを数える。ミュートや非表示、停止の解除後は、ほかの条件も満たせば以前のお知らせが再び表示される。受信設定の変更は次の配信から効く。

一括既読は、その時点で表示できる未読のお知らせに既読時刻を記録し、すでにある既読時刻を保つ。ミュートや停止で表示から外れているお知らせは、未読のまま残る。

## 画面と受信設定

- `GET /my/slides` の「お知らせ」リンクは、本人に未読があるときだけ件数を併記する。管理画面を開くだけでは既読にならない。
- `GET /notifications` は、先に 1 つの文で一括既読にし、そのとき既読になった項目を控えてから、本人に表示できる最新 50 件を取得する。この応答では、控えた項目に「新着」が付く。既読にしたあとに届いたお知らせは、未読のまま残る。既読にする対象には 51 件目以降も含む。各項目には東京の日付がある。引用と初公開ではそのスライド、参加とフォローでは相手のプロフィールにリンクする。題名のないスライドには slug を表示する。
- `GET /settings#notifications` の「お知らせ」では、引用、slide でフォローしている人の初公開、自分へのフォロー、フォローしているコミュニティに入った新しいスライドについて、それぞれ受信設定を確認できる。既定はすべて「受け取る」。
- 各種類のフォームは `POST /notifications/preferences` に `kind` と変更後の `receive`（`1` または `0`）を送る。フォーム以外の形式は 415 で拒否する。フォームを受けたら同一オリジンを検査し、本人の設定を更新して `/settings#notifications` に戻る。未対応の種類や値では設定を変更しない。

未ログインで一覧を開くと 401 とログインの案内が返る。ログインが切れた状態で設定を送信すると `/settings` に戻る。停止中の本人には、どちらの操作でも 403 と停止中の画面が返る。

## 退会時の削除

`src/decks/deletion-store.ts` の `markAccountDeleted` は、退会する人が受け手または相手のお知らせと、その人の受信設定を、アカウントを削除するのと同じ D1 バッチで消す。
