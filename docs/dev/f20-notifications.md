# お知らせの実装設計

[知りたい出来事が、お知らせに届く](../features/f20-notifications.md)のうち、引用と参加のお知らせの配信と、本人が一覧・未読件数・受信設定を確認する画面を扱う。

## 保存するもの

| テーブル | 内容 |
| --- | --- |
| `notifications` | 1 行が 1 件のお知らせ。`recipient_user_id` は受け手、`actor_user_id` は出来事を起こした人の GitHub ユーザー ID。`created_at` は到着時刻で、`read_at` が NULL の間は未読。 |
| `notification_opt_outs` | ユーザー ID と受け取らない種類の組。行がなければ、その種類を受け取る。 |

引用のお知らせ（`cited`）では、`deck_id` が引用したスライド、`target_deck_id` が引用されたスライドを指す。受け手、種類、相手、双方のスライド ID の組に一意索引を置く。ページ番号と版はこの組に含めない。スライドを持たない種類でも重複を防げるよう、索引では NULL の ID を空文字列として扱う。

## 公開時に届ける条件

1. アップロードの確定時に、HTML から見つけた共有 URL を版ごとに `citations` に記録する。
2. 作者または CI の公開状態の更新が成立し、更新後が一般公開なら、その時点の公開版の引用を読む。リンクの handle から作者を特定し、その作者と slug から削除されていない引用先を特定する。引用先が下書きでも、作者には届く。
3. 自分のスライドへの引用、受け手が引用元の作者をミュートしている場合、受け手が引用のお知らせを止めている場合は記録しない。対象の選択と通知の挿入は 1 つの SQL 文で行う。

同じスライドの複数ページを引用した場合も、版の更新や公開の再開で同じ組が再び見つかった場合も、最初の 1 件を保つ。通知の書き込みに失敗した場合は `notifications_unrecorded` と引用元のスライド ID、エラー名をログに残す。公開の更新はそのまま成立する。

## GitHub でフォローしている人が参加したとき

1. GitHub ログインの callback で、セッションを作る前に、参加者の GitHub ユーザー ID で `accounts` を確認する。行がなく、セッションが発行され、その後に行がある場合を初回とする。ハンドルが付かない間は照会せず、後のログインで初めてハンドルが付いたときに知らせる。退会後の再参加も同じ条件で扱う。ログインの拒否時やリポジトリ接続時には照会しない。
2. プロフィールの保存処理の後、`accounts` と `profiles` の両方に行がある人から、参加者本人と停止中の人を除く。登録が古い順に最大 50 人を選び、同じ登録時刻ならユーザー ID 順にする。
3. 参加者のトークンが有効なうちに、対象者ごとに `GET /users/{対象者の現在の login}/following/{参加者の login}` を並行して呼ぶ。照会全体で 3 秒の期限を共有し、GitHub が `204` を返した人に届ける。`404` はフォローなしとして扱う。通信エラーやタイムアウトがあっても、ほかの人の `204` は有効で、ログインは成立する。
4. 参加者をミュートしている人と、この種類を受け取らない設定の人を除き、1 つの SQL 文で `github_followee_joined` を記録する。書き込み時にも双方のアカウントの存在を確かめ、同じ受け手・参加者の通知がすでにあればその 1 件を保つ。照会や記録に失敗したときは、`join_notifications_unrecorded` とエラー名をログに残す。トークンは callback の最後に失効させる。

この上限は招待制の期間に使う。フォロー一覧のページ送り、失敗の再試行、過去の参加や後から始めたフォローへの遡及配信は行わない。GitHub のフォロー関係は保存せず、slide での自動フォローも行わない。受信設定は受け手が選び、参加者が自分の参加を知らせない設定は設けない。

## 一覧と未読件数

どちらも受け手の ID で絞り、同じ表示条件を使う。

- 相手のアカウントがあり、相手が停止中でなく、受け手が相手をミュートしていないこと。
- 引用の場合、引用元が削除されておらず、一般公開中で、運営の非表示の対象でないこと。引用先も、削除されておらず、運営の非表示の対象でないこと。

一覧は到着の新しい順に読む。題名は読み取った時点の各スライドの公開版から取得し、公開版や題名がなければ NULL になる。未読件数は表示できる行のうち `read_at` が NULL のものを数える。ミュートや非表示、停止の解除後は、ほかの条件も満たせば以前のお知らせが再び表示される。受信設定の変更は次の配信から効く。

一括既読は、その時点で表示できる未読のお知らせに既読時刻を記録し、すでにある既読時刻を保つ。ミュートや停止で表示から外れているお知らせは、未読のまま残る。

## 画面と受信設定

- `GET /slides` の「お知らせ」リンクは、本人に未読があるときだけ件数を併記する。管理画面を開くだけでは既読にならない。
- `GET /notifications` は、本人に表示できる最新 50 件を取得してから一括既読にする。この応答では、取得時に未読だった項目に「新着」が付く。既読にする対象には 51 件目以降も含む。各項目には東京の日付と、引用元のスライドまたは参加した人のプロフィールへのリンクがある。引用元・引用先の題名がなければ、それぞれの slug を表示する。
- `GET /settings#notifications` の「お知らせ」では、引用と GitHub でフォローしている人の参加について、現在の受信設定を確認できる。どちらも既定は「受け取る」。
- 各種類のフォームは `POST /notifications/preferences` に `kind` と変更後の `receive`（`1` または `0`）を送る。同一オリジンを検査し、本人の設定を更新して `/settings#notifications` に戻る。未対応の種類や値では設定を変更しない。

未ログインで一覧を開くと 401 とログインの案内が返る。ログインが切れた状態で設定を送信すると `/settings` に戻る。停止中の本人には、どちらの操作でも 403 と停止中の画面が返る。

## 退会時の削除

`src/decks/deletion-store.ts` の `markAccountDeleted` は、退会する人が受け手または相手のお知らせと、その人の受信設定を、アカウントを削除するのと同じ D1 バッチで消す。
