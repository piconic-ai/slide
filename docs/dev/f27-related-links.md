# 関連リンクの実装設計

[関連リンクを紐付ける](../features/f27-related-links.md)の設計。作者がスライドに足した録画やブログのリンクを、viewer の題名の下に並べる。題名は任意で、入れなければサイト名を出す。リンク先へは問い合わせない。リンクを引用として数えない。

## ファイルの分担

| ファイル | 層 | 役割 |
| --- | --- | --- |
| `src/links/link.ts` | 純粋 | 種類、上限、URL と題名の検査(`parseLinkInput`。URL は `src/share/https-url.ts` の `parseHttpsUrl` で、プロフィールのリンクと共有する)、サイト名(`siteNameOf`)、画面に戻すときの理由の解析 |
| `src/links/kind-hosts.ts` | 純粋(データ) | 動画と記事のホスト名の一覧。足すときは 1 行足す |
| `src/links/kind.ts` | 純粋 | URL から種類を決める(`kindOfUrl`)。ホスト名と、その下のサブドメインで比べる |
| `src/links/link-parts.ts` | 純粋 | 種類の名前(日本語と英語)と、種類のアイコン |
| `src/links/store.ts` | store | 一覧、追加、外す。上限と持ち主の確認は SQL に含める |
| `src/decks/links-frame.ts` | 純粋(HTML の部品) | 1 本の管理の「関連リンク」の枠 |
| `src/share/viewer-links-frame.ts` | 純粋(HTML の部品) | viewer の「関連リンク」の節 |
| `src/decks/routes.ts` | routes | `POST /slides/:deck/links`、`POST /slides/:deck/links/:link/delete` |

## 表

`related_links`(migration 0039)は、スライド(`deck_id`)に属する。版には属さないので、版を差し替えても残る(F27-AC14)。

| 列 | 内容 |
| --- | --- |
| `id` | リンクの鍵(UUID)。「外す」が指す |
| `deck_id` | スライド。`decks` を参照する |
| `kind` | `video`、`article`、`other`。CHECK で縛る。足すときに URL から決める(F27-AC34)。表の形は変えていない |
| `url` | 正規化した `https:` の URL |
| `title` | 題名。作者が入れた 1〜100 文字(CHECK)。入れなかったときは NULL(migration 0045 で NOT NULL を外した)。画面は NULL のとき、サイト名だけを出す |
| `position` | 足すたびに最大値 + 1。外しても詰めず、再利用しない。並びは `position` の昇順 |
| `created_at` | 足した時刻 |

`(deck_id, position)` は一意。並べ替えは作らない(D-52)。

## 足す

`addLink` は、持ち主の確認、スライドの存在、10 件の上限を、1 つの `INSERT ... SELECT ... WHERE` に含める。事前に件数を数えて足すと、同時の追加が上限を超えうるためである(`src/links/links.test.ts` に同時の追加のテストがある)。0 行しか入らなかったときは、スライドが自分のもので生きているかを引き直して、`full`(上限)と `missing`(ほかの人のもの、無い、削除済み)を分ける。`missing` は、スライドが無いときと同じ 404 で答える(F27-AC13)。

「外す」も、リンクの鍵とスライドと持ち主を 1 つの `DELETE` の条件にする。

## URL と題名の検査

境界(routes)で `parseLinkInput` を 1 度だけ通し、store には解析済みの値を渡す。

- URL は、前後の空白を除いたうえで、空白と制御文字を含むものを断る。URL の解析は、途中の tab や改行を黙って取り除くので、解析の前に見る。
- 2,000 文字を超えるもの、`new URL` が解析できないもの、`https:` 以外(`http:`、`javascript:`、`data:`、`//host`、スキームの無いもの)、利用者名やパスワードを含むものを断る。保存するのは `URL.href` の正規の綴りである。
- 題名は任意。前後の空白を除いて空なら、題名なし(`title: null`)にする。入力があるときは、1〜100 文字(コードポイントで数える。絵文字は 1 文字)。制御文字(改行、C1 を含む。`\p{Cc}`)、書式文字(ゼロ幅スペース、左右の向きの印と上書き。`\p{Cf}`)、行と段落の区切り(U+2028、U+2029)は断る(`title_invalid`)。そのうえで、見える文字が 1 つもない題名(空白、全角の空白、U+3164 や U+2800 のような空白に見える文字だけ)は、断る(`title_missing`。入力が空なのとは別で、空は断らない)。
- 断った理由は、`?links=<理由>` として管理のページへ戻して、枠の上に 1 文で出す(`role="alert"`)。入力した値は戻さない。

## 種類

足すとき、作者には選ばせず、URL のホスト名から決める(F27-AC34、AC35)。`parseLinkInput` が、`kind` が省かれたとき(無い、`null`、空)に `kindOfUrl` を呼ぶ。MCP の道具は `kind` を省いてよく、指定があればそれを使う(F27-AC36)。指定が 3 つのどれでもなければ断る(`kind`)。

- 一覧(`src/links/kind-hosts.ts`)は、動画と記事のホスト名だけ。一覧のホストと、その下のサブドメインに当たれば、その種類。当たらなければ「その他」。`speakerdeck.com` のように、一覧にないものは「その他」で足りるので、書かない。
- 比べるのは `new URL(...).hostname`(小文字、国際化ドメイン名は punycode)。そのため、見た目が似た別のドメイン(キリル文字の `у` を使った `уoutube.com` など)は一覧と一致せず、「その他」になる。末尾の `notyoutube.com` や `youtube.com.example` も一致しない(`.` で区切って、ホスト名の終わりと比べる)。パスや問い合わせの文字列に一覧の名前があっても、見ない。
- 推定は、足すときの 1 回だけ。保存した後の種類は、一覧を変えても動かない。

## サイト名

URL のホスト名を、`URL.hostname` のまま出す。国際化ドメイン名は、`xn--` で始まる ASCII の綴り(punycode)になる。

- ASCII の表記で出す(2026-11-25 に依頼者が決めた。それまでは暫定の判断だった)。理由は、見た目が似た別のドメインを本物に見せる偽装(ホモグラフ)を、読者に見えるサイト名で許さないためである。日本語のドメインは読みにくくなる。
- `www.` は取り除かない。

## 同じ URL

- いまは、同じ URL を 2 件足すことを、断らずに許している。2026-11-25 に依頼者が、断ることに決めた(F27-AC44〜F27-AC49、F23-AC39、F23-AC40)。入れたとおりの URL と正規化した URL の両方を持ち、正規化した URL で比べる。作り直すときは、`parseLinkInput` ではなく store の条件に足す。正規化の規則は、仕様の未決事項にある(提案の表)。同じ日に、href に使う URL を整える(追跡用のクエリと Luma の `tk` を除く)ことと、押したときの確認の画面も決めた(F27-AC50〜F27-AC59)。入れたとおり・整えた・正規化した、の 3 つの形を持つ。

## 見せる

viewer は、そのページを返す条件を満たす人に、リンクを出す。一般公開中のスライドは読者のだれにでも、作者のみのスライドは作者の preview だけに開くので、リンクの読み取りは版を選んだあとに、スライドの鍵で 1 回行う。ほかの人に開かない状態では、ページそのものが 404 になり、リンクは出ない(F27-AC9、AC10)。

節は、リンクが 1 件もないとき、見出しごと出さない(F27-AC11)。リンクは `rel="noopener nofollow ugc"` を付け、新しいタブでは開かない。長い題名は、1 行で切って `…` を付け、全文を `title` に入れる。サイト名も、長いときは切る。丸いリンクは横に並べて折り返し、幅 375px で横にはみ出さない(F27-AC20、ブラウザのテスト)。

viewer の CSP は変えない。リンクは移動先を開くだけで、動画は埋め込まない(D-55)。

## 取り込まないもの

- 引用として数えない(F27-AC16)。引用の検出は、版の HTML の受け取りの確定だけが呼ぶので、関連リンクの経路は引用の表に書かない(テストで、共有 URL を足しても `citations` が空のままであることを確かめる)。
- 画像は取らない。題名は足す 1 回だけで、見せるときも、あとからも取り直さない(F27-AC29)。

## 題名の自動取得はしない

一度、題名を空にして足したときだけリンク先から題名を取る仕組みを作ったが(2026-11-23。#376)、同じ日に依頼者の判断で取り除いた。connpass の利用規約(第 7 条 17 号)のように、API 以外の方法での自動のアクセスを禁じるサイトがあるためで、いずれのサイトも取得しない(F27-AC42)。

- 題名は任意。入れなければ `title` は NULL で保存し、画面はサイト名(ホスト名)だけを出す(F27-AC39)。NULL を許す列は migration 0045 のまま(適用済みで、消すものはない)。
- 追加は `addLink` を呼ぶだけで、外へは出ない。MCP の答えの `titleSource` は `given` か `none`(F27-AC41)。
- 取り除いたもの: 取得(`title-client.ts`)、HTML の解析(`title-parse.ts`)、宛先の検査(`title-policy.ts`)、取得の入口(`api.ts`)、取得の前の確認(`readAddRoom`)、作者ごとの頻度の制限(`PAGE_SHOT_RATE_LIMITER` は元の用途の、ページの撮影だけに戻した)、取った題名を整える `fetchedTitleOf`。
- 将来、取得を足すなら、サイトごとの利用規約を確かめ、API が提供されているサイトだけを対象にする。

## 消す

`src/decks/deletion-store.ts` の `deletionSteps` が、スライドを削除済みにする同じ batch で、そのリンクを消す。スライドの削除と、退会(持っているすべてのスライド)の両方に効く(F27-AC18、AC19)。削除済みのスライドには、リンクを足せない。
