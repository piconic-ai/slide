# 画面の言語

サービスの画面を日本語と英語で表示する仕組みと、英語の用語を記載する。作者の資料の翻訳は [多言語の説明](../features/f06-localization.md) で扱い、ここでは扱わない。計画と残りの範囲は [サービスの画面を日本語と英語で切り替える #100](https://github.com/piconic-ai/slide/issues/100) を参照する。

## 言語を決める

`src/site/lang.ts` の middleware が、リクエストごとに `ja` か `en` を決める。判定には Hono の `languageDetector`(`hono/language`)を使う。

1. `?lang=` の値
2. cookie `language` の値
3. `Accept-Language`(q の高い順。`en-US` は `en` として扱う)
4. どれにも当てはまらなければ `ja`

大文字や地域付きの値(`?lang=EN`、`?lang=en-US`)は `en` として扱い、そのまま cookie に保存する。対応していない値(`?lang=fr`、壊れた cookie)は無視し、次の判定に進む。たとえば `?lang=fr` で `Accept-Language: en` なら英語、何も送っていなければ日本語になる。

- cookie は、`?lang=` に対応する値が付いていたときだけ書く。`languageDetector` の既定(`caches: ['cookie']`)では判定のたびに `Set-Cookie` を返すため、`caches: false` にしている。
- cookie は `Path=/`、`SameSite=Lax`、`Secure`、`HttpOnly`、有効期間1年で、`Domain` は付けない。`Lax` にするのは、ほかのサイトのリンクから共有 URL を開いたときにも選んだ言語を使うためである。
- 管理 origin の HTML と 304 には `Vary: Accept-Language, Cookie` を付ける。言語の違う画面をキャッシュが取り違えないようにするためである。
- ハンドラーは `langOf(c)` で言語を受け取る。

## 文言を書く

文言は、画面のモジュールごとに `messages()`(`src/site/i18n.ts`)で言語ごとの辞書として持つ。日本語の辞書が形を決め、英語の辞書にキーの欠けや余分なキーがあると型検査で失敗する。入れ子の辞書の余分なキーも検出する。型を明示して `messages<T>()` に渡す辞書は、変数側の型注釈で検査する。数や名前を差し込む文言は、引数を受け取る関数にする。

- サービス名は `SERVICE_NAME`(`src/site/service.ts`)から差し込む。名前が決まるまで([#14](https://github.com/piconic-ai/slide/issues/14))辞書に直接書かない。
- API のエラー文言と upload の CLI の出力は英語のままにする。
- 英語の画面に日本語だけで書いたものを出すとき(言語の切り替えの「日本語」、規約の本文の仮の目次)は、その要素に `lang="ja"` を付ける。
- 英語の文言がまだない画面は、フッターも日本語で出す。1 つのページの中で言語が混ざらないようにするためである。
- 英語の画面に日本語が残っていないことは、`japaneseOutside()`(`src/site/test-japanese.ts`)でテストする。`lang="ja"` の要素の中と、script・style は対象外になる。作者が入力した題名などは、テストの入力を英語にして確かめる。

## 切り替える

全ページのフッターに「日本語 / English」を置く(`siteFooter()`、`src/site/footer.ts`)。今の言語は文字だけで、もう一方は今のページに `?lang=` を付けたリンクになる。URL の path では言語を分けない。共有 URL(`/@handle/deck`)を変えないためである。

## 用語

英語の画面では、次の訳語を使う。機械翻訳ではなく、画面ごとに読み直して決める。

| 日本語 | 英語 | 説明 |
| --- | --- | --- |
| デッキ | deck | 作者が送るスライド一式の単位 |
| 版 | version | 1回の送信で受け取ったファイル一式(実装上の deployment) |
| 受領・受領完了 | received | 版のファイルをすべて受け取り終えたこと |
| 受信中 | receiving | 版のファイルを受け取っている途中 |
| 受領履歴 | upload history | デッキが受け取った版の一覧 |
| 下書き | draft | 受領したが一般公開していない版 |
| 一般公開 | public | 誰でも共有 URL で読める状態。操作は publish |
| 公開停止 | paused | 一般公開を一時的に止めた状態。操作は pause / resume |
| 作者限定(で開く) | author-only (open as author) | 作者本人だけが、下書きの版を開くこと |
| 共有 URL | share link | 読者に渡す `/@handle/deck` の URL |
| 連携 | connect | デッキとリポジトリを結び付けること |
| 公開モード | publishing mode | 手動公開(manual)か、リポジトリ設定に従う(follow the repository)か |
| 配信ドメイン | content domain | 資料を管理画面と別の origin から配る domain |
| 退会 | delete account | アカウントとすべてのデッキを削除すること |

## トップページ

トップページはビルド時に言語ごとに生成する静的ファイルである(`src/site/home-page.tsx`)。文言とモックの画面は `src/share/home-ja.ts` と `src/share/home-en.ts` に、どちらも `HomeCopy` 型で書く。モックは言語ごとに中身が違うので、文言だけを差し替えるのではなく、言語ごとに書き下ろす。最近のデッキの一覧(`RecentDecks`)には `lang` を props で渡し、案内の文言と公開日の書き方を言語に合わせる。

## 公開ページ

共有 URL の viewer、作者のプロフィール、公開されていない資料の案内は、リクエストの言語で表示する。viewer は資料を画面いっぱいに出すのでフッターを置かず、ヘッダーにもう一方の言語へのリンクだけを置く(スマートフォンの幅でもヘッダーの行が増えないようにするため)。正しい綴りへの 301 では、`?lang=` を引き継ぐ。「リンクをコピー」を押したあとの表示は、`public/share.js` がボタンの `data-copied` から読む。

トップページ、viewer、プロフィールの応答には、検索エンジン向けに `Link` ヘッダーで言語ごとの URL を付ける。

```
Link: <https://slide.piconic.ai/@handle/deck?lang=ja>; rel="alternate"; hreflang="ja",
      <https://slide.piconic.ai/@handle/deck?lang=en>; rel="alternate"; hreflang="en",
      <https://slide.piconic.ai/@handle/deck>; rel="alternate"; hreflang="x-default"
```

`<link>` 要素ではなくヘッダーにするのは、トップページがビルド時に作る静的ファイルで、公開時の origin(`PUBLIC_ORIGIN`)を知らないためである。各 URL は path に `lang` だけを付けたもので、ほかのクエリ(`utm_source` など)は含めない。`x-default` は `lang` のない URL で、ブラウザの設定から言語を選ぶ。公開されていない資料の 404 には付けない。
