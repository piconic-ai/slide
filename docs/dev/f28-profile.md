# プロフィールとプロフィール画像の実装設計

[メールのコードでログインする](../features/f28-email-login.md) のうち、プロフィールを書くこととプロフィール画像(F28-AC35〜F28-AC54)、[気になる人をフォローする](../features/f21-follow.md) のうちプロフィールに出るもの(F21-AC57〜F21-AC60)を実装するための契約。ログインと利用者の識別子は [メールのコードでログインする実装設計](f28-email-login.md) にある。

状態: 実装した(第二スコープの作業 A2、2026-11-22)。PR を 4 本に分けて積んだ。下の「PR の分け方」に、どの PR がどの条件を満たすかを書く。

## データ

利用者の識別子は `auth_user.id`(サービスが発行する)。プロフィールの表は、すべてこの id を持つ。

| 表 | 列 | 決まり |
| --- | --- | --- |
| `profiles`(0037) | `user_id`、`name`、`bio`、`location`、`website` | 表示名は必須で 1〜50 文字。自己紹介は 160 文字まで、場所は 50 文字まで、Web サイトは 2048 文字まで。空の項目は、空文字でなく NULL で持つ。長さは表の CHECK でも守る |
| `profiles`(0042 で足す) | `use_gravatar` | 0 か 1。既定は 1(F28-AC47) |
| `profile_links`(0042) | `user_id`、`position`(1〜3)、`url` | SNS のリンク。書いた順。主キーは `(user_id, position)` なので、4 つ目は表にも入らない |
| `profile_pictures`(0043) | `user_id`、`uploaded_at` | アップロードした画像があるかを表す。画像の中身は R2 の `avatars/<user_id>` にある |
| `picture_removals`(0043) | `id`、`user_id`、`removed_by`、`reason`、`removed_at` | 運営が画像を外した記録(F28-AC51)。外した後も残す |

migration は 0042(リンクと切り替え)と 0043(画像と運営の記録)の 2 本。どちらも足すだけで、適用済みのファイルは変えない。

## 入力の検査(D-30)

`src/profile/profile-input.ts` は純粋な関数で、フォームの値を受け取り、保存できる値か、直す点の一覧を返す。直す点は、項目ごとの判別可能な union(`ProfileProblem`)で、文言は画面の側が日本語・英語で持つ。1 つ直すたびに次の点が出る、という往復をなくすため、問題は全部まとめて返す。

| 項目 | 決まり |
| --- | --- |
| 表示名 | 必須。前後の空白と、見えない文字(制御文字、ゼロ幅スペース、向きを変える記号)を取ると、1 文字以上 50 文字以下 |
| 自己紹介 | 160 文字以下 |
| 場所 | 50 文字以下 |
| Web サイト | 1 つ。`https:` の URL |
| SNS のリンク | 3 つまで。それぞれ `https:` の URL。空の欄は数えない |

- 長さは、コードポイントで数える(絵文字は 1 文字)。SQLite の `length()` も文字で数えるので、表の CHECK と食い違わない。ちょうどの長さは保存できる。
- 一行の項目は、見えない文字と改行を空白 1 つにし、空白の連続を 1 つにする。孤立したサロゲートは U+FFFD にする。絵文字の連結に使うゼロ幅の接合子(U+200C、U+200D)は残す。
- URL は、利用者が書いたとおりに `new URL` で読み、`https:` で、ホスト名に `.` があり、ユーザー名とパスワードがないものだけを受け付ける。scheme のない `example.com` は受け付けない(理由は「`https://` から書いてください」)。保存するのは、読み出した形(`href`)。2048 文字を超えるものは断る。
- 自己紹介は HTML として扱わない。保存した文字をそのままエスケープして出す(F28-AC40)。
- 保存した値も境界で検証し直す。読むときに、`https:` でない URL は「なし」にし、自己紹介は上限で切る。D1 を直接書き換えた値が、リンクにならないようにするため。
- 本文の大きさ: 1 つの項目から読むのは 1 万文字まで。それを超えるものは、切っても上限を超えているので、必ず断られる。SNS の欄は 50 まで読む。

### 自己紹介の改行(暫定)

改行の扱いは、仕様の未決事項(F28)である。第二スコープでは、**改行を残す**ことにしている(暫定。依頼者の確認を待つ)。改行はすべて `\n` にそろえ、3 つ以上の連続は空行 1 つにする。行の前後の空白は取る。表示は `white-space: pre-line` で、自己紹介の中の改行だけが改行になる。決まったら、`multiLineOf` を変えるだけで切り替えられる。

## 設定の画面

- 「プロフィール」の枠(`src/site/settings-profile-frame.ts`): 表示名、自己紹介、場所、Web サイト、SNS のリンク 3 欄、「保存する」。プロフィール画像の欄は、PR 2・3 で足す。
- 「アカウント」の枠(`src/site/settings-account-frame.ts`): ハンドルと、メールアドレス。「変えられません。」「自分にだけ見えます。」の注記。ログアウトのボタンはこの枠に置く。メールアドレスを出すのは、本人の設定ページだけ(D-27)。
- `POST /settings/profile` は、同じ origin からの form だけを受け、検査が通れば保存して `/settings?saved=profile#profile` へ 303 で戻す。通らなければ、400 で設定のページをもう一度描き、入力した値を残し、項目の下に理由を出す(F28-AC36〜AC39)。ログインしていなければ 401。
- 「GitHub から同期し直す」と最後に同期した日は、A1 が取り除いた。設定にないことを、テストで確かめる(F28-AC53)。

## プロフィールのページ

`profileCard` が、表示名、ハンドル、自己紹介、場所、Web サイト、SNS のリンクを出す。空の項目は、行も見出しも出さない(F21-AC60)。外へのリンクには、`rel="nofollow noopener noreferrer ugc"` を付ける。

## プロフィール画像

プロフィール画像は、アップロードした画像、Gravatar の画像、頭文字の順に使う(D-31)。決めるのはサービスの側で、ページには、プロフィール画像を配る経路の URL(`/avatars/<利用者の id>`)だけを載せる。メールアドレス、そのハッシュ、Gravatar の URL は、どのページの HTML、どの API の応答にも出さない(F28-AC48)。

| 場所 | 出し方 |
| --- | --- |
| ヘッダーのアイコン | `GET /api/session` が `avatarUrl` として経路を返し、`/share.js` が画像を重ねる |
| プロフィール、viewer の作者、フォローの一覧、設定 | サーバーが描く HTML に、頭文字の上へ `faceImage`(`src/profile/face.ts`)で画像を重ねる。どこも同じ部品を使う |

画像は、頭文字の上に重ねる。画像が 404 のとき(プロフィール画像が無い人)と読めないとき、`/share.js` が画像を隠すので、頭文字が見える。壊れた画像の印は出ない。お知らせと表紙のカードは、プロフィール画像を出さない。

### 配信の経路

`GET /avatars/:userId`(`src/profile/face-routes.ts`)。ログインは要らない。

1. `:userId` がサービスの id の形(英数字と `_`、`-`、64 文字まで)でなければ 404。メールアドレスの形(`@` や `.` を含む)は、ここで断る。
2. アカウントがなければ 404。人がいない場合と、プロフィール画像がない場合は、同じ 404 で、本文も空にする。id から、ほかのことが分からないようにする。
3. アップロードした画像があれば、R2 の `avatars/<id>` を返す。行があって物がないときは、次へ進む。
4. 「Gravatar の画像を使う」が入なら、Gravatar の画像を返す(下)。
5. どれもなければ 404。

応答は、画像だけを持つ。`Content-Type` は、保存した画像の型。`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、`Cache-Control: public, max-age=60`。メールアドレスやハッシュは、ヘッダーにも出さない。1 分の cache は、別のページが古い画像を出しうる長さである。設定のプレビューだけは、アドレスに `?v=<アップロードした時刻>` を付けるので、すぐ変わる。

### アップロード(D-34)

`POST /settings/picture`(multipart、同じ origin の form だけ、ログイン必須)。

- 先に、`Content-Length` が 1 MB に 64 KB を足した値を超えていれば、本文を読まずに断る。
- ファイルは、大きさ(1 MB まで)と、先頭のバイト(PNG、JPEG、WebP の印)で調べる(`picture-policy.ts`)。名前と、ブラウザが言う型は、見ない。GIF、SVG、HTML は、名前が `.png` でも断る。
- 通ったものは、「画像を縮める口」(`PictureShrinker`、`src/profile/picture-policy.ts`)に渡す。口の実装は Cloudflare Images の binding(`env.IMAGES`)の 1 つだけで、本番もローカルも同じ経路を通る(ローカルの `wrangler dev` と Vitest の `getPlatformProxy` は、Miniflare の Images の代役(sharp)で動かす)。`info` で縦横を測り(どちらも 8192 ピクセルまで)、`transform({ width: 256, height: 256, fit: 'cover' })` で 256 ピクセルの正方形(中央を切り出す)の WebP(品質 85)に書き出す(`picture-client.ts`)。元の画像のメタデータ(撮った場所など)は残らない。読めないものは「画像として読めません」と断る。PNG、JPEG、WebP のどれも、同じように縮む。
- binding がない環境では、アップロードを 503 で断る(「いま、プロフィール画像を変えられません。サービス側の準備が整うまで、しばらくお待ちください。」。利用者向けなので、原因が運営の側にあることだけを伝え、binding などの語は出さない)。元の画像を、縮めずに保存することはしない(D-34)。
- R2 の `avatars/<id>` に、縮めた画像だけを置く。元の画像は保存しない。同じ鍵に置くので、2 回目は 1 回目を置き換える。D1 の `profile_pictures` に、置いた時刻の行を置く。物を先に置き、行を後にする。
- 外す操作は `POST /settings/picture/remove`。行を先に消し、物を後に消す。行が「プロフィール画像がある」ことの正なので、物の消し損ねは、だれにも読まれない。

### 選んだらすぐアップロードする(F28-AC85〜F28-AC87)

設定のファイル欄は、「画像を選ぶ」のピルのボタン(`label.picture-pick`)で包んだ `input[type=file]` で、input 自体は見えないが、キーボードと読み上げには残る。`/share.js` の `bindPictureUpload` が、`change` で、種類(PNG、JPEG、WebP。ブラウザが種類を言わないときは送って、サービスの検査に任せる)と大きさ(1 MB)を先に確かめる。問題があれば送らず、欄を空にして、`data-` 属性で渡された、サーバーと同じ文言の理由を出す。問題がなければ、フォームを `requestSubmit()` で送る。送っている間は、2 回目の選択を送らない。スクリプトが動くときは、「画像をアップロード」のボタンを隠す。動かないときは、ボタンが残り、検査はサービスの側だけである(サーバー側の検査は、どちらでも同じに働く)。

### 片付け(F28-AC88、F28-AC89)

- 差し替え: 同じ鍵 `avatars/<id>` に置くので、前の画像は残らない。物を置いたあとに行を書けなかったときは、前に画像がなかった場合に限り、置いた物を消す(前の画像があるときは、行が前のままで、物は新しい。どちらも読まれる)。
- 外す: 行を先に消し、物を後に消す。行がなくても物を消すので、途中で止まって残った物は、外す操作(本人、運営)で片付く。
- 「Gravatar の画像を使う」を切る: 保管していた `gravatar/<id>` を消す。入のあいだは、期限(画像 24 時間、なし 1 時間)まで保管する。
- 退会: D1 の行と、R2 の 2 つの物を消す(上の「退会」)。
- 残るもの: `picture_removals`(運営の記録)。保管の期限が切れた `gravatar/<id>` は、次に開かれるまで物が残る(読まれず、開かれると置き換わる)。行のない `avatars/<id>` を、まとめて探して消す掃除は、作っていない。

**binding は `wrangler.jsonc` の `"images": { "binding": "IMAGES" }` で足した**(依頼者の明示の許可を得た、2026-11-23。この 1 点だけで、権限、secret、DNS、route、vars は変えていない)。足した理由: ローカルの代用(PNG だけを縮める)では、JPEG と WebP の操作を確かめられず、ローカルと本番で挙動が分かれるため。型は、`wrangler types` が `worker-configuration.d.ts` に出す。Cloudflare Images の変換は、料金に関わる(無料の枠と、それを超えたときの単価は、Cloudflare の現行の料金表で確かめる。プロフィール画像は 1 回のアップロードにつき 1 回の変換で、閲覧では変換しない)。人の確認に残るのは、料金と、本番の実物(縮小の品質、メタデータが消えること、読めない画像の判定)である。

## Gravatar(D-32、D-33)

「Gravatar の画像を使う」は、`profiles.use_gravatar`(既定は入)。アップロードした画像が無いときに限って使う。

- サービスが、Gravatar へ取りに行く。URL は `https://gravatar.com/avatar/<ハッシュ>?s=256&d=404`。ハッシュは、メールアドレスの前後の空白を取り、小文字にして、SHA-256 を 16 進で書いたもの([Gravatar の仕様](https://docs.gravatar.com/rest/hash/))。`d=404` を付けると、画像が無いとき Gravatar は 404 を返す。
- 答えは 3 つ: 画像がある(200 と画像)、無い(404)、応答しない(それ以外、接続の失敗、3 秒を超えた、画像でない型、1 MB を超える)。
- 取りに行った答えは、R2 の `gravatar/<id>` に cache する。画像は 24 時間、「無い」は 1 時間(あとから Gravatar を作った人の画像が、1 時間で出るように)。「応答しない」は cache せず、古い画像が残っていればそれを返し、なければ 404(頭文字)にする。
- Gravatar へ送るのは、ハッシュだけである。読者のブラウザは、Gravatar へつながない。ページの CSP は広げない(`img-src 'self'` のまま)。

## 運営の画面

運営の画面(`admin.slide.community`、Cloudflare Access の内側)の「プロフィール画像を外す」で、その人のアップロードした画像を外せる(D-35)。ハンドルを入れ、理由を書く(必須)。外すと、`removePicture` を呼び、`picture_removals` に、外した運営の人、理由、時刻の行を残す。外した後は、Gravatar か頭文字に戻る。読者がプロフィール画像を通報する窓口は作らない(既存の通報の窓口で受ける)。

## 退会

退会すると、`profile_pictures` と `profile_links` の行、R2 の `avatars/<id>` と `gravatar/<id>` を消す。`picture_removals` は、運営の記録なので残す(中身は id、運営の人、理由、時刻で、画像もメールアドレスもない)。R2 は D1 のあとに消すので、途中で失敗しても、だれにも読まれない物が残るだけである。
