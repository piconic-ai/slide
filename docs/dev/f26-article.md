# 実況記事の実装設計

[発表を書き起こした記事を添える](../features/f26-article.md)の設計。記事の保存、Markdown の変換と許可する要素、ページの埋め込み、記事からの引用、記事の HTML を出す場所を決める。[引用でつながる](f24-citations.md)の F24-AC19〜F24-AC21 も、ここで扱う。

## ファイルの分担

記事のコードは `src/articles/` にまとめる。

| ファイル | 層 | 役割 |
| --- | --- | --- |
| `markdown.ts` | 純粋 | Markdown を許可した要素だけの HTML にする。ページの埋め込みになる段落を見つける。本文が書いた共有 URL を読む。出力が許可に収まるかの検査 |
| `article.ts` | 純粋 | 本文の検査(50,000 文字、公開できる本文か)、改行の正規化、状態の型 |
| `store.ts` | store | `articles` と `article_citations` の読み書き。保存・公開・取り下げ・読み出し。公開中は引用を同じ batch で書く |
| `embed-store.ts` | store | 本文のページの URL を、画像と説明を出せる行き先に解く(一般公開中・非表示・停止・存在の条件は SQL に含める) |
| `edit-page.ts` | pages | 記事の編集ページ。1 本の管理の「記事」の枠 |
| `viewer-article.ts` | pages | viewer の記事の節(見出しなし) |
| `routes.ts` | routes | `/slides/:deck/article`(表示、保存、公開、取り下げ) |

viewer の枠は P1 が置いた `viewerArticleFrame`(`src/share/viewer-article-frame.ts`)、1 本の管理の枠は `articleFrame`(`src/decks/article-frame.ts`)で、どちらも本文を出す部品を呼ぶだけにする。

## 保存

migration 0040 が `articles` を作り、0041 が `article_citations` を作る。どちらも、空の D1 に足すだけで、既存の表は変えない。

| 列 | 意味 |
| --- | --- |
| `deck_id` | 主キー。スライド 1 本につき 1 本(F26-AC9)。版(`deployments`)を指さないので、版を差し替えても残る(F26-AC8) |
| `body` | Markdown の本文。CHECK で 50,000 文字まで(F26-AC16)。SQLite の `length` は文字を数えるので、絵文字は 1 文字になる |
| `status` | `draft` か `published`。新しい記事は `draft` |
| `created_at`、`updated_at` | 秒。「最後に保存した日」は `updated_at` |

本文の検査は、書く前に純粋な関数(`checkBody`)で行う。CRLF は LF にそろえ(フォームの送信は `\r\n` で送る)、NUL は捨ててから数える。50,000 文字ちょうどは保存でき、50,001 文字は保存できない。公開する本文は、空白だけでないことも要る(読者に、見出しだけで中身のない節を見せないため)。この「空の本文は公開できない」は、仕様に書かれていない決めである。

公開の状態は、スライドの公開の状態とは別に持つ。読者に出るのは、スライドが一般公開中(`readSharedDeployment` が答える間)で、記事が `published` のときだけである(F26-AC4、F26-AC5)。作者は、スライドが作者のみ限定公開の間も、下書きも、viewer で読者と同じ見え方で見られる(F26-AC2)。

退会とスライドの削除は、`deletionSteps`(`src/decks/deletion-store.ts`)の中で、記事と記事の引用を消す(F26-AC28、F26-AC29)。スライドを削除済みにする文と同じ batch である。

## Markdown の変換

### 依存の選び方

Markdown の変換器を足す。D-43 のとおり、生の HTML を既定で通さないものを選び、理由をここに書く。

| 候補 | 生の HTML | 表・取り消し線 | 自動リンク | 結果 |
| --- | --- | --- | --- | --- |
| `marked` | 既定で通す。別に無害化する部品が要る | 既定である | 既定である | 通さない設定がなく、無害化に別の部品を足すことになるので選ばない |
| `micromark` と `micromark-extension-gfm` | 既定で通さない | 拡張で足す | 拡張で足す | 安全だが、HTML にするまでに構文木を使う部品が増え、ページの埋め込みと引用のためにリンクの位置を読むのが重い |
| `remark` と `rehype` の連鎖 | 既定で通さない | 拡張で足す | 拡張で足す | 部品が多く、Workers の bundle が大きくなる |
| `markdown-it` | `html: false` が既定で、生の HTML は文字として出る | 既定で入っている | `linkify` | 選ぶ |

`markdown-it`(15 系)を選ぶ。CommonMark に従い、生の HTML を通さず、表と取り消し線を持つ。構文解析の結果が token の列で、描画の規則を 1 つずつ置き換えられるので、出す要素と属性を、本文からではなくこちらの規則から決められる。ブラウザや Node の API を使わない JavaScript で、Workers で動く。保守されている。

### 許可の決め方

HTML は本文から取らない。次の 3 重の守りを重ねる。

1. **構文解析**。`html: false` で、本文の `<script>` などは文字になる。画像の規則は止める(`disable('image')`)。画像のアップロードは作らないので([範囲外](../features/f26-article.md))、画像の記法で書いたものは、ふつうのリンクの記法として読まれる。リンクの検査(`validateLink`)は、`https://`、`http://`、`mailto:` で始まるものだけを通す。それ以外(`javascript:`、`data:`、`vbscript:`、`file:`、`//`、相対 URL、`#` だけの断片)は、リンクにならず、書いたままの文字で出る(F26-AC13)。検査は、token の正規化(実体参照の復元、エスケープ)のあとの値に対して行う。
2. **描画の規則**。出す要素は、規則が書く。リンクは `<a href rel="noopener nofollow ugc">` の 2 つの属性だけで、`title` と `target` は書かない(F26-AC14)。表のセルの配置は `style` になるので書かない。コードの info line は `class` にしない。見出しは `#` を `h3`、`##` を `h4` にして、`h6` で止める(viewer の記事の節に見出しはなく、本文の見出しが最初の見出しになる)。
3. **出力の検査**(`onlyAllowed`)。描画の結果を、許可の一覧(要素ごとの属性)と照らし、`<` が 1 つでも一覧の外にあれば、変換の結果を捨てて、本文全体を文字として出す。規則の書き間違いや、依存の更新で出力が変わったときのための 2 つ目の鍵であり、1 つ目ではない。

許可する要素は `p`、`h3`〜`h6`、`ul`、`ol`(`start` だけ)、`li`、`blockquote`、`pre`、`code`、`em`、`strong`、`s`、`br`、`hr`、`table`、`thead`、`tbody`、`tr`、`th`、`td`、`a`(`href`、`rel`)に、ページの埋め込みの `div`、`span`、`img`、`a`(`class`、`aria-label`、`data-article-page`)である。`script`、`style`、`iframe`、`form`、`svg`、イベント属性、`style` 属性は、一覧になく、入らない(F26-AC12)。

`markdown-it` の入れ子の上限(100)を超えた入れ子は、文字として出る。入力が 50,000 文字までなので、`[` や `>` や `*` を並べた本文でも、変換は 3 秒に収まる(テストで確かめる)。

### 自動リンク

自動リンクは、`https://` と `http://` で始まる URL と、`<https://…>` の形だけにする(`www.` や、スキームのないアドレスは作らない)。`mailto:` のリンクは、リンクの記法か `<mailto:…>` で書ける。

## ページの埋め込み

段落が、**1 行で、共有 URL 1 つだけ**のとき、そのページの画像にする(D-45)。次の条件を、すべて満たすものだけが対象である。

- 最上位の段落である(リスト、引用、表、コードの中は対象にしない)。
- 段落が、リンク 1 つだけで、その文字が URL そのものである。リンクの記法で別の文字を付けたものと、文の中の URL は、ふつうのリンクにする(F26-AC21)。
- URL が、サービスの origin(`PUBLIC_ORIGIN`、`https:`)の、ページ番号つきの共有 URL(`/@handle/slug/3`)で、クエリと断片がない。末尾の `/`、大文字の handle、`03` のようなゼロ詰めは、引用と同じ読み取り(`citationOfHref`)で正規の名前にする。`http:` と、ほかの origin、`/@handle/slug`(ページ番号なし)は、ふつうのリンクにする。
- 1 つの記事で画像にするのは、違うページを 20 まで(`MAX_EMBEDS`)。それより後ろは、ふつうのリンクにする。D1 を引く数を抑えるためである。

画像にするかは、解いた結果で決める(`embed-store.ts`)。

| URL が指すもの | 出すもの |
| --- | --- |
| この記事のスライド | そのページの画像(F05 のページごとの画像。ページを伝える script を読み込んでいない版は表紙)。押すと上のスライドがそのページに移る(F26-AC17、F26-AC18) |
| ほかの人の、一般公開中で、非表示でも停止でもないスライド | そのページの画像と、「△△さんの『□□』3 ページ」。押すとそのスライドのそのページを開く(F26-AC19、F26-AC20) |
| 上のどれでもない(作者のみ限定公開、公開を止めた、存在しない、非表示、停止中の作者) | 何も出さず、ふつうのリンクにする。題名も存在も、記事から分からない(F26-AC22) |

解く条件は、viewer と同じ `readSharedDeployment`(公開中の版、`notHidden`)を使う。作者のみ限定公開のスライドと、存在しないスライドは、どちらも答えがなく、同じ見え方になる。記事はキャッシュしない(viewer は `no-cache`)ので、公開の状態の変化は次の読み込みに出る。

「いまの版に無いページ」(F26-AC23、F26-AC24)は、版の総ページ数が分からないと判定できない。[説明したいページを画像付きで共有する](../features/f05-page-ogp.md)は総ページ数を取らないと決めていて、ページを伝える script が送るのも、いま見ているページの番号だけである。総ページ数の取り方は決まっていないので、判定の関数(`missingPages`)は総ページ数を引数に取り、値が分からない(null)ときはすべてのページを「ある」とする。どう取るかは依頼者に決めてもらう。

画像の `<img>` には `data-cover` を付ける。壊れた画像の印を出さないための、`/share.js` の `hideBrokenCovers` に乗せる。画像の下の面には、題名とページ番号を出す(`deckCover` と同じ 2 層)。

押したときの移動は、`/share.js` が行う。`a[data-article-page]` を押すと、`#deck` の枠の `src` を、版の origin の `/#<ページ>` にして、枠の位置までスクロールする。枠はスライドの origin で動くので、中の文書には触れない。`src` の断片だけを変えるので、枠の中の文書は読み込み直されず、`hashchange` で動くスライド(Marp など)がそのページに移る。script が動かない環境では、`href` の `/@handle/slug/3` が、そのページの viewer を開く。

## 記事からの引用

公開中の記事が書いた共有 URL を、引用として数える(D-46)。数える URL は、段落の埋め込みも、文の中のリンクも、別の文字を付けたリンクも含む。コードの中の URL は、リンクではないので数えない。自分のこのスライドへのリンクは数えない。

`article_citations` は、記事が公開中の間だけ行を持つ。

- 公開する、または公開中の記事を保存する: 記事の表の更新と、`article_citations` の入れ直し(消して、書く)を、1 つの batch で行う。
- 取り下げる: 状態を `draft` にして、行を消す(F24-AC20)。もう一度公開すると、本文から読み直して書く。
- 本文から読むのは、純粋な `linkedShareUrls`。重複を除き、自分のスライド(作者の handle と slug)を除き、100 件(`MAX_CITATIONS`)までにする。

「引用している側」を読む `readCitedBy`(`src/citations/store.ts`)は、スライドの公開中の版の引用(`citations`)か、記事の引用(`article_citations`)のどちらかがあるスライドを、引用している側とする。公開の状態、非表示、停止、ミュート、自分自身の除外、並び(公開中の版を受け取った新しい順)は、これまでと同じである。記事のスライドが公開中であることは、公開中の版の結合で求める。記事は版ではなくスライドに属するので、公開中の版を差し替えても、記事の引用は残る。

記事の引用は、「このスライドが引用しているスライド」(`readCites`)には、足さない。受け入れ条件が、引用された側の一覧だけを求めているためである。プロフィールの「引用した」「引用された」の数と一覧、カードの数は、`pairs()`(`src/citations/pair-store.ts`)が、公開中の版の引用と公開中の記事の引用を合わせた 1 つの元から求める。同じ組は、どちらにあっても 1 行で、数でも 1 である(F24-AC24)。

## 記事の HTML を出す場所

記事の HTML は、viewer の管理 origin で出す(D-49、F26-AC15)。作者の HTML が動く版の origin(`d-<ID>.…`)とは別である。作者の HTML の sandbox(`allow-scripts allow-same-origin`の枠)の中に入れない。

- viewer の CSP は変えない。記事は script も、新しい origin の画像も、`form-action` も要らない。画像は、サービスの `/covers/` と、スライドが表紙に選んだ版の origin のものだけである(どちらも、いまの `img-src` で読める)。
- 編集ページは、管理画面の CSP(`default-src 'none'`、`script-src 'self'`、`form-action 'self'`)のままである。入力は `<textarea>` で、プレビューは、サーバーで描いた HTML を、同じ部品(`renderArticle`)で出す。

## 編集ページ

`/slides/:deck/article` は、スライドの作者だけが開ける。ほかの人のスライドと、存在しないスライドは、どちらも同じ 404 になる(F26-AC27)。保存、公開、取り下げは、`POST /slides/:deck/article` の 1 つの経路で、フォームの `action`(`save`、`publish`、`unpublish`)で分ける。CSRF の守り(`csrf()`)と `requireOwner` は、ほかの管理画面と同じである。

- 本文が 50,000 文字を超えたときは、保存せず、422 で、入力した本文を残したまま、理由を出す(F26-AC16)。
- 保存・公開・取り下げのあとは、編集ページに戻り、結果を一言で示す。
- 「プレビュー」は、フォームの送信(`action=preview`)で、本文を保存せずに描き直す。JavaScript を使わない。
- 保存していない変更があるまま離れようとすると、ブラウザの確認を出す(F26-AC30)。`/share.js` が、`form[data-unsaved-guard]` の入力を見て、`beforeunload` を設定する。ページ内の移動(router)が確認を飛ばさないよう、この編集ページへの移動と、ここからの移動は、ページの読み込みにする(`src/site/router-policy.ts`)。

仕様の「未決事項」と同じである。加えて、次を決めていない。

- 画像を押す操作の読み上げに使う文言。いまは、行き先を `aria-label` に書いている。
