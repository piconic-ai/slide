# 引用の実装設計

[引用でつながる](../features/f24-citations.md)の設計。スライドの中のリンクから引用を読み取り、viewer に表紙のカードで出す。試作にあった SNS の投稿のタイムラインと、イベントとコミュニティの表示は、コードと経路ごと取り除いた。

## ファイルの分担

引用のコードは `src/citations/` にまとめる。

| ファイル | 層 | 役割 |
| --- | --- | --- |
| `citation.ts` | 純粋 | HTML の文字列から共有 URL へのリンクを読む。版ごとにまとめ、重複と自分自身へのリンクを除く |
| `citing.ts` | 純粋 | 表示する件数(4 件)と、残りの件数の計算 |
| `cards.ts` | 純粋 | 保存した行を、カードに出す値(題名、リンク、作者、表紙の URL)へ変える。カードの格子の HTML |
| `pair-store.ts` | store | プロフィールの引用の組。一覧、数、カードの数 |
| `profile-pages.ts` | pages | プロフィールの引用の一覧のページ(行と、前後のページへの道) |
| `cited-count.ts` | 純粋 | カードに添える「引用された N 件」の文 |
| `store.ts` | store | `citations` の読み書き。公開の状態、非表示、停止、ミュートの条件は SQL に含める |
| `citation-store.ts` | store | 版の HTML を R2 から読み、引用を保存する(`recordCitations`) |

画面の枠は、viewer の `viewerCitations`(`src/share/viewer-citations.ts`)だけで、`cards.ts` の格子と、共通の表紙のカード(`src/site/deck-card.ts`)を使う。

## 検出

受け取りの確定(`POST /api/uploads/:id/finalize`)が、版を ready にする前に `recordCitations` を呼ぶ。継ぎ目はこの 1 回の呼び出しだけで、受け取りの入口(ブラウザの session での開始、AI エージェント)が変わっても、確定を通る限り引用は読まれる(`src/citations/upload.test.ts`)。

- 読むのは、その版の HTML ファイル(`media_type` が `text/html`)。`index.html` を先頭に、最大 200 ファイル、各ファイルの先頭 512KB まで。512KB より後ろにあるリンクは読まれない(画像を埋め込んだ 1 ファイルのスライドで起こりうる)。512KB で切れたファイルでは、末尾に接した引用符なしの `href` を捨てる。途中で切れた値(`talk-long` の `talk-lo`、`/12` の `/1`)が、別のスライドへの引用になるのを避けるためである。
- リンクは、`href` 属性の値として読む。引用符つきでも、minify された HTML の引用符なしでもよい。タグの種類は問わない(`<a>`、`<area>`、SVG の `xlink:href`)。
- HTML として構文解析はしない。スライドは script でページを描くことが多いので、script が markup をそのままの形で持っていれば(`'<a href="https://…">'`)、その `href` も読む。そのため、コメントの中に書いたリンクも数える。script がエスケープした形(`"<a href=\"…\">"`)やデータ(`{ href: "…" }`)で持つリンクは読めない。文中に書いただけの URL、`src`、`action`、`content` の値は数えない。
- 数えるのは、サービスの origin(`PUBLIC_ORIGIN`)の共有 URL(`/@handle/slug`、`/@handle/slug/6`)だけ。相対 URL、別の origin、プロフィールは数えない。viewer が正規の綴りへ 301 で送る綴り(大文字の handle、末尾の `/`、`%40`、`06` のようなページ番号)は、正規の名前に直して数える。読者がそのリンクで移れるのに、カードが出ないことを避けるためで、1 つのスライドは 1 つの名前でしか保存されない。origin は、port を付けない、サービスが書くとおりの綴りに限る(大文字小文字は問わない)。
- URL として解析するのは、サービスの origin で始まる値だけにする。URL でない値の解析は失敗に時間がかかり、10MB の版に 150 万個並べると、確定が 10 秒を超えたためである。さらに、1 つの HTML で解析するのは 2000 個までで、それより後ろは読まない(1 つの版が持てる引用は 100 件)。
- 1 つの版が持つ引用は、重複を除いて最大 100 件。同じスライド(同じ handle と slug)へのリンクは保存しない。
- R2 の読み取りに失敗したときは、引用なしで確定を続ける(`citations_unrecorded` を記録する)。引用は表示を足すだけなので、受け取りを失敗させない。後から読み直す手段は、まだない。

`citations` の行は、版(`deployment_id`)と、リンクが名指した相手(`target_handle`、`target_slug`、`target_page`。ページ番号なしは 0)を持つ。相手は、リンクの綴りのまま保存し、表示のときに、いまの公開の状態と突き合わせる。ページ番号は保存するが、画面にはまだ使っていない。

## 記事からの引用

公開中の記事が書いた共有 URL は、`article_citations`(migration 0041)に持ち、引用している側の判定に加わる。保存と出し入れは[実況記事の実装設計](f26-article.md#記事からの引用)に書いた。`readCitedBy` は、公開中の版の引用か、公開中の記事の引用のどちらかがあるスライドを、引用している側とする。

## 表示する条件

どの版の引用を、だれに出すかは、読むときに SQL で決める(`store.ts`)。

- **引用した側**: スライドの公開中の版(`decks.public_deployment_id`)の引用だけを数える。新しい版を受け取っても、作者が公開中の版を入れ替えるまで、出る引用は変わらない。公開を止めると消え、もう一度公開すると戻る。
- **引用された側**: カードを出すのは、そのスライドが一般公開されている間だけ。作者のみのスライドや、公開を止めたスライドの題名と表紙は、引用を通して見えない。
- **自分自身**: 引用した側と同じスライドは、読むときにも除く。保存のときに名前(handle、slug)が決まっていなかったリンクが、後から自分を指すことがあるためである。同じ作者の別のスライドは数える。
- **非表示、停止、ミュート**: 最近のスライドの一覧と同じ条件(`notHidden`、`notMutedBy`)を使う。運営が非表示にしたスライド、停止中の作者のスライド、読む人がミュートした作者のスライドは、カードにも「ほか N 件」の数にも入らない。
- 何ページ引用していても、スライドごとに 1 枚。並びは、公開中の版を受け取った新しい順。

viewer は、引用している側とされている側を、それぞれ 4 件まで出し、残りを「ほか N 件」で示す。1 件もない側は、置き場所(`data-reader-lists`)を空にして、見出しごと出さない。置き場所そのものは常に置く。ミュートと解除の後に、`/share.js` がページを取り直して、置き場所ごと差し替えるためである([ミュートの実装設計](f19-mute.md))。

スライドの編集の画面は、引用しているスライドの一覧を出さない(F24-AC18)。引用された作者への知らせは、viewer の一覧とお知らせ(F20-AC3)が担う。

## カードと CSP

引用のスライドは、枠(iframe)で動かさない。引用しただけで、相手のページの上で自分のスライドが動くのを避けるためである。カードは、viewer へのリンクと表紙の画像だけを持つ。

- viewer の `frame-src` は、読んでいるスライドの版の origin と `'self'` だけである。
- 表紙は、スライドが自分のファイルを指すことがあり、ミュートの後は一覧が入れ替わるので、`img-src` はすべての版の origin を許す(トップページと同じ)。
- 読めなかった表紙は `/share.js` が隠し、題名を入れた面が見える。

## スライドの中のリンクで移る

スライドは sandbox の中で動き、viewer を移動できない。読者がスライドの中の共有 URL へのリンクを押すと、スライドの枠がその URL を要求する。

1. サービスは、枠からの要求(`Sec-Fetch-Dest: iframe`)で共有 URL の path のものに、viewer へ移動を頼むだけのページを返す(`followedLinkPage`、`src/share/pages.ts`)。このページは自分の origin からだけ枠に入れられる。
2. そのページが、viewer に `{ type: 'slide:open', path }` を `postMessage` で送る。
3. viewer(`/share.js`)は、読んでいるスライドの枠の、自分の origin からの依頼で、path が共有 URL の形のときだけ移動する。ページ番号つきなら、そのページから開く。

スライド自身が `slide:open` を送っても、origin が違うので移動しない。共有 URL でないサービスのページ(プロフィール、管理画面)と、ほかのサイトへのリンクでは、viewer は動かない。戻る操作で枠がサービスのページに戻ったときは、移動をやり直さずにスライドを読み込み直す。

## プロフィールの引用の一覧と数

[プロフィールの「引用した」「引用された」](../features/f24-citations.md)(F24-AC22〜F24-AC35)と、頭の数・タブ(F21-AC54〜F21-AC56)、スライドのカードの数(F24-AC33、F24-AC34)の設計。

### 引用の組

プロフィールの行は、引用した側のスライドと、された側のスライドの組ごとに 1 行である(D-61)。`citations` の行は、版と、リンクのページごとに 1 行あるので、`src/citations/pair-store.ts` が、組ごとにまとめる(`GROUP BY` で、引用した側のスライドとされた側のスライドの組にする)。同じ組が、何ページで引用されていても、1 行になる。

どの組を数えるかは、`pair-store.ts` の 1 か所で決める。一覧、プロフィールの頭の数、カードの数は、同じ組の集まりを数えるので、互いにずれない。

- 引用した側は、公開中の版の引用だけを数える。両側のスライドが、公開中で、削除されておらず、非表示でなく、停止中の作者のものでない。viewer の一覧(`readCitedBy`、`readCites`)と同じ関数 `notHiddenOf`、`notMutedByOf` を使う。`notHidden`、`notMutedBy` は、`decks` に結んだ条件で、2 つのスライドが出会う問い合わせのために、別名の表も受け取れるようにした。
- 同じ作者のスライド同士の組は入れない(D-63)。viewer の一覧には、これまでどおり出る。viewer は同じスライドだけを除き、プロフィールは同じ作者を除く。
- 見る人がミュートしている作者は、プロフィールの作者の側でない側(一覧に並ぶ側)だけで見る。プロフィールの持ち主自身をミュートしていても、プロフィールは開ける(フォロー中、フォロワーと同じ)。

組の日(「引用が生まれた日」)は、引用した側のスライドの、公開中の版が ready になった日にする。新しい版に入れ替えると、その日に変わる。同じリンクを残したまま再公開しても、日が動く(行が一覧の先頭へ移る)。組ごとの初めて引用した日を持つ表は作らない(migration 0045 は使わない)。この定義は、決めたことに書いてなかったので暫定である。記事の引用(作業 B)が加わるときは、`pair-store.ts` の組の集まりに記事の組を足し、同じ組は早いほうの日にする。

### 一覧と数

| 問い合わせ | 役割 |
| --- | --- |
| `listPairs` | 1 ページ分(50 件)の行。日の新しい順、同じ日は引用した側・された側のスライドの id の順 |
| `countPairs` | 全ページ分の組の数。プロフィールの頭の数とタブの数 |
| `readCitedCounts` | 指定した作者のスライドごとの「引用された数」。カードの数。D1 の束縛の上限(100)を超えないよう、作者を重複なく 50 人ずつに分けて問い合わせる |

経路 `/@handle/citing` と `/@handle/cited` は、`parseSharePath` が `citations` として読む。`following`、`followers` と同じく、スライドの URL の名前にならない(F24-AC35)。自動で決めるときは `-2` を付け、手で変えるときは断る(`isReservedSlug`)。この名前のスライドが行に紛れ込んでいても、一覧が開く。ページは `?page=N` で、数でないものと 0 以下は、プロフィールと同じ 404 になる。存在しないハンドルと停止中の作者は、プロフィールと同じ 404 である。ログインしていなくても見られるが、ミュートが見え方を変えるので、キャッシュしない。

### カードの数

引用された数は、スライドのカード(プロフィール、トップの「最近のスライド」と「フォロー中の人の新着」、viewer の引用)の、日付の後ろに「引用された 3 件」(英語は “Cited by 3”)と添える。0 件のカードには何も出さない。トップの 2 つは、`/api/public/slides` と `/api/home` の答えに `citedBy` を足した。

## 決めていないこと

仕様の「未決事項」と同じである。

- 引用が 4 件を超えたときに、残りを見る画面。
- スライドは読者の操作なしに、自分の枠を別の共有 URL へ移動できる。その場合も viewer は移動する。読者が押したときだけ移動する形にできるかは、確かめていない。
- 引用の読み取りに失敗した版を、後から読み直す手段。
- `Sec-Fetch-Dest` を送らない古いブラウザでは、スライドの中の共有 URL へのリンクは枠の中で拒否され、移動しない。
