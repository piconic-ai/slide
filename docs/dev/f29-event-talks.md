# イベントの発表の実装設計

[イベントの発表として並ぶ](../features/f29-event-talks.md)の設計。作者がスライドの関連リンクに、イベントのページの URL を入れると、そのスライドがイベントのページ(`/events/:id`)に並ぶ。サービスは、イベントのページを取りに行かない。照らすのは関連リンクだけで、スライドの本文と記事の中のリンクは見ない(F29-AC13)。

## ファイルの分担

| ファイル | 層 | 役割 |
| --- | --- | --- |
| `src/events/event-url.ts` | 純粋 | URL の形の判定(`isEventAddress`)と、鍵へのそろえ方(`eventRefOf`) |
| `src/events/event-name.ts` | 純粋 | イベント名の出し方(`eventNameOf`)、サービス名、元のページへのリンクの文 |
| `src/links/kind.ts` | 純粋 | 種類の既定。イベントの形なら「イベント」、その後に動画と記事のホスト名 |
| `src/links/store.ts` | store | 関連リンクの追加、外す、種類の変更。イベントとの対応も同じ batch で作り直す |
| `src/events/store.ts` | store | イベントのページ、スライドの入っているイベント、一覧、名前を直す |
| `src/events/event-page.ts` | pages | イベントのページ |
| `src/events/routes.ts` | routes | `GET /events/:id` |

## URL の形の判定

作者が種類を選ばずに足したリンクは、URL の形で種類の既定を決める(F29-AC1〜F29-AC3、F27-AC47)。判定は、`new URL` で解析したホスト名(小文字、末尾の `.` を除く)とパスで行い、文字列の前方一致では見ない。パスや問い合わせの文字列に `connpass.com` が入っていても、イベントにならない。

| サービス | ホスト名 | パス |
| --- | --- | --- |
| connpass | `connpass.com`、`<グループ>.connpass.com` | `/event/<番号>`(末尾の `/` は任意) |
| Doorkeeper | `<グループ>.doorkeeper.jp` | `/events/<番号>` |
| Luma | `luma.com`、`lu.ma` | `/<文字列>`(1 段だけ。英数字、`-`、`_`) |

- グループは、ホスト名の 1 段(英小文字、数字、`-`)。`a.b.connpass.com` は当たらない。
- Luma の、サイトの経路の語(`discover`、`calendar`、`user`、`signin` など)は除く。一覧は `LUMA_SITE_PATHS` の 1 か所に置き、大文字小文字を区別せずに比べる。
- 判定は、種類の既定を決めるためだけに使う。作者が種類を変えれば、そちらを使う(F29-AC4)。

## 鍵へのそろえ方

種類が「イベント」のリンクは、`eventRefOf` でイベントの鍵を持つ。URL の形に関わらず鍵を作る(F29-AC4)。

- `https` にする。ホスト名を小文字にし、末尾の `.` を除く。クエリとフラグメントを捨てる。パスの末尾の `/` を除く。`lu.ma` を `luma.com` にする(F29-AC6)。パスの大文字小文字は変えない。
- サービスの判定の前に、パスの末尾の `/` の連なりを 1 つにそろえる。`https://connpass.com/event/123//` も connpass のイベントになる(そろえないと `web` と判定され、鍵だけが connpass と同じ文字列になる)。
- 番号の先頭の `0` を落とす(`0410635` は `410635`。`0` だけなら `0`)。
- connpass は、グループに関わらず、`https://connpass.com/event/<番号>` を鍵にする(F29-AC7)。Doorkeeper は、グループを含めた URL を鍵にする(番号はグループごとに振られていると扱う)。
- 鍵のほかに、サービス(`connpass`、`doorkeeper`、`luma`、`web`)、サービスの中の番号(Luma は文字列、その他はホスト名とパス)、イベントのホスト名(connpass は `connpass.com`)、元のページへ案内する URL、そのリンクに書かれたホスト名(`linkHost`)を返す。
- イベントの URL(`url`)は、鍵と同じく正規化した形にする。connpass はグループを含まない `https://connpass.com/event/<番号>/` にする。イベントのページが案内する先は、これとは別に、開くたびにリンクから決める(「イベントのページ」の節)。
- 書かれたホスト名は、イベントではなく、リンクの側(`related_link_events.host`)に持つ。同じ connpass のイベントに、別のグループの URL を書いたリンクが結びつきうるからである。コミュニティの紐づけ用リンクとの照らし合わせ(作業 C)は、イベントに結びついたリンクのホスト名の集合(`listEventLinkHosts`)で行う。
- 関連リンクの入力は `https:` だけなので、`http` は保存されない。それでも、鍵は `http` と `https` を同じにする。

解析は境界で 1 度だけ行う。`parseLinkInput` が、種類が「イベント」のとき、`eventRefOf` の結果を入力に含める。store は解析済みの値だけを受け取る。

## 表

migration 0050 で、2 つの表を足す。既存の表は作り直さない(第三スコープの指示書の D-04)。

### `events`

| 列 | 内容 |
| --- | --- |
| `id` | サービスが振る番号(`INTEGER PRIMARY KEY AUTOINCREMENT`)。`/events/:id` と、既定の模様の色に使う |
| `key` | 鍵。一意 |
| `service` | `connpass`、`doorkeeper`、`luma`、`web`(CHECK) |
| `ref` | サービスの中の番号(または文字列) |
| `host` | イベントのホスト名。鍵から決まる(connpass は `connpass.com`) |
| `url` | イベントの URL。鍵から決まる(connpass はグループを含まない)。connpass のイベントのページが案内する先は、ここではなくリンクから決める |
| `name` | イベント名。最初に保存された題名、または運営が直した名前。無いときは NULL |
| `named_by`、`named_at` | 名前を直した人と時刻。直していなければ両方 NULL(CHECK で、片方だけを許さない) |
| `created_at` | 最初のリンクが入った時刻 |

イベントは消さない。リンクがすべて外れたイベントは、一般公開中のスライドが無いので、ページは 404 になる(F29-AC12)。同じ URL がまた入れば、同じイベントに戻る。

### `related_link_events`

| 列 | 内容 |
| --- | --- |
| `link_id` | 関連リンク。主キー。1 つのリンクは 1 つのイベントにだけ入る |
| `event_id` | イベント |
| `host` | そのリンクの URL に書かれたホスト名(connpass ならグループ)。`listEventLinkHosts` が集合で返す |
| `created_at` | 対応を作った時刻 |

`event_id` に索引を張る。1 本のスライドは、リンクごとに別のイベントに入れる(F29-AC23)。

### 種類「イベント」の持ち方

`related_links.kind` は CHECK で `video`、`article`、`other` に縛られている。CHECK を変えるには表の作り直しが要り、第三スコープでは表を作り直さない。そこで、**`related_link_events` に行のあるリンクを、種類「イベント」とする**。そのリンクの `kind` の列には `other` を入れ、読むときは対応の行を優先する。

- 種類を読むのは `listLinks` の 1 か所で、対応の表を結合して `event` を返す。画面、viewer、AI エージェントの道具は、この関数だけを通す。
- 対応の行が無いリンクは、`kind` の列のとおり。

## 対応を作り直す

関連リンクを足す、外す、種類を変えるときに、対応を同じ D1 の batch で作り直す。batch は 1 つのトランザクションなので、リンクと対応がずれた状態は残らない。リンクの URL は変えられない(変えるときは、外して足し直す)。

- **足す**: リンクの `INSERT` が入ったときだけ(`WHERE EXISTS` で確かめる)、イベントを `INSERT ... ON CONFLICT DO NOTHING` で作り、名前が NULL で題名があれば題名を入れ、対応を足す。上限や持ち主で断られた追加は、イベントを作らない。
- **外す**: 持ち主の確認と同じ条件で、対応を消してからリンクを消す。
- **種類を変える**: 持ち主の確認と同じ条件で、`kind` を書き換え、対応を消す。「イベント」にしたときは、足すときと同じ手順で対応を作る。
- **スライドの削除と退会**: `deletionSteps` が、リンクを消す前に、そのリンクの対応を消す。

## イベント名

イベント名は、そのイベントのリンクの題名のうち、最初に保存されたもの(F29-AC8)。`events.name` が NULL のときだけ書くので、後から別の題名で足しても変わらない。題名の無いリンクだけのイベントは、`eventNameOf` が「connpass のイベント 410635」のように出す(F29-AC9)。リンクを外しても、名前は戻さない。

運営は、運営の画面でイベント名を直せる(F29-AC15)。直すと `named_by`、`named_at` を書く。コミュニティの管理者が直すこと(F29-AC22)は作業 C が作る。「直せる人か」を答える `mayRenameEvent` を置き、いまは運営だけを通す。

## 並び順

公開日時は、スライドが初めて公開された時刻(`decks.first_published_at`。無い古い行は、公開中の版の `ready_at`)。

- イベントの一覧は、そのイベントの一般公開中のスライドのうち、最も早い公開日時の新しい順(F29-AC10)。同じ時刻は番号の大きい順。
- イベントのページの発表は、公開日時の新しい順。同じ時刻は URL の名前の順。

一般公開中のスライドの条件は、トップの「最近のスライド」と同じ(公開中の版があり、`ready`、運営が隠していない)。作者のみ限定公開と非公開のスライドは出ない(F29-AC12)。

## イベントのページ

`/events/:id` は、番号が数字でないとき、イベントが無いとき、一般公開中のスライドが無いときに 404 を返す。上から、カバー画像、頭(コミュニティのロゴと名前、イベント名、元のページへのリンク)、「発表 n 本」と表紙のカードの一覧を出す。日時と場所は出さない(F29-AC19)。

- 元のページへのリンクは「connpass で見る」のようにサービス名を入れ、`rel="noopener nofollow ugc"` を付ける(F29-AC14)。
- connpass の元のページへのリンクの先は、そのイベントに結びついた、公開中のスライドの関連リンクのうち、最も古いもの(`related_link_events` の `created_at`、同じ時刻なら挿入の順)が書いたグループの `https://<グループ>.connpass.com/event/<番号>/` にする。そのリンクがグループを含まないときは `https://connpass.com/event/<番号>/`。下書きや非公開のスライドのリンクは数えない(下書きは作者だけのもの)。だれが見ても同じ先にするため、見る人のミュートやブロックは当てない。グループは保存のときに小文字にそろえてある。最も古いリンクが消えたり、種類や URL が変わって結びつきが作り直されたりすると、残りのうち最も古いものに従う。表に案内先を持たず、`readEventPage` が開くたびに、公開中の発表を引くのと同じ条件の問い合わせ 1 つで引き、純粋な `sourceUrlOf`(`src/events/event-url.ts`)で URL にする。鍵(グループを捨てる)は変えない(F29-AC14、2026-11-25 と 2026-11-26 の依頼者の回答)。Doorkeeper、Luma、その他は `url` のまま。
- カバー画像は、コミュニティが無いイベントでは、イベントの番号から 5 色の 1 つを選んだ既定の模様(F29-AC21)。コミュニティのカバー画像とロゴと名前は、作業 C が差し込む。ページの関数は、カバーとコミュニティを引数で受け取る。
- ページを開いても、サービスは外へ通信しない(F29-AC16)。

## 1 本の管理

「関連リンク」の枠の追加のフォームに、種類の選択を足す。既定は「URL から決める」で、選べば、その種類で足す。既存の行ごとに種類を選び直して「保存する」で変える(F27-AC45)。種類が「イベント」の行の下に、どこに並ぶかを 1 文で出す(F29-AC17)。「発表したイベント」の枠に、そのスライドが入っているイベントを、関連リンクに足した順で並べる(F29-AC18)。

## 外へ取りに行かない

リンクを足すときも、イベントのページを出すときも、外へ通信しない(F29-AC16、F27-AC42)。テストで `fetch` を差し替え、呼ばれないことを確かめる。
