# ブラウザーテストから BarefootJS の IR に移す

画面の構造は実装の TSX を `renderToTest` でコンパイルして検証できる。ブラウザーでしか観測できない結果は、構造を確認するテストを追加した後も実際の操作で確かめる。

## 1件を分割する手順

1. テストが失敗してほしい変更を列挙し、それぞれを対応する画面・コンポーネント・受け入れ条件に結び付ける。表示の途中に出てくるコンポーネント名だけで移行先を決めない。
2. 検証したい要素をどのソースが生成するかを追う。BarefootJS のコンパイル対象は `vite.config.ts` の `components` 設定で確認する。IR にはコンパイル対象の実ソースを渡す。Hono が返す HTML はルートのレスポンスで確認できる。
3. IR が表現する事実を検証する。たとえば見出しの ID と一覧の `aria-labelledby` が対応するか、空き枠にリンクがないか、通知に `role="status"` があるかを調べる。条件分岐やループのテンプレートは IR に両方現れる。データを入れたときにどちらが表示されるか、何件になるか、リンク先が何になるかは、実際に描画された結果で確認する。
4. IR に移した検証をブラウザーから取り除く。残る操作と観測結果が別のブラウザーテストと重なる場合は、その操作に固有の検証を統合する。レスポンスを受けた後の表示、アクセシブル名、キーボード操作、CSS の寸法、CSP・iframe の隔離は、それらを実際に通るケースを残す。
5. 構造に誤りを1つ入れ、対応する IR テストが失敗することを確かめて戻す。対象のブラウザーテストも実行する。削減効果は、同一端末・同一ワーカー数で、IR を含めた変更後と変更前の関連ファイルを交互に測る。実行件数、中央値、範囲、計測対象を PR に記録する。途中でケース数が変わった回は分け、端末の負荷変動が差を上回る場合は短縮率を結論にしない。

同じ画面で入力ごとのエラーを確かめている場合は、その判定と文言を作る本番関数を直接テストできる。たとえばドロップの不正な HTML・ZIP は `prepareDrop` と `refusalMessage` で検証する。ブラウザーでは代表の失敗と再入力を通し、警告の更新、送信の有無、保存先の状態まで確かめる。

自動保存のように時間が条件になるテストでは、通常の時計で自動保存が働くケースを残し、拒否や競合のケースでは Playwright の時計を進める。予期しない再送の応答を保留すると、テストが「保存中」の表示を見逃さないことも確かめられる。

## ローカルで試す

表紙の例は [HomeTimeline の IR テスト](../../src/site/home-timeline-component.test.ts) にある。パッケージをインストールした worktree で、次のコマンドで実行できる。

```sh
pnpm test src/site/home-timeline-component.test.ts
```

このテストは TSX の実ソースを読み、コンパイルエラーがないことを確認してから、閲覧リンクの子孫に代替表示と表紙画像があるかを調べる。コンパイル結果からは画像の実際の URL、読み込みの成功、クリック後の移動先は決まらない。これらは [表紙のブラウザーテスト](../../src/site/home-cover.browser.test.ts) で確認する。テストを試すには先に `pnpm build` を実行し、Chromium を用意する。

`@barefootjs/test@0.41.3` の ESM 配布物は `HomeTimeline` と `HomeCarousel` の解析時に TypeScript のファイルシステムを初期化できない。`vitest.config.ts` で、この依存だけを同梱のソース入口に解決している。BarefootJS の更新時にはこの2つの本番コンポーネントで通常のエントリーポイントを再検証する。

## 複数人・複数エージェントで進める

- 最初に基準コミットをそろえ、`git ls-files '*.browser.test.*'` と CI の実行対象を突き合わせる。別名のファイルやテスト用ヘルパーからブラウザーを起動していないかも確認する。
- 同じソースとブラウザーテストを変更する人を1人に決める。各担当は「元の観測結果」「それを生成する本番ソース」「IR で検出する回帰」「ブラウザーに残す操作と観測結果」を記録する。セットアップでページを通るだけのケースも区別する。
- 構造解析と差分の確認は並列に行える。速度を比較するときは、同じ端末で別のベンチマークを同時に起動せず、関連ファイルだけを1ワーカーで順番に実行する。全件とカバレッジは最新コミットの CI で確認する。
