# slide の設計

HTML スライドを、いつもの制作環境から公開・共有・販売できるサービスを作る。設計段階であり、ここにある機能は実装済みを意味しない。更新日 2026-11-05。

## 何のために作るか

登壇者が GitHub で管理するスライドを公開し、読者が URL から読めるようにする。将来は資料の販売と PRO・TEAM を通じ、SaaS の契約・決済・権限管理を一通り学ぶ。売れることの検証は、着手の条件にしない。

一方、利用場面を想像できない機能は作らない。各機能の採用理由は、誰が、どんな場面で困り、何をして、どうなればよいかで説明する。技術的に作れることだけを採用理由にしない。

## 読む順序

1. [ストーリーマップ](story-mapping.canvas)で、利用者の行動、各段階の対象機能・前提・完了条件を確認する。
2. マップにある機能名のリンクから、各 feature の具体的な利用場面と受け入れ条件を読む。
3. 実装を考えるときは [開発者向け設計](dev/index.md)を読む。

実装する範囲と順序はストーリーマップ内で管理し、一覧を別の文書に複製しない。

## 決まっている方針

- 収益は有料資料の販売手数料、PRO、TEAM。販売には Stripe Connect を使う。
- PRO は独自ドメイン、大容量、閲覧分析。TEAM は PRO にチーム限定共有と SSO を加える。
- 作者が販売・一般公開を止めたり退会したりしても、購入済みの読者の閲覧は維持する。資料更新後は編集後の内容を提供する。
- 販売価格と無料ページを設定できる。購入は資料全体に対するもので、ページごとの課金ではない。
- 翻訳・音声・文字起こしの生成は作者側で行う。OGP 画像だけは作者の画像を優先し、ない場合に必要なページをサービスが撮影して保存する。生成クレジットは扱わない。
- 初期は本人だけがアップロードし、小さい容量・頻度の上限から始める。上限は後から運用設定で変更する。
- 受け取るのはビルド済みの静的ファイルだけ。ビルド方法は作者が手元や CI で用意する。
- Workers を使い、配信と保存の費用を抑える。公開管理とアクセス制御はキャッシュより前で行う。
- タテブログへの適用は、はてな・KADOKAWA の許可が整ってから。slide 単独の開発を妨げない。

## まだ採用しない案

共同編集・コメント、pedit や Peitho Studio からの直接連携、GitHub のネットワークを使う SNS、遠隔発表同期は保留。具体的な利用者の場面と既存手段の困りごとが明確になった時点で feature にする。広告と広告収益還元、翻訳・音声・記事のプラットフォーム側生成は今回の方針から外す。

[着想元](https://slides.yusu.ke/my-slides-app)、[Zenn の公開体験](https://zenn.dev/zenn/articles/zenn-cli-guide)、[LISTEN](https://listen.style/guide)は参考。各サービスの全機能を再現する計画ではない。
